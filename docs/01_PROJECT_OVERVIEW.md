# 프로젝트 개요 — 힘·촉각 기반 Blind Sweeping

기준일: 2026-09-14. 출처 ID는 [출처 목록](06_SOURCE_REGISTER.md)을 따른다. 이 문서의 현재 방향은 S-0914를 우선하며, 설계 후보는 별도로 표시한다.

## 1. 연구 목적과 동기

선반의 가려진 물체를 찾거나 후속 조작 공간을 확보하려면 앞을 가리는 물체를 밀어야 하는 상황이 생긴다. 상위 시스템은 무엇을 치울지 판단하고, 하위 정책은 지정된 접촉 조작을 실행한다. 본 연구의 직접 대상은 **초기 시각 정보 이후 실시간 힘·촉각 피드백으로 Sweeping을 수행하는 하위 정책**이다. [S-TASK1, S-0914]

시각 정보를 시스템 전체에서 배제하는 것이 목적이 아니다. 손과 팔이 들어가면서 물체가 가려지고 연속적인 물체 pose 추정이 불확실해지는 구간을 다룬다. 연구 설명은 ‘Vision이 나쁘므로 없앤다’가 아니라 **상위 시각 판단과 하위 접촉 피드백의 역할 분담**으로 구성한다. 시각 방식 대비 속도·안정성이 우월하다는 주장은 비교 실험 전에는 하지 않는다. [S-0911]

### 현재 연구 질문

> 초기 정보와 수행 가능한 시작 조건이 주어졌을 때, 연속 시각 추적 없이 제한된 손목 F/T·촉각 정보로 물체를 얼마나 안정적으로 밀 수 있으며, 접촉 위치·센서 커버리지·신호 세기에 따라 그 능력은 어떻게 달라지는가?

이 문장은 9월 14일 피드백을 종합한 연구 질문이다. 논문 제목, 정량적 성공 기준, 최종 contribution 문장이 확정되었다는 뜻은 아니다. [S-0914]

## 2. 전체 시스템에서의 위치

```text
상위 시각 관측 / 과업 판단
  ├─ 궁극적으로 찾을 물체와 현재 치울 물체를 구분
  ├─ 수행할 조작과 시작 조건 결정
  └─ 접근 계획·실행
          ↓
하위 Blind Sweeping [본 연구]
  ├─ 초기 대상 정보와 목표 방향·거리 수신
  ├─ 접근 결과의 위치·자세 불확실성 아래 시작
  ├─ 실제 접촉 형성 및 밀기
  ├─ F/T·촉각을 이용한 실행 중 적응
  └─ 종료 및 결과 반환 [세부 설계 미정]
          ↓
상위 재관측·다음 조작 [전체 시스템 배경]
```

초기 관측, 상위 목표 설정, 물체 근처까지의 접근은 하위 Sweeping과 분리한다. 전체 장면을 한 번에 복원하거나 전체 탐색을 하나의 RL로 완성할 의무는 없다. [S-0910, S-0911]

### 상위·하위 경계

| 항목 | 역할과 경계 |
| --- | --- |
| 조작 대상 선택 | 상위 판단. 하위 정책이 탐색 목표를 처음부터 고르지 않음 |
| 방향·거리 결정 | 상위 과업 명령의 중심. 정확한 인코딩은 미정 |
| 접근 경로·시작 위치 | 상위 계획 또는 별도 접근 모듈 |
| 접근 후의 실제 접촉 | 오차가 남으므로 하위 연구의 핵심 |
| 기본 밀기와 센서 활용 | 본 연구 |
| 전방향 이동의 최종 범위 | 9/11에 논의되었으나 구현 범위는 추가 결정 |
| 간섭 종류 판단·다중 물체 처리 | 현재 필수 기능으로 확정하지 않음. 후순위 확장 |
| 전체 상위 판단기 구현 | 본 연구 범위 밖 |

‘상위가 수행 가능한 조작을 준다’는 가정은 모든 목표 거리에서 무간섭을 보증한다거나, 항상 촉각 센서 위에 접촉한다는 뜻이 아니다. [S-TASK1, S-0914]

## 3. 작업 환경과 시작 조건

배경은 다수 물체가 있는 선반이다. 9월 13일 연구안은 무작위 배치와 좌우 Sweep을 구체화했으나 9월 14일에는 배치의 복잡성보다 제한 센싱 문제를 우선하라고 조정되었다. 따라서 단일 물체, 단순 clutter, 실제 clutter를 구분해 실험할 수 있지만 최종 장면 수나 물체 수는 확정되지 않았다. [S-TASK1, S-0914]

오른쪽으로 밀 때 Hand가 대상 왼쪽에, 왼쪽으로 밀 때 대상 오른쪽에 도달한 상태를 출발안으로 삼았다. 초기 위치·자세에 변동을 주는 이유는 접근 결과가 정확하지 않기 때문이다. 시작 시 이미 접촉한 상태만 허용할지, 약간 떨어진 상태도 포함할지는 미정이다. [S-TASK1]

9월 10일의 넓은 3D 초기 자세 랜덤화는 사전 검증이었다. 최종 의도는 Home에서 자유롭게 reaching하는 RL이 아니라 **물체 근처에서 실제 접근 오차를 반영해 시작하는 정책**이다. 실제 접근을 반복해 상대 pose 오차 분포를 측정하라는 후속 과제가 있다. [S-0910]

과거 ‘임의 위치에서 시작·중단 후 재개’ 구상은 이 최신 경계 아래에서 재해석해야 한다. 임의 위치는 아무 위치나 뜻하지 않으며, 장기적으로 재사용 가능한 근접 시작 상태를 의미하도록 범위를 정해야 한다. [C-BRAINSTORM, S-0910]

## 4. Blind의 정확한 의미

| 시점·정보 | 현재 방향 |
| --- | --- |
| 접근 전 시각 관측 | 허용 |
| 초기 대상 물체 pose | 사용 구상 |
| 초기 주변 관측 | 사용 가능. ‘전혀 모른다’는 조건을 강제하지 않음 |
| Sweep 중 대상 물체 시각 pose 갱신 | 하지 않는 연구 방향 |
| Sweep 중 F/T·촉각 | 실시간 사용 |
| 로봇 고유감각 | 활용 가능한 정보. 정확한 구성은 미정 |
| 다음 상위 조작을 위한 재관측 | 전체 시스템에서 가능하며 한 번의 Sweep 중 관측과 구분 |

초기 주변 정보를 허용한다는 말은 모든 주변 물체의 완전한 pose를 actor에 넣기로 정했다는 뜻이 아니다. 초기 정보의 표현과 모듈별 전달 범위가 미정이다. [S-0914]

별도의 명시적인 물체 pose estimator를 하위에 구축하는 것은 기존 TASK 1의 필수 요구가 아니었다. 접촉 이력으로 상태가 정책 내부에 반영되는 구상과 명시적 pose 출력은 구분한다. 이런 추정기를 추가하는 제안은 별도 연구 선택으로 기록해야 한다. [S-TASK1]

## 5. 하드웨어와 센서가 제공하려는 정보

구성 계획은 **UR5e → ATI Axia80-M8 6축 F/T → Inspire Dexterous Hand**다. Hand 6자유도와 17개 촉각 센서 영역이 프로젝트 전제이며 실제 모델·원시 출력·구동 범위를 확인해야 한다. ATI Ethernet형 구매 방향은 과거 대화에서 확인되지만 설치·수신·실물 학습 성공을 뜻하지 않는다. [S-TASK1, C-HARDWARE]

F/T는 손목을 통해 전달되는 3축 힘과 3축 모멘트를, 촉각은 손의 센서 영역별 접촉 정보를 제공하는 역할이다. 센서별 Grid를 하나의 연속값 또는 Boolean으로 축약하는 안이 있다. 무엇을 합산·평균·최대화할지와 Boolean 임계값은 미정이다. [S-TASK1]

9월 14일에 강조된 문제는 센서가 있어도 필요한 정보가 항상 관측되지 않을 수 있다는 점이다. 센서가 없는 위치의 접촉, 약한 힘, 접촉 위치의 변동, 공간 해상도 차이를 실험 대상으로 삼아야 한다. 현재 장비에서 이러한 한계가 어느 수준인지 실측된 것으로 서술하지 않는다. [S-0914]

## 6. 정책 입력·행동의 현재 수준

초기 입력의 중심은 대상 pose와 목표 방향·거리다. 실시간 입력의 중심은 F/T와 촉각이다. 고유감각, EEF 상태, 이전 action, 센서 history는 구체화 대상이다. 9/13안의 Geometry 미사용은 이전 설계 방향으로 보존하되, 9/14 이후 전체 관측 계약이 새로 확정되었다고 가정하지 않는다. [S-TASK1, S-0914]

행동은 Cartesian 조작 명령을 사용하는 흐름이다. 9/10의 보고 구현은 OSC였고, 9/13안에는 Diff-IK 등의 변환이 제시된다. Δpose·velocity·wrench 중 어떤 action인지, rotational DOF를 얼마나 허용하는지, 실물 controller를 무엇으로 쓸지 확정되지 않았다. [S-0910, S-TASK1]

Hand는 사전 정의 자세를 활용하는 구상이며 손등을 이용한 밀기도 예상되었다. **손등·측면에서 밀 때 촉각 커버리지와 실제 접촉면이 맞는지**는 확인할 중요한 항목이다. 이는 센서 배치를 실제로 확인한 결론이 아니라 두 기록을 연결한 검증 질문이다. [S-TASK1, S-0914]

PPO는 대화에서 사용 중인 학습 기반으로 나타난다. RNN·history·hybrid action은 필수 확정 구조가 아니다. 기존 PPO 설정과 현재 구현 불확실성은 [코드 현황](07_CODE_AND_HARDWARE_STATUS.md)에 기록한다. [C-PPO]

## 7. 연구 결과로 보여 주어야 할 것

교수 피드백에 따른 방향은 센서 활용이 접촉 유지, 안정성, 과도한 힘, 전도, 수행 시간, 물체 특성 적응 등에 어떤 영향을 주는지 비교하고, 실제 센싱·제어의 어려움을 기록하는 것이다. 어떤 지표를 최종 채택할지와 수치 기준은 미정이다. [S-0910, S-0914]

인계 문서에서 제안하는 결과 구조는 다음과 같다. **기본 Blind 조작 가능성 → F/T·촉각 각각의 기여 → 접촉·센싱 불확실성에 대한 실패 조건 → 실물 적용 시 차이**를 순서대로 제시한다. 이 구조는 실행 계획이지 확보된 성과가 아니다.

‘센서 입력을 붙였다’는 구현 설명과 ‘어떤 조건에서 센서가 유효하고 한계가 무엇인지 보였다’는 연구 결과를 구분한다. 현재 문서에는 성공률, 실물 성능, 학습 수렴 수치가 확인된 상태로 들어 있지 않다.

## 8. 이번 연구에 자동으로 포함하지 않는 것

상위 VLM·장면 탐색기, 전체 motion planning 시스템, 석사생 2의 Approach–Rotation–Push 및 목표 접근성 판단, 엄격한 rotation-free 제약, 자코비안 기반 structured compliance, 자기 결합 분리·peg-in-hole·thin-object pinch 등의 예전 대안은 현재 본 연구의 필수 요구가 아니다. [S-0911, S-0914, C-ARCHIVE, C-BRAINSTORM]

추가 간섭 판별과 중단은 폐기가 아니라 `DEFERRED`다. 반면 실물의 위험을 제한하기 위한 안전 감독은 별개이므로 연구 범위 축소를 이유로 제거하지 않는다.

## 9. 용어

| 용어 | 이 저장소에서의 의미 |
| --- | --- |
| Target / manipulated object | 이번 Sweep에서 밀 대상 |
| Search target | 상위 과업에서 궁극적으로 찾을 물체 |
| Blind / no online vision | 하위 실행 중 지속 물체 시각 관측을 사용하지 않음 |
| Initial pose | 초기 관측 당시의 대상 pose. 현재 pose와 다름 |
| Proprioception | 관절·EEF 등 로봇 자체 상태 정보 |
| Tactile region | 손의 센서 영역. 그 내부 taxel/Grid와 구분 |
| Feasibility | 가정한 조건에서 가능성을 확인하는 단계. 최종 성능 검증과 다름 |
| GT / oracle | 시뮬레이션 정답 또는 이상적인 정보. 최종 실물 actor 입력과 구분 |
| Homing / standby | 9/13안에서는 근처에서 접촉을 풀고 대기하는 구상. 반드시 Home 복귀가 아님 |
| Interference | 밀기에 필요한 정상 접촉과 구분되는 추가 상호작용. 센서만으로 식별 가능하다는 보장은 없음 |
