# 앞으로 집중할 것과 진행할 작업

기준일: 2026-09-14. 현재 결과는 **연구 방향과 검증 우선순위를 정리한 상태**이며 완성된 Blind 정책의 성능 결과가 아니다.

교수 지시의 근거는 S-0910·S-0911·S-0914다. 아래 작업 분해, 우선순위 번호, 산출물 이름, 완료 기준은 그 지시를 실행 가능한 형태로 바꾼 **인계용 제안(PROPOSED)**이다. 확정된 일정표나 이미 수행한 실험표로 취급하지 않는다. 출처는 [출처 목록](06_SOURCE_REGISTER.md)을 따른다.

## 1. 가장 중요한 결론

당분간 연구의 중심을 **‘어려운 clutter 상황에서 어떤 기능을 더 넣을까’에서 ‘이 센서 조건으로 무엇을 관측하고 제어할 수 있는가’로 이동**시킨다. 기본 Blind sweeping, 센서별 기여, 접촉 불확실성, 실물 적용의 실패 원인을 먼저 다룬다. [S-0914]

정의가 필요한 관측·행동·성공 조건을 정리하는 일은 계속 필요하다. 다만 그 과정이 곧바로 회피·간섭 분류·상위 판단 기능의 확장으로 이어지지 않도록 한다. 학생이 제기했던 reward 설계 문제 자체가 부정된 것은 아니다.

## 2. 우선순위와 산출물

| 순서 | 작업 | 산출물 제안 | 완료 기준 |
| --- | --- | --- | --- |
| P0-A | 현재 코드·장비 사실 확인 | 구현 현황표, 센서 인벤토리 | 보고·실제 확인·미확인을 구분하고 코드 커밋/원시 sample을 연결 |
| P0-B | 현재 태스크의 최소 계약 작성 | 관측/행동/reset/성공/종료 계약 초안 | 미정 항목을 숨기지 않고 학습·실물·평가 정보 경계를 표시 |
| P0-C | 선행연구 검토 | 센서·관측·태스크 비교표 | 실제 원문 근거로 겹치는 부분과 미해결 질문을 제시 |
| P0-D | 센싱 feasibility 확인 | 센서/비센서 접촉과 약한 신호의 테스트 로그 | ‘접촉함’과 ‘센서가 감지함’을 구분해 설명 가능 |
| P1-A | 최소 환경에서 기본 조작 확인 | 재현 가능한 baseline run | GT 누출 없이 입력→행동→물체 이동을 추적 가능 |
| P1-B | 센서·불확실성 비교 | ablation 및 실패 조건 표 | 동일 조건 비교와 미지 물체/조건 평가 분리 |
| P1-C | 실제 접근 오차와 실물 연결 | 상대 pose 오차 분포, 실물 smoke-test 로그 | 가정이 아닌 실측으로 reset·센서 모델의 일부를 갱신 |
| P2 | clutter·간섭 등 확장 판단 | 확장 여부 결정 기록 | 기본 결과와 문헌 대비 추가 기여가 설명될 때만 채택 |

P0-C 문헌 검토와 P0-A/B/D의 설계·검증은 병행할 수 있다. 실물이 없으면 장비 의존 항목을 ‘미확인’으로 남기고, 가정을 명시한 시뮬레이션을 진행한다. 모든 하드웨어가 도착할 때까지 연구를 멈추라는 순서가 아니다.

## 3. P0-A — 현재 사실을 먼저 고정

### 코드 확인

구현 저장소·브랜치·커밋과 실행 명령을 확보하고 actor observation, critic observation, action scaling, controller, reward, termination, reset을 실제 코드에서 추적한다. 특히 현재 object pose가 매 step actor로 들어오는지 확인한다. 9/10 보고된 OSC 구현과 9/13안의 Diff-IK 설명 중 무엇이 현재 코드인지 결론을 낸다. [O-01, O-06]

설정 파일을 수정하기 전에 실제 run에 적용되는 PPO config를 확인한다. 로그와 체크포인트가 없으면 학습 완료·성공률을 기록하지 않는다. 기존 환경을 먼저 보존하고, 필요한 변경만 별도 커밋에 담는다.

### 장비 확인

Hand 정확한 모델과 구동 자유도, 센서 영역별 위치, 원시 Grid 형상·단위, 센서 ID, 유효 상태, timestamp, 실제 수신 주기를 기록한다. F/T의 통신 형식, 좌표계, 영점·부하 보정, 장착 상태도 별도 확인한다. 구매 방향과 설치 완료를 구분한다. [O-02–04]

**완료 판단:** 새 에이전트가 ‘현재 구현된 것/설계만 있는 것/원시 데이터가 없는 것’을 표 하나로 구분할 수 있어야 한다.

## 4. P0-B — 최소 실험 계약을 작성

첫 환경에서 다룰 물체·방향·시작 영역을 제한하고 선택 이유를 남긴다. 좌우 sweep과 단순 물체를 출발점으로 삼는 것은 가능하지만 최종 연구 범위를 영구 고정하는 결정과 구분한다. [O-05–09]

필수로 구분할 항목은 다음과 같다.

| 구분 | 정해야 하는 것 |
| --- | --- |
| 초기 정보 | 관측 시점, 대상 pose 표현, 방향·거리, 초기 주변 정보의 범위 |
| 실행 입력 | F/T·촉각·선택한 고유감각/history, 단위·좌표계·유효성 |
| 행동 | Cartesian 명령 종류, 허용 DOF, scaling·rate, Hand mode |
| reset | 접근 후 위치·자세 오차, 초기 접촉 여부, 물체 배치 |
| 물리적 성공 | 대상 물체의 명령 방향·거리 만족, 허용 오차·안정성 조건 |
| 실제 종료 | Blind 실행에서 언제 끝낼지, 판단 실패를 어떻게 기록할지 |
| 안전 감독 | 학습 판단과 독립적인 실물 제한·수동 개입 원칙 |

전체 조건을 아직 결정할 수 없으면 하나의 시험 조건으로 `PROPOSED`를 명시한다. 숫자는 편의상 넣은 값인지 실측 근거가 있는지 구분한다. 자세한 설계 메모는 [구현·평가 문서](05_IMPLEMENTATION_AND_EVALUATION.md)에 있다.

## 5. P0-C — 선행연구를 기여로 연결

### 확인해야 할 질문

초기 시각 이후 조작 중 시각을 쓰지 않는지, 전혀 보지 않는지, 부분 시각을 계속 쓰는지 구분한다. wrist F/T만인지 tactile만인지, 결합인지 확인한다. 촉각이 연속 전자피부인지 부분 영역인지, 공간 해상도와 원시 정보가 무엇인지 확인한다. Task가 pushing/sweeping인지, grasp correction/assembly인지 구분한다. 실물 검증의 실제 범위와 실패 조건도 기록한다. [S-0914 §6]

| 논문 | 실행 중 관측 | 센서·커버리지 | 태스크·시작 조건 | 정책·history | 실물 검증 | 본 연구와 중복 | 남는 질문 | 원문 위치 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 조사 후 입력 |  |  |  |  |  |  |  |  |

기존 대화의 MAT·primitive action·reverse curriculum 자료는 조사 출발점일 뿐 이 인계에서 원문을 새로 검증한 논문이 아니다. 관련성이 약하면 억지로 포함하지 않는다. 문헌 조사는 ‘비슷한 제목 수집’으로 끝내지 않고 센싱 조건별 차이로 연구 질문을 좁힌다.

**완료 판단:** 왜 현재 센서 구성과 접촉 불확실성의 조합을 별도로 연구해야 하는지, 무엇은 이미 알려져 있는지, 어떤 주장은 아직 입증이 필요한지 구분할 수 있어야 한다.

## 6. P0-D — 센싱 feasibility를 실험 문제로 바꾸기

처음부터 정책 수렴에 모든 검증을 맡기지 말고, 간단한 제어와 동기 로그로 센서 입력이 의도한 현상을 반영하는지 확인한다. [S-0914 §4, §6에 따른 실행 제안]

| 테스트 | 확인할 질문 | 남길 데이터 |
| --- | --- | --- |
| 센서 부위 접촉 | 의도한 영역의 출력과 F/T가 반응하는가? | 영역 ID, pose, raw/가공 신호, timestamp |
| 비센서 부위 접촉 | 실제 접촉이 있지만 tactile이 약하거나 없는 상황을 표현하는가? | 평가용 실제 접촉 위치와 정책 입력 분리 |
| 무부하·자세 변화 | 접촉 아닌 부하·운동 변화가 신호에 얼마나 포함되는가? | raw/보정 F/T, robot state |
| 약한 접촉·가벼운 물체 | 접촉과 noise를 구분할 수 있는가? | 물체/선반 조건, 반복 측정, 실패 사례 |
| 신호 누락·지연 | 무접촉과 통신/센서 오류를 구분하는가? | 유효성, sample age, 실제 수신 간격 |

실물 부재 시 센서 모델의 가정과 적용 범위를 먼저 적고, 이상적인 전체 손 접촉 정보를 실제 tactile인 것처럼 사용하지 않는다. 약한 신호를 다룬다는 이유로 물체 마찰을 올려 쉬운 조건만 만들고 일반적 성공이라고 보고하지 않는다. 어려운 조건을 단순화한 테스트와 원래 조건을 구분한다.

**완료 판단:** ‘어떤 접촉은 관측되며 어떤 접촉은 관측되지 않는가’를 정책의 성공 여부와 별개로 설명할 수 있어야 한다.

## 7. P1-A/B — 기본 조작과 센서 기여 비교

먼저 제한한 환경에서 controller·action·reward·reset이 정상 동작하는지 확인한다. GT를 이용한 디버그·oracle baseline은 이름과 입력을 명시한다. 최종 Blind 조건의 actor와 섞지 않는다.

그다음 동일한 목표·robot state·초기 분포 아래 무접촉센서 기준선, F/T-only, tactile-only, 결합 센싱을 비교하는 안을 검토한다. history는 실제 관측 부족이나 시간적 모호성이 확인될 때 추가 비교한다. 모든 비교는 필요성·훈련 비용을 검토해 선택하며 한 번에 전체 조합을 구현할 의무는 없다. [O-11, O-14]

물체 이동·접촉 손실·전도·최대 힘·수행 시간을 함께 기록한다. 평균 성능뿐 아니라 센서 사각지대·약한 신호·접근 오차에 따른 실패군을 남긴다. train/test의 물체와 조건을 구분하고 seed·훈련량·controller 조건을 기록한다. 검증하지 않은 단일 run의 성공을 일반화 성능이라고 쓰지 않는다.

## 8. P1-C — 접근 오차와 실물 검증

상위 접근을 반복하여 목표 대비 최종 EEF–물체 상대 pose 오차를 측정한다. 시뮬레이션 초기 분포가 실제 접근 오차를 반영하도록 갱신한다. 기존 임의 randomization이 현실적이라고 가정하지 않는다. 동일 원인의 perception error를 reset과 observation noise에 중복 반영하지 않도록 모델링 근거를 남긴다. [S-0910 §3]

실물 단계는 장비·제어·안전 확인을 전제로 한다. 시뮬레이션과 실물의 신호 단위·좌표계·지연·부하 보정·촉각 영역 대응을 맞추고, 실물에서 관측 가능한 종료 방식으로 시험한다. 실패를 PPO 성능 문제로 즉시 환원하지 말고 센싱·제어·접근·안전 개입을 나누어 기록한다. [S-0914 §6]

**완료 판단:** 실제 로봇의 어떤 조건에서 성능이 유지되거나 깨지는지 재현 가능한 로그와 실험 조건으로 설명할 수 있어야 한다.

## 9. P2 — 확장은 언제 검토하는가

간섭 감지·중단, 복잡한 clutter 회피, 다중 물체 처리로 확대하기 전에 다음 질문에 답한다. 기본 Blind sweep은 어느 조건에서 가능한가? 실패가 센서 정보 부족 때문인지 제어·학습 문제인지 구분했는가? 기존 연구와 비교해 추가 판단 기능의 기여가 남는가? 고정 임계값·규칙 기반 방법과 구분되는 실험을 만들 수 있는가?

이 질문에 답할 근거가 부족하면 확장을 계속 보류한다. 단, 실물의 안전 감독은 이 확장 gate와 관계없이 유지한다.

## 10. 다음 미팅에 가져갈 내용

핵심은 새 기능 목록이 아니라 **확인된 사실과 다음에 검증할 질문**이다. 현재 구현과 센서 준비 상태, 좁힌 연구 질문, 센싱 조건별 선행연구 표, 최소 실험 계약, 실제/시뮬레이션 접촉 로그, 실패 사례, 남은 결정 사항을 준비한다.

아직 정책 결과가 없다면 없다고 적고, 어떤 가정을 검증했는지 제시한다. 교수 지시·학생 제안·실험 결과를 분리한다. 수치가 없는 상태에서 성공률·실시간성·실물 이전 성능을 주장하지 않는다.
