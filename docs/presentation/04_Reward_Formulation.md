**기준일: 2026-10-05**

**주 근거:** 「중간발표_최종.pdf」 실제 PDF 22–27쪽. 하단 슬라이드 번호는 23–28이며, 본 문서는 파일의 실제 쪽수를 사용한다. Reward Ablation은 실제 PDF 32쪽을 참조한다.

**문서 상태:** 최종 발표본의 보상 설계 설명. 구현 완료, 최종 계수 확정 또는 성능 검증 결과를 의미하지 않는다.

이 보상의 목적은 **현재 물체 위치를 실행 중 관측하지 못하는 정책이 대상 물체를 목표까지 정확하고 안정적으로, 빠르게 이동하도록 학습하는 것**이다. 목표 도달을 주목적으로 두고 접촉 방향·접촉 유지·명령 연속성·완료 시간을 함께 평가한다. CoP 기반 회전 Sub-Goal은 접촉 신호의 물리적 의미를 중간 학습 목표로 연결하는 보조 항이다.

PDF에 제시된 식은 아래에 보존한다. PDF에 없는 CoP 추정의 상세 계산은 원리 보충으로, 구현에 필요한 선택은 `OPEN` 또는 `PROPOSED`로 구분한다. 특히 최종 발표본에는 회전 목표 생성식과 $r_{\mathrm{sg}}$의 구체적인 함수가 제시되지 않았다.

## 1. 전체 보상과 각 항의 역할

실제 PDF 22쪽의 보상 구성은 다음과 같다. 시간 첨자 $t$는 각 정책 Step의 값을 구분하기 위해 붙였다.

```math
r_t=w_1r_{\mathrm{goal},t}
+w_2r_{\mathrm{normal},t}
+w_3r_{\mathrm{contact},t}
+w_4r_{\mathrm{action},t}
+w_5r_{\mathrm{time},t}
+w_6r_{\mathrm{sg},t}.
```

| 항 | 계산 대상 | 학습하려는 행동 | 역할 |
| --- | --- | --- | --- |
| $r_{\mathrm{goal}}$ | 현재 대상 물체와 목표 사이의 위치 오차 | 물체를 목표에 가깝게 이동 | 과업의 주목적 |
| $r_{\mathrm{normal}}$ | 실제 접촉 법선과 현재 물체에서 목표로 향하는 방향 | 목표에 유효한 방향으로 밀기 | 접촉 방향 보조 |
| $r_{\mathrm{contact}}$ | 접촉 유무와 활성 촉각 영역의 가중 비율 | 접촉을 유지하고 여러 영역 활용 | 접촉 안정성 보조 |
| $r_{\mathrm{action}}$ | 현재·직전 Arm 및 Hand 명령의 차이 | 명령 급변 억제 | 제어 안정성 보조 |
| $r_{\mathrm{time}}$ | 성공 여부와 성공까지 걸린 시간 | 조기에 목표 도달 | 성공 시점의 완료 보상 |
| $r_{\mathrm{sg}}$ | 접촉 해석으로 만든 회전 목표와 현재 손 자세 | 접촉 편차를 줄이는 보정 행동 학습 | 탐색·수렴을 돕는 보조 목표 |

$w_1,\ldots,w_6$는 항 사이의 가중치다. 각 항 내부에도 거리 Scale, 접촉 비율 계수, Arm·Hand 변화량 계수 등이 있으므로, 가중치 숫자만으로 목표 도달의 실제 기여가 지배적이라고 판단할 수 없다. Step별 크기와 Episode 누적 기여를 함께 확인해야 한다. 최종 가중치는 발표에 제시되지 않았다.

접촉 영역이 많거나 회전 목표를 잘 추종하더라도 물체가 목표에 도달하지 못하면 과업 성공이 아니다. 성공·실패 판정은 [성공·종료 조건](05_Success_and_Termination.md)에서 별도로 다룬다.

## 2. 목표 도달 보상

### 2.1. 발표 식과 계산 의미

실제 PDF 23쪽의 식은 다음과 같다.

```math
r_{\mathrm{goal},t}
=\exp\left(-\frac{\|\mathbf{p}_t-\mathbf{p}_g\|}{\sigma_p}\right).
```

| 기호 | 의미 |
| --- | --- |
| $\mathbf{p}_t$ | 현재 대상 물체 위치. 시뮬레이션의 특권 정보 |
| $\mathbf{p}_g$ | 초기 물체 위치와 사용자·상위의 방향·거리 명령으로 정한 목표 위치 |
| $\sigma_p$ | 위치 오차에 대한 보상 감소의 Scale |

목표는 [과업과 실행 구조](02_Task_Definition_and_Framework.md)의 명령으로 설정한다. 보상 계산 시에는 현재 **물체** 위치와 목표의 차이를 구한다. Hand나 EEF가 명령 거리만큼 이동한 것을 물체 이동으로 대신 계산하지 않는다.

$\sigma_p>0$일 때 위치 오차가 0이면 보상은 1이고, 오차가 커지면 보상이 0에 가까워진다. 따라서 이 항은 성공 시점에만 주는 보상이 아니라, 목표와의 거리를 매 Step 평가하는 연속적인 학습 신호다. $\sigma_p$가 작을수록 목표 근처에서 보상이 더 빠르게 변하며, 클수록 먼 거리까지 완만하게 변한다.

발표 그래프에는 $\sigma_p=0.1\mathrm{m}$가 예시로 표시되어 있다. **곡선 설명용 예시값이며, 실제 학습에 적용된 최종 계수라는 근거는 없다.** 위치의 좌표계, 노름의 구현 정의 및 Scale의 적용값은 코드에서 확인해야 한다.

### 2.2. Privileged Information의 경계

학습 환경은 물체의 현재 위치를 알고 있으므로 행동 결과를 채점할 수 있다. 그러나 최종 Blind Actor는 현재 물체 위치를 실행 중 계속 받지 않는다. 초기 물체 위치·목표 조건이 Actor에 들어가는 것과 현재 물체 정답이 매 Step 들어가는 것은 다른 조건이다.

보상에 시뮬레이션 정답을 사용하는 것은 실행 시 그 정답을 관측한다는 뜻이 아니다. Critic에 어떤 특권 정보를 제공할지까지 이 식만으로 확정할 수 없으며, Actor·Critic·Reward의 실제 입력 경계는 구현 시 별도 확인해야 한다.

## 3. 접촉력 방향 정렬 보상

### 3.1. 발표 식

실제 PDF 24쪽의 식은 다음과 같다. PDF의 내적을 벡터 내적 표기로 옮겼으며, **분모 2를 유지**했다.

```math
r_{\mathrm{normal},t}
=-\frac{1-\hat{\mathbf{n}}_t^{\mathsf{T}}
\hat{\mathbf{d}}_{\mathrm{ref},t}}{2}.
```

| 기호 | 발표의 정의 |
| --- | --- |
| $\hat{\mathbf{n}}_t$ | Hand–대상 물체 사이 접촉력의 법선 단위벡터. 특권 정보 |
| $\hat{\mathbf{d}}_{\mathrm{ref},t}$ | 현재 물체 위치에서 목표 위치로 향하는 단위 방향. 특권 정보 |

정상적인 단위벡터가 정의되는 경우 현재 위치에서 목표로 향하는 방향은 다음 관계로 해석할 수 있다. 이는 발표에 적힌 방향 정의를 풀어 쓴 식이다.

```math
\hat{\mathbf{d}}_{\mathrm{ref},t}
=\frac{\mathbf{p}_g-\mathbf{p}_t}
{\|\mathbf{p}_g-\mathbf{p}_t\|}.
```

두 방향이 같으면 $r_{\mathrm{normal}}=0$, 직교하면 $-0.5$, 반대면 $-1$이다. 여기서 “정렬할수록 보상이 증가한다”는 것은 음의 값이 0으로 올라간다는 뜻이다.

### 3.2. 무엇을 정렬하는가

이 항은 현재 물체에서 목표로 향하는 방향과 실제 접촉 법선을 맞추려는 설계다. 초기의 고정 Sweep 방향만 사용하면 물체가 옆으로 벗어난 이후에도 같은 방향을 평가하게 되지만, 발표의 기준 방향은 현재 물체 위치에 따라 달라진다. 이 정의에는 현재 물체 정답을 사용한다.

Hand Orientation은 접촉 법선에 영향을 주므로 이 보상으로 목표에 유효한 손의 자세를 유도하려 한다. 그러나 식의 직접 평가 대상은 접촉 법선이며, 손바닥의 기구학적 법선이나 손목에서 측정한 합력 방향으로 임의 대체하지 않는다. 마찰이 있는 접촉에서는 법선과 전체 접촉력 방향이 다를 수 있다. 발표의 `Contact Force 정렬`이라는 명칭만으로 접선력까지 포함한 합력 정렬식이 확정된 것은 아니다.

### 3.3. 구현 전 확인 사항

| 상태 | 항목 | 필요한 결정 |
| --- | --- | --- |
| `OPEN` | 법선 부호 | 대상 물체에 작용하는 방향과 Hand에 작용하는 반력 중 어느 방향을 사용하는지 명시 |
| `OPEN` | 다중 접촉 | 여러 접촉의 대표 법선을 선택·집계하는 방법 |
| `OPEN` | 무접촉 | 접촉 법선이 없는 Step의 처리와 유효성 Gate |
| `OPEN` | 목표 도달 부근 | $\lVert\mathbf{p}_g-\mathbf{p}_t\rVert=0$ 또는 매우 작은 값에서 단위 방향을 처리하는 방법 |
| `OPEN` | 좌표계 | 두 방향을 같은 좌표계로 변환하는 규칙 |

이 사항을 임의의 상수나 기본 방향으로 채우지 않는다. 접촉 법선 정렬을 만족한다는 사실만으로 손바닥·손등 사용이나 목표 도달이 보장되는 것도 아니다.

## 4. 접촉 상태 유지와 활성 영역 보상

### 4.1. 발표 식

실제 PDF 25쪽은 접촉의 존재 $C_t$와 활성 영역의 가중 비율 $N_t$를 구분한다.

```math
C_t=\mathbf{1}_{\{\sum_{i=1}^{17}c_{t,i}>0\}},
\qquad
N_t=\frac{\sum_{i=1}^{17}\alpha_i c_{t,i}}
{\sum_{i=1}^{17}\alpha_i}.
```

```math
r_{\mathrm{contact},t}=\beta_1C_t+\beta_2N_t.
```

| 기호 | 의미 |
| --- | --- |
| $c_{t,i}$ | 선택한 작업 면의 $i$번째 촉각 영역의 Binary 접촉값 |
| $\alpha_i$ | 촉각 영역의 중요도 가중치 |
| $\beta_1$ | 접촉 존재 보상의 계수 |
| $\beta_2$ | 활성 영역 비율 보상의 계수 |

먼저 17개 접촉값의 합이 양수인지 확인해 $C_t$를 계산한다. 다음으로 활성 영역의 가중 합을 전체 영역의 가중 합으로 나누어 $N_t$를 계산한 뒤 두 값을 합산한다. 작업 면을 구분하는 Header는 접촉 영역이 아니므로 합산하지 않는다.

영역 가중치가 음이 아니고 전체 합이 양수라는 조건에서는 $N_t\in[0,1]$이다. 같은 가중치라면 $N_t$는 활성 영역 수를 17로 나눈 값이다. 이 조건 및 최종 가중치 값은 구현 설정에서 명시해야 한다.

### 4.2. 접촉 면적의 대리 지표

발표에서는 “유효 접촉 면적 극대화”로 설명하지만, 식에서 직접 계산하는 값은 **Binary 센서의 활성 영역 가중 비율**이다. 센서 영역 안의 실제 접촉 면적, 압력 분포 또는 모든 접촉의 안정성을 직접 측정하는 값은 아니다. 활성 영역이 증가하는 것을 접촉 범위가 넓어지는 대리 신호로 사용하는 설계다.

한 영역만 활성화되어도 $C_t$의 보상은 얻으며, 추가 영역이 활성화되면 $N_t$의 기여가 증가한다. 따라서 접촉 존재와 공간 분포에 대한 선호를 별도 계수로 조정할 수 있다. 손끝과 손바닥 중앙 등의 중요도 차이는 $\alpha_i$로 표현할 수 있지만, 그 차이를 수치로 확정한 자료는 없다.

발표 그래프의 $\beta_1=\beta_2=0.5$, $\alpha_i=1$은 식의 형태를 보여주는 예시다. 또한 이 식에는 “대상 물체와 닿은 영역만”을 선택하는 Contact ID가 없다. 실물 Binary 센서가 다른 접촉에도 반응할 수 있다는 점을 고려하고, 시뮬레이션에서 정답 물체 ID로 접촉값을 골라 Actor에 제공하면 동일한 센싱 조건인지 따로 확인해야 한다.

## 5. Action 변화량 억제

실제 PDF 26쪽은 다음처럼 두 변화량에 **음수 부호**를 붙인다.

```math
r_{\mathrm{action},t}
=-\lambda_r\|\mathbf{a}_{r,t}-\mathbf{a}_{r,t-1}\|_2^2
-\lambda_h\|\mathbf{a}_{h,t}-\mathbf{a}_{h,t-1}\|_2^2.
```

$\mathbf{a}_{r,t}$는 Arm의 6D Cartesian 증분 명령이고, $\mathbf{a}_{h,t}$는 Hand의 2D 정규화 목표 명령이다. $\lambda_r$, $\lambda_h$는 Arm·Hand의 명령 변화량 계수다.

계수가 양수이면 이전 명령과 같을 때 해당 벌점은 0이고, 차이가 커질수록 벌점이 커진다. 이는 Action의 절대 크기를 작게 만드는 식이 아니다. 일정한 크기의 명령을 유지하는 것과 명령을 급하게 바꾸는 것을 구분하여, 명령 연속성을 유도한다.

실제 Cartesian 증분에서는 병진과 회전의 단위가 다르고 Hand는 정규화 목표를 사용한다. 따라서 두 계수를 같은 수치로 두었다고 동일한 물리적 부담을 평가하는 것은 아니다. **정규화된 정책 출력과 Scale·Clip을 적용한 실제 제어 명령 중 어느 값을 평가하는지**, Arm 내부 병진·회전의 Scale, Episode 첫 Step의 직전 Action 초기값은 `OPEN`이다. 이 문서는 새로운 Scale이나 계수를 선택하지 않는다.

## 6. 성공 시 조기 완료 보상

실제 PDF 26쪽의 시간 항은 다음과 같다.

```math
r_{\mathrm{time}}
=R_{\mathrm{success}}
+w_{\mathrm{fast}}\exp\left(-\frac{t_{\mathrm{success}}}{T_{\mathrm{ref}}}\right).
```

| 기호 | 의미 |
| --- | --- |
| $R_{\mathrm{success}}$ | 성공 시 받는 기본 보상 |
| $w_{\mathrm{fast}}$ | 빠른 성공의 추가 보상 계수 |
| $t_{\mathrm{success}}$ | 성공까지 걸린 시간 |
| $T_{\mathrm{ref}}$ | 성공 시간 정규화에 사용하는 기준 수행 시간 |

발표 본문은 과업 성공 시 기본 보상을 얻고, 빨리 완수할수록 더 큰 보상을 받는다고 설명한다. [기존 발표 진행 메모](1st_draft/HELP.md)도 성공 시 완료 보상을 한 번 부여하는 흐름으로 설명한다. 따라서 최신 시간 항은 매 Step 일정 비용을 내는 식이 아니라 **성공 시점에 조기 완료를 장려하는 이벤트 보상**으로 정리한다.

$w_{\mathrm{fast}}>0$, $T_{\mathrm{ref}}>0$이면 같은 성공이라도 완료 시간이 짧을수록 추가 보상이 크다. 실패를 빨리 종료한 경우에는 성공 보상을 받을 근거가 없다. 다만 PDF 식 자체에는 성공 Indicator나 미성공 Step의 값이 없으므로, 코드에서는 성공 이벤트의 Gate와 중복 지급 방지를 명시해야 한다. 정확한 성공 조건은 [성공·종료 조건](05_Success_and_Termination.md)을 따른다.

이 방식은 예전의 $-\Delta t/T_{\mathrm{ref}}$ Step 시간 비용과 다르다. 해당 과거식을 최신 보상에 함께 적용한다고 임의로 합치지 않는다. $w_5$는 전체 시간 항을 다른 보상과 조절하고, 내부 $w_{\mathrm{fast}}$는 기본 성공 보상 대비 조기 완료 성분을 조절한다. 둘 모두 최종값은 미명시다.

## 7. CoP 기반 회전 Sub-Goal

### 7.1. 왜 중간 목표를 만드는가

실제 PDF 27쪽은 $r_{\mathrm{sg}}$를 접촉 신호의 물리적 해석으로 정책의 탐색과 수렴을 돕는 보조 보상으로 제시한다. 물체 위치를 보지 못하는 Actor는 Tactile·F/T의 변화와 이후 목표 도달의 관계를 경험으로 학습해야 한다. 회전 Sub-Goal은 그 관계의 일부를 **현재 손 자세와 비교할 수 있는 중간 목표**로 바꾸려는 설계다.

두 센서가 Actor 관측에 들어가는 것과, 두 센서의 관계를 해석해 학습 보상을 만드는 것은 다른 경로다. CoP나 Sub-Goal을 57D Actor 관측에 추가하거나, 추정된 회전을 Action으로 강제하는 구조가 아니다. Sub-Goal 추종이 최종 물체 이동에 도움이 되는지는 보상 비교 실험으로 검증한다.

### 7.2. 발표 그림과 기존 설명의 계산 흐름

최종 PDF의 그림은 `CoP 추정 → CoP 평가·가중 → CoP 변화 → 회전 보정`을 제시한다. [기존 발표 진행 메모](1st_draft/HELP.md)와 [발표 대본](1st_draft/05_Midterm_Presentation_Script_15min.md)의 설명을 연결하면 다음 다섯 단계다. 구체적인 함수·계수까지 확정했다는 의미는 아니다.

| 순서 | 처리 | 입력과 출력 | 현재 명시 수준 |
| --- | --- | --- | --- |
| 1 | 접촉 평면 근사 | 활성 촉각 영역·손 기구학 → 접촉 평면과 활성 영역 | 개념·설명 제시. 평면 선택·근사 함수 미명시 |
| 2 | CoP 추정 | 외부 접촉 Wrench·접촉 평면 → 평면 위 하중 작용 위치 | 개념 제시. 발표에 추정식 없음 |
| 3 | 신뢰도 평가 | CoP와 활성 영역의 공간 일관성·법선력 유효성 → 보조 항의 반영 정도 | Weighting 개념 제시. 신뢰도 함수·임계값 미명시 |
| 4 | 회전 목표 생성 | 같은 기준에서 비교한 CoP 변화 → Hand Yaw Sub-Goal | 회전 $\psi$ 보정 방향 제시. 목표 생성식 미명시 |
| 5 | 보조 보상 계산 | 현재 손 자세·회전 목표·신뢰도 → $r_{\mathrm{sg}}$ | 추종을 유도하는 의도 제시. 보상 함수 미명시 |

예를 들어 손의 가장자리 쪽으로 하중 중심이 이동하면, 접촉 상태가 달라졌다는 단서로 해석하고 이탈을 줄일 회전 목표를 만들려 한다. Actor는 현재 손 자세를 관측할 수 있으므로 그 목표와의 자세 차이를 줄이는 행동을 학습할 수 있다. 이때 **CoP 변화는 Slip을 포함한 접촉 변화의 단서**이며, Slip의 유일한 판정이나 정확한 물체 Pose 추정값은 아니다.

### 7.3. CoP 추정의 원리 보충 — 발표 확정식과 구분

다음은 PDF에 없는 식이다. 접촉 평면과 힘·모멘트의 관계가 왜 하중 위치의 단서를 제공하는지 설명하는 **물리 모델의 보충**이며, 실제 구현된 추정기나 확정된 $r_{\mathrm{sg}}$ 계산식으로 취급하지 않는다.

같은 좌표계·모멘트 기준점에서 외부 접촉 합력과 모멘트를 $\mathbf{F}$, $\mathbf{M}$, 접촉 평면 위 기준점을 $\mathbf{c}$, 평면 단위 법선을 $\mathbf{n}$이라 두자. 한 지배적인 접촉 Patch의 하중을 평면 위 점 $\mathbf{p}$에 작용하는 합력으로 근사할 수 있다면 다음 조건을 사용한다.

```math
\mathbf{M}=\mathbf{p}\times\mathbf{F},
\qquad
\mathbf{n}^{\mathsf{T}}(\mathbf{p}-\mathbf{c})=0.
```

이를 만족하는 점의 계산 관계는 다음과 같다.

```math
\mathbf{p}_{\mathrm{CoP}}
=\mathbf{c}
+\frac{\mathbf{n}\times(\mathbf{M}-\mathbf{c}\times\mathbf{F})}
{\mathbf{n}^{\mathsf{T}}\mathbf{F}}.
```

먼저 $\mathbf{M}-\mathbf{c}\times\mathbf{F}$로 평면 기준점에 대한 모멘트를 구하고, 평면 법선과의 외적을 법선 방향 힘으로 나누어 평면 위 위치 편차를 구한다. 이 관계가 유효하려면 접촉 평면·외부 Wrench·접촉 근사가 서로 일관되어야 한다. 아무 Wrench나 이 식에 넣으면 물리적으로 유효한 CoP가 복원되는 것은 아니다.

| 조건 | 필요한 이유 | 현재 상태 |
| --- | --- | --- |
| 충분한 법선력 | $\mathbf{n}^{\mathsf{T}}\mathbf{F}$가 0에 가까우면 위치 추정이 불안정 | 유효성 평가 필요. Force Threshold 최종값 미명시 |
| 하나의 지배적인 접촉 Patch 또는 이에 준하는 모델 | 손의 여러 비평면 부위·선반 등의 하중이 섞이면 한 점으로 설명하기 어려움 | 적용 가능한 접촉 조건 검증 필요 |
| 평면과 힘의 일관성 | 다른 면의 힘이나 근사 평면과 맞지 않는 모멘트는 잘못된 위치를 만들 수 있음 | 잔차·일관성 검사 방식 미명시 |
| 공통 좌표계와 모멘트 기준점 | 힘을 회전하는 것만으로 모멘트 기준점이 맞춰지지는 않음 | Wrench Transform과 기준점 명시 필요 |
| 비접촉 성분의 분리 | Joint Reaction Wrench에는 Hand 중력·관성 등도 포함될 수 있음 | 기존 대본은 시뮬레이션에서 외부 성분 분리를 설명. 코드 검증 전 |
| 접촉 모멘트 모델 | 단일 힘으로 설명되지 않는 자유 모멘트가 있으면 위 점 모델의 조건이 달라짐 | 적용 가능성과 잔차 처리 검증 필요 |

특히 손가락과 손바닥의 여러 영역이 동시에 닿았다는 사실만으로 이들이 하나의 평면 Patch를 이룬다고 가정하지 않는다. 손 기구학을 이용한 평면 근사와 근사 유효성 판단이 필요하다. 또한 같은 손목 Wrench에 대상 물체·작업판 접촉이 함께 포함되면, 촉각만으로 대상별 하중이 자동 분리되는 것은 아니다.

### 7.4. 신뢰도와 시간 변화의 처리

Binary Tactile은 접촉 영역을 알려주지만 영역 내부 압력의 정답은 주지 않는다. 추정 CoP가 활성 영역 근처에 있는지 확인하는 것은 공간적 일관성 검사이며, 이 결과를 곧 추정 정확도라고 부를 수 없다. 신뢰도가 낮으면 보조 보상의 영향도 낮춘다는 구조는 기존 설명에 있으나, 거리 함수·가중 함수·경계값은 최종 발표에 없다.

`OPEN`인 구현 항목은 다음과 같다.

- 선택 면과 활성 센서 기하로 접촉 평면·영역을 만드는 방법.
- 접촉력 부족, 무접촉, 양면 동시 접촉 및 모델 불일치에서 CoP와 보조 보상을 처리하는 방법.
- CoP의 활성 영역 이탈을 측정할 거리 정의와 신뢰도 반영 함수.
- 손이 이동·회전하거나 Hand 관절이 변할 때, 연속 CoP를 비교할 기준 좌표계.
- 접촉 면 전환·접촉 소실·Episode Reset 시 변화량과 이력을 초기화하는 규칙.
- CoP 변화에서 Yaw 보정의 부호·크기·한계를 정하는 함수.
- Yaw의 주기성을 고려한 자세 오차 정의와 $r_{\mathrm{sg}}$ 함수.

손의 회전만으로도 세계 좌표계에서 표현된 CoP 위치는 바뀔 수 있다. 따라서 좌표계 변화와 접촉면에서의 실제 하중 이동을 구분해야 한다. 임의의 CoP 차분에 바로 Slip이나 회전 보정 부호를 부여하지 않는다.

기존 논의의 “CoP 이동에 직접 벌점” 같은 보조식이 있다 하더라도, 최신 PDF의 핵심은 **CoP 변화로 회전 Sub-Goal을 만들고 관측 가능한 손 자세의 추종을 유도하는 것**이다. 과거 보조식을 최신 $r_{\mathrm{sg}}$의 확정 함수로 승계하지 않는다.

## 9. Step별 계산 순서와 구현 확인

아래 순서는 수식의 의존관계를 따라 정리한 **구현 확인용 흐름(`PROPOSED`)**이다. 실제 환경의 버퍼 갱신·제어 Decimation·센서 수집 순서를 확인한 결과가 아니다.

1. 정책 Action을 보존하고 제어기에 전달한다. 현재 Action과 직전 Action을 보상 계산 전에 모두 사용할 수 있어야 한다.
2. 물리 Step 이후의 물체 정답, 접촉 정보, 촉각·Wrench 및 손 상태를 수집한다. 각 값의 시점과 좌표계를 맞춘다.
3. 물체 위치 오차로 $r_{\mathrm{goal}}$을 계산한다. 유효한 접촉 법선·목표 방향이 정의되면 $r_{\mathrm{normal}}$을 계산한다.
4. 선택 면의 17D 접촉값으로 $C_t$, $N_t$, $r_{\mathrm{contact}}$를 계산하고, 현재·직전 Action으로 $r_{\mathrm{action}}$을 계산한다.
5. CoP 모델이 유효한 경우 평면·외부 Wrench·공간 일관성·시간 변화를 평가해 회전 목표와 $r_{\mathrm{sg}}$를 계산한다. 구체 함수는 확정 후 구현해야 한다.
6. 성공·실패·시간 제한을 판정하고, 성공 이벤트에 $r_{\mathrm{time}}$을 지급하도록 처리한다. 성공과 실패가 동시에 발생한 경우의 우선순위는 별도 명세가 필요하다.
7. 항별 가중합을 기록한 뒤 직전 Action·CoP 이력을 갱신한다. Reset 시 이전 Episode의 이력이 섞이지 않도록 한다.

선반 접촉, 전도, Impulse 또는 Z 상승을 평가·종료에서 다룬다고 해서 해당 페널티가 이 여섯 항의 보상식에 이미 포함된 것은 아니다. 최신 PDF의 합산식에 없는 항은 구현·검증 여부를 별도로 기록한다.

## 10. 가중치 조정과 보상 기여 검증

초기 목표는 목표 도달을 중심으로 접촉·명령 안정성을 유지하고 조기에 완료하도록 하는 것이다. 실제 가중치 조정에서는 목표에 정지하지 않고 접촉 보상만 누적하는지, Action 변화 벌점 때문에 필요한 보정을 회피하는지, 회전 목표 추종이 물체를 목표에서 멀어지게 하는지 등을 확인해야 한다. 이는 발생한 결과를 보고한 것이 아니라 보상 설계의 확인 항목이다.

`PROPOSED`인 확인 방법은 항별 Step·Episode 기여와 물체 위치 오차·접촉 소실·완료 시간을 함께 기록하는 것이다. 보상 합만 높아졌다는 이유로 성공·안정성이 개선되었다고 결론 내리지 않는다. CoP 신뢰도가 낮은 조건에서도 보조 항이 주보상을 압도하는지 확인한다.

실제 PDF 32쪽의 Reward Ablation은 동일한 센서 관측·학습 조건 아래 다음 세 구성을 각각 학습하는 계획이다. 표는 구성 항만 나타내며, 발표 그림에 생략된 최종 가중치를 새로 정한 것이 아니다.

| --- | --- | --- |
| Case 1. Base Rewards | Goal + Action + Time | 과업 목표·명령 연속성·조기 완료의 기준 성능 |
| Case 2. w/o Sub-Goal | Case 1 + Normal + Contact | 접촉 관련 보상을 추가한 안정성·도달 성능 변화 |
| Case 3. Proposed Rewards | Case 2 + Sub-Goal | 회전 목표가 학습 효율과 최종 Sweeping 성능에 미치는 추가 효과 |

Case 1–2는 Normal과 Contact를 함께 추가하므로 각 항의 단독 효과를 분리하는 실험은 아니다. Case 2–3은 센서 입력을 그대로 두고 $r_{\mathrm{sg}}$의 추가 효과를 확인한다. 회전 목표 추종 오차가 줄더라도 성공률·최종 물체 위치 오차·학습 효율이 개선되었는지 별도로 평가해야 한다. 전체 지표와 통제 조건은 [학습·평가 계획](06_Evaluation_and_Schedule.md)을 따른다.

## 11. 과거 초안에서 갱신된 내용과 남은 명세

| 항목 | 과거 문서 | 최종 PDF 기준 |
| --- | --- | --- |
| 보상 전체 구성 | 초기 Method는 보상 항의 방향과 미정 수치를 설명 | 여섯 항의 가중합과 CoP 회전 Sub-Goal 제시 |
| Normal의 기준 방향 | 2026-09-30 정리본은 명령 Sweep 방향으로 설명 | 현재 물체 위치에서 목표 위치로 향하는 방향 |
| Contact | 2026-09-30 정리본은 $\beta C_t+(1-\beta)N_t-1$ | $\beta_1C_t+\beta_2N_t$ |
| Action Rate | 2026-09-30 정리본은 양의 식과 부호 미확인 표시 | Arm·Hand 변화량 앞 음수 부호 명시 |
| Time | 2026-09-30 정리본은 Step 시간 비용 | 성공 시 기본 보상 + 조기 완료 보상 |
| Sub-Goal | 초기 Method·2026-09-30 정리본에는 최신 흐름 미포함 | CoP 변화 → 신뢰도를 반영한 회전 목표 추종 |
| Reward Ablation | 2026-09-30 정리본은 후속 후보로 분류 | 최종 PDF에 세 조건의 비교 계획 포함 |

대조 대상은 [1차 Method 초안](1st_draft/03_Method.md), [2026-09-30 발표 정리본](2026-09-30_midterm/README.md), [요약문](2026-09-30_midterm/midterm_summary.md)이다. 과거 문서는 작성 당시의 기록으로 보존하며, 그 식을 최신 PDF와 혼합하지 않는다. [기존 발표 진행 메모](1st_draft/HELP.md)와 [대본](1st_draft/05_Midterm_Presentation_Script_15min.md)은 Sub-Goal의 설명 흐름을 보충한다.

현재 남은 명세는 전체·내부 가중치의 최종값, Normal의 유효성·집계, Action 평가 Scale, 성공 보상의 이벤트 처리, CoP 평면·외부 Wrench의 구성, 신뢰도·회전 목표·$r_{\mathrm{sg}}$ 함수다. **최종 PDF에 식이 있는 항과, 계산 의도만 제시된 Sub-Goal을 구분하여 구현해야 한다.** 이 문서는 미명시 수치를 발명하거나 새 보상 함수를 확정하지 않는다.
