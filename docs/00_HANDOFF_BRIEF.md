# Blind Sweeping — 단일 파일 인계 요약

**기준일: 2026-09-14. 이 문서만 전달해도 현재 연구 방향을 파악할 수 있도록 작성했다.**

## 연구가 무엇인가

선반에서 물체를 치워 공간과 시야를 확보하는 상위 시스템의 하위 조작 기술을 연구한다. 본 연구는 석사생 1의 담당 영역이며, 초기 시각 정보와 상위 계획으로 주어진 조건에서 **실행 중 시각 관측을 갱신하지 않고 손목 F/T와 Hand 촉각을 이용해 지정된 물체를 미는 정책**이 대상이다. 초기 시각 정보까지 제거하는 연구가 아니다.

‘대상 물체’는 **이번에 밀 물체**다. 선반 뒤에서 궁극적으로 찾으려는 물체와 구분한다. 상위 판단기의 선택, 전체 탐색 계획, 물체 근처까지의 접근은 직접 구현 범위에서 분리한다. 하위 정책은 접근 완료 후의 불확실한 근접 상태에서 시작한다.

## 지금 무엇에 집중해야 하나

9월 14일 교수 피드백은 **복잡한 랜덤 배치 회피·추가 간섭 판별을 먼저 붙이지 말고, 시각 없이 제한된 힘·촉각 정보로 기본 Sweeping을 수행할 때의 문제를 깊이 검증하라**는 것이다.

핵심 질문은 실제 접촉 위치가 달라도 동작하는지, 센서가 없는 손 부위에 접촉하면 어떻게 되는지, 가벼운 물체에서 F/T 신호가 충분한지, F/T와 촉각이 각각 어떤 정보를 제공하는지, 센서 커버리지·해상도가 성능을 어떻게 제한하는지다. 이것들은 **이미 검증된 하드웨어 결함이 아니라 확인해야 할 연구 질문**이다.

복잡한 clutter는 연구 배경으로 유지할 수 있다. 다만 물체 수나 기능 수를 늘리는 것 자체를 기여로 삼지 않는다. 단일 물체 조건으로 기본 문제를 분리해 검증하는 것은 가능하지만, 최종 환경이 단일 물체로 확정된 것은 아니다.

## 시스템과 센싱 계획

```text
초기 시각 관측 / 상위 판단
  → 조작할 물체와 목표 방향·거리 결정
  → 별도 접근 계획·실행
  → 물체 근처에서 하위 정책 시작
  → 초기 정보 + 실시간 F/T·촉각 + 채택할 고유감각/이력
  → Cartesian 조작 명령
  → 종료·결과 전달 방식은 추가 설계
```

장비 계획은 UR5e → ATI Axia80-M8 6축 F/T → Inspire Dexterous Hand다. 프로젝트에서는 Hand 6자유도와 17개 촉각 영역을 전제로 논의했다. 이전 연구안은 각 영역의 gram-force Grid를 scalar 또는 Boolean 하나로 축약하여 17차원으로 사용하는 방안을 제시했다. 실제 제품의 원시 포맷·센서 위치·부착 범위·해상도·샘플링률을 검증한 명세는 아직 없다. 9월 14일 회의에서는 센서와 Hand 실물이 아직 준비되지 않았다고 보고되었다.

초기 대상 Pose, 목표 방향·거리, 실시간 6축 F/T, 촉각 표현이 입력의 중심이다. 정확한 관측 벡터, 고유감각·history 구성, tactile 축약 방식은 미정이다. 23차원은 F/T+17개 축약값일 뿐 전체 입력 차원이 아니다.

## 최신 결정과 반드시 남겨 둘 미정 사항

| 항목 | 현재 해석 |
| --- | --- |
| Vision | 초기 사용 허용. 한 번의 하위 Sweep 중 지속 물체 시각 추적 없음 |
| 초기 주변 정보 | 처음부터 전혀 모른다는 강제 가정은 9/14에 수정. 하위 정책에 넣을 범위는 미정 |
| 시작 조건 | 별도 접근이 완료된 물체 근처. 실제 접촉과 촉각 감지는 보장되지 않음 |
| 방향·거리 | 목표 조건의 중심. 좌우는 구체적인 출발안이며 전방향 범위는 추가 결정 필요 |
| Geometry | 9/13안은 명시 입력 없음. 9/14에 상세 입력 사양을 다시 확정하지 않음. 완전 형상 입력을 자동 추가하지 않음 |
| Controller | 9/10 보고 구현은 OSC. 이후 연구안에는 Diff-IK 등의 변환이 등장. 최종 실물 제어 경로 미확정 |
| Hand 제어 | 사전 정의 자세 구상. 손가락 전체 자유 제어를 확정하지 않음 |
| 간섭 판별·중단 | 9/13의 중심 제안에서 9/14 이후 후순위 확장으로 이동 |
| 완료·대기 | 물체 목표 도달과 EEF 이동을 구분. 실물의 Blind 종료 판정과 대기 전환 방식은 미정 |
| 안전 정지 | 연구용 간섭 판별의 우선순위와 별개. 안전 기능을 제거하거나 자동 해제하지 않음 |

## 실제로 어느 정도 진행됐나

9월 10일 회의에서 기존 Sweeping 환경을 Joint action에서 Cartesian/OSC로 바꾸고, 일부 상대 관측과 EEF·물체 초기 상태 랜덤화를 시험했다고 보고했다. 다양한 초기 joint configuration에서 Sweeping이 가능했다는 보고도 있다.

그러나 당시 **F/T 없음, tactile 없음, 완전한 Blind 정책 아님, Sim-to-Real 전, 실제 접근 오차 기반 초기 분포 없음**으로 명시되었다. 이 결과는 사전 feasibility이며 현재 연구의 완성 결과가 아니다. 9월 11일에는 Isaac Lab/RSL-RL PPO 설정 코드가 대화에 공유되었다. 그 설정만으로 현재 observation이나 정책 성능을 알 수 없다.

이 인계에서는 실제 학습 저장소·코드 커밋·로그·체크포인트를 확인하지 못했다. 따라서 ‘구현되어 있다’는 표현은 과거 보고 수준과 코드 검증 수준을 구분해야 한다.

## 다음에 해야 할 일

**첫째, 현재 사실을 고정한다.** 실제 코드의 actor observation, reset, action→controller 경로, reward·termination을 읽고 구현 현황표를 만든다. 장비의 실제 준비 상태와 센서 데이터 구조를 확인한다. 이미 쓰던 환경을 무작정 교체하지 않는다.

**둘째, 선행연구와 센싱 feasibility를 병행한다.** Blind/부분 시각 관측 아래 F/T·촉각 조작 연구를 센서 구성·커버리지·해상도·태스크·실물 검증 기준으로 비교한다. 실물이 없으면 명시적인 가정으로 시뮬레이션 센서 모델을 만들고, 접촉 위치·센서 사각지대·약한 신호 조건을 분리해 확인한다.

**셋째, 최소 조작 실험을 만든다.** 접근 완료 후 근접 상태에서 단순 물체를 밀며, 학습·평가 정답과 actor 입력을 분리한다. 목표 물체 이동과 Hand 이동을 따로 측정한다. 기본 제어·보상·센싱을 확인한 뒤 F/T-only, tactile-only, 결합 센싱, 필요시 history 사용을 비교한다. 이 비교 구성은 인계 문서의 제안이지 이미 승인된 실험표는 아니다.

**넷째, 실제 접근 오차와 실물 전달을 검증한다.** 상위 접근을 반복하여 EEF–물체 상대 pose 오차를 측정하고 초기 분포를 갱신한다. 센서·제어가 실물에서 검증되면 시뮬레이션과 실제의 차이와 실패 조건을 로그로 남긴다. 간섭 판별 등 확장은 이 기본 결과 이후 필요성을 판단한다.

## 다른 에이전트가 하지 말아야 할 일

Pivoting·접근·장면 해석을 석사생 1의 필수 과업으로 합치지 않는다. 과거 structured compliance·strict rotation constraint·RNN·hybrid action 제안을 현재 확정 요구사항으로 되살리지 않는다. 사용자가 초안이라고 명시한 roadmap을 절대 규격으로 취급하지 않는다.

훈련용 GT Pose를 최종 Blind actor에 계속 제공한 뒤 Blind 성능이라고 보고하지 않는다. 접촉 ID나 시뮬레이션 전용 정보가 관측에 새지 않도록 한다. F/T 증가가 곧 주변 물체 간섭을 의미한다고 단정하지 않는다. EEF 이동 거리로 물체 성공을 대체하지 않는다. PPO 설정을 바꾸기 전에 실제 실패 원인을 확인한다.
