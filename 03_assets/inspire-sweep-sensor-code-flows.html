패드 하나는 무엇으로 구현되어 있는가?

구조도 · 기존 USD의 손바닥 패드 한 개를 예로 든다. 17개 패드는 같은 방식으로 선택한다.

패드라는 이름의 파이썬 센서 객체가 곧 물리 패드는 아닙니다. 원본 USD에는 패드 body·고정 조인트·mesh가 이미 있습니다. spawn_ur5e_axia80_inspire()가 이 USD를 로드하고 activate_contact_sensors=True를 넘깁니다. Isaac Lab이 강체에 contact-report API를 적용한 뒤 ContactSensor가 그 body의 물리 접촉을 읽습니다.

감지 영역은 mesh에서 어떻게 만드는가?

Flowchart · build_metadata()의 실제 연산 순서. 좌표 변환 식은 Gf의 행벡터 관례를 따른다.

build_tactile_regions.py가 collision mesh를 읽고 scipy.spatial.ConvexHull로 영역을 만듭니다. footprint.equations의 각 행은 a·x + b·y + c ≤ 0인 반평면입니다. 런타임은 모든 변에 대해 ≤ 0.0005 m를 적용합니다.

Z 하한은 pad hull의 법선 Z 성분이 0.5 이상인 facet에 속하는 정점들의 최소 Z에서 0.5 mm를 뺍니다. Z 상한은 같은 pad frame에서 부모 collider 정점의 최대 Z에 0.5 mm를 더합니다. 따라서 이 구간은 패드 두께와 다릅니다. 부모 hull에 묻힌 패드 위의 접촉을 감지하려고 바깥쪽으로 확장한 관측용 영역입니다.

--check는 geometry에서 metadata를 재생성해 저장 JSON·source hash와 비교하며 파일을 쓰지 않습니다. --check 없이 실행할 때만 JSON을 저장합니다. 기존 USD를 수정하는 단계는 없습니다.

설정한 센서는 어떤 물리 데이터를 읽는가?

Flowchart · 초기화 때 view와 인덱스를 준비하고, 관측 평가 때 직접 힘과 상세 접촉점을 읽는다.

TactileContactBits.__init__()는 센서의 실제 body_names와 17개 기대 이름을 대조하고 _body_ids를 만듭니다. ProjectedTactileContactBits.__init__()는 로봇 pose용 _robot_ids와 부모별 ParentContactRegions도 캐시합니다. 두 인덱스는 서로 다른 배열의 순서를 맞추는 역할입니다.

get_contact_data() 반환을 scalars, points, normals, _, counts, starts로 풉니다. counts와 starts는 [N,K](K는 filter 수), 원시 점 buffer는 [C,3](C는 capacity)입니다. uint32 인덱스를 long으로 바꾸고 reset 행의 count를 0으로 만듭니다. repeat_interleave로 각 유효 점의 행을 만들고 indices = starts[rows] + offsets로 gather합니다. env_ids = rows // K, force = scalar × normal입니다.

세 임계값을 구분합니다. ContactReport의 0은 접촉 보고 설정, ContactSensorCfg.force_threshold는 air/contact 시간 추적용, 실제 정책 Binary의 0.05 N은 ObsTerm.params["threshold_n"]입니다. buffer 범위 초과·포화·비정상 수치는 오류로 처리합니다.

 106  def unpack_contact_points(raw, fresh, num_envs, total_contacts=None):
 107      """Gather live per-pair slices with a known allocation size.
 108  
 109      The runtime batches all parent counts into one host readback, then supplies
 110      total_contacts to avoid a separate CUDA synchronization per parent view.
 111      Unused/reset slices are never gathered or classified.
 112      """
 113      scalars, points, normals, _, counts, starts = raw
 114      if counts.ndim != 2 or counts.shape[0] != num_envs or starts.shape != counts.shape:
 115          raise RuntimeError("Expected contact counts/starts shaped (num_envs, filters) for one parent body")
 116      if counts.shape[1] == 0 or points.ndim != 2 or points.shape[1] != 3 or normals.shape != points.shape or scalars.numel() != len(points):
 117          raise RuntimeError("Expected a filtered tactile contact buffer with scalar forces and 3D points/normals")
 118      # PhysX provides uint32 indices; torch indexing requires signed long.
 119      counts, starts = counts.to(torch.long), starts.to(torch.long)
 120      filter_count = counts.shape[1]
 121      counts = torch.where(fresh[:, None], counts, 0)
 122      live = counts > 0
 123      torch._assert_async(
 124          ~((counts < 0) | (live & ((starts < 0) | (starts + counts > len(points))))).any(),
 125          "Invalid or truncated tactile contact buffer",
 126      )
 127      total = int(counts.sum()) if total_contacts is None else total_contacts
 128      if total == 0:
 129          return points[:0], points[:0], normals[:0], torch.empty(0, dtype=torch.long, device=points.device)
 130      torch._assert_async(counts.sum() < len(points), "Tactile contact buffer full; increase max_contact_data_count_per_prim")
 131      counts = counts.flatten()
 132      rows = torch.repeat_interleave(
 133          torch.arange(counts.numel(), device=counts.device), counts, output_size=total,
 134      )
 135      block_starts = counts.cumsum(0) - counts
 136      offsets = torch.arange(total, device=counts.device) - block_starts[rows]
 137      indices = starts.flatten()[rows] + offsets
 138      position, normal = points[indices], normals[indices]
 139      force = scalars[indices].reshape(-1, 1) * normal
 140      torch._assert_async(
 141          torch.isfinite(position).all() & torch.isfinite(normal).all() & torch.isfinite(force).all(),
 142          "Tactile contact point data contains non-finite values",
 143      )
 144      return position, force, normal, rows // filter_count

한 접촉점이 어떻게 17개 중 한 bit가 되는가?

Flowchart · ParentContactRegions.accumulate()와 ProjectedTactileContactBits.__call__()의 텐서 연산.

torch.einsum("mpd,ped->mpe", local[..., :2], planes[..., :2]) + planes[..., 2]가 모든 점·패드·polygon 변의 부등식을 한 번에 평가합니다. 부모별 영역의 변 개수가 다르면 남는 plane을 [0,0,-1]로 채워 항상 통과하게 합니다. normal은 회전만 하고 point는 pad 위치를 뺀 뒤 회전합니다.

한 접촉점은 같은 부모의 후보 영역 중 하나에만 배정합니다. 영역 밖이면 argmin의 값이 생겨도 valid=False로 force를 0으로 만들어 누적합니다. output.view(-1,3).index_add_(...)로 Python 환경별 반복 없이 같은 환경·채널의 벡터를 합산합니다. 그 뒤 norm을 계산하므로 채널 내부에서 서로 반대인 접촉력의 상쇄는 가능합니다. 직접 경로와 투영 경로 사이의 결합은 bit OR입니다.

손바닥 채널 0의 계산 예 — 저장 geometry + 설명용 0.1 N 입력
입력·검사값·결과
sensor-local 접촉점(0, 0, 5.584) mm — metadata의 실제 부모 표면 probe
법선metadata 표면 법선의 반대 방향 사용, |local normal Z| ≈ 0.973 ≥ 0.2
영역XY polygon 내부, −0.555 ≤ 5.584 ≤ 18.347 mm → 통과
힘·Binary한 점의 법선 힘 크기 0.1 N → mapped norm ≥ 0.05 N → projected[0]=1
최종직접 pad 힘 0을 가정하면 direct[0]=0, 0 OR 1 → tactile[0]=1

0.1 N은 계산 설명과 CPU probe의 합성 입력입니다. 시뮬레이터나 실물에서 관측한 하중으로 해석하지 않습니다.
