01 / TACTILE · BASELINE-TACTILE-V0

패드 직접 접촉 + 가려진 영역의 부모 접촉 투영

적용: Isaac-Inspire-Sweep-Baseline-Tactile-v0 · ProjectedTactileContactBits · N은 병렬 환경 수

기본 Baseline-v0의 흐름: 손바닥 palm_tactile.net_forces_w → norm ≥ 0.05 N → palm_contact_bit 1D → 전체 관측 41D. 위 17D 경로는 이 term을 교체하는 파생 환경입니다.

투영이 필요한 이유: 기존 부모 링크의 convex hull이 패드 일부를 덮습니다. 기존 물리 형상을 유지하면서 접촉점이 원래 패드의 감지 영역에 해당하는지 판정합니다. 직접 패드 읽기는 상대 물체 필터가 없고, 부모 접촉 투영은 현재 mass_cylinder에만 적용합니다. 부모 링크에만 발생한 선반·바닥 접촉은 투영하지 않습니다.

채널 순서: 손바닥 1 + 엄지 4 + 검지·중지·약지·소지 각각 3 = 17. 출력은 채널별 0/1이며, 압력 이미지·변형·전단력 분포를 출력하는 모델은 아닙니다. 법선 힘은 같은 채널 안에서 합산하고 채널 간에는 합치지 않습니다.

02 / FORCE–TORQUE · SHARED IMPLEMENTATION

고정 조인트 반력 → EEF 기준 6축 wrench

적용: Baseline-v0 / Baseline-Tactile-v0 · FixedJointWrenchReader → wrist_wrench_eef

센서 모델: spawn 시 기존 wrist–hand 직접 연결을 Axia80 body와 두 고정 조인트로 교체합니다. axia80_measurement_joint는 Axia80와 Hand base 사이이며, 이 조인트를 통해 손에 전달되는 반력을 사용합니다. 별도의 F/T ContactSensor를 만드는 경로가 아닙니다.

좌표와 기준점: 로컬 Isaac Lab API는 raw wrench를 부모 body 좌표계의 반력으로 설명합니다. 현재 관측 코드는 axia80_link pose를 F로, ee_frame target pose를 C로 사용해 회전과 r × F 이동을 적용합니다. 이 그림은 코드의 변환 계약을 설명하며, 실제 PhysX 반력 기준점·부호의 물리 검증을 이번 작업에서 수행한 것은 아닙니다.

두 센서의 공통 처리: reset 시 sensor_data_fresh=False인 행은 0으로 만들고, 다음 step에서 갱신된 값을 읽습니다. 유효 행의 비정상 수치·센서 구성은 오류로 처리합니다. 전체 관측에는 현재 물체 위치도 포함되므로 이 두 환경을 최종 Blind 정책으로 해석하지 않습니다.
