INSPIRE SWEEP BASELINE / UML / 2026-10-14

학습 실행과 Isaac Lab 연결

UML 시퀀스 다이어그램. 네 task의 공통 실행 경로와 PPO 학습 주기를 보여준다. 초기 설정 로딩은 학습 스크립트에, Manager·Scene·물리 호출은 Isaac Lab 실행 계층에 묶었다.

환경 선택과 생성

  1. AppLauncher(args_cli)가 Isaac Sim 앱을 시작한다. import inspire_sweep_baseline의 gym.register()가 task ID와 환경·PPO 설정 entry point를 연결한다.
  2. @hydra_task_config(task, agent)가 등록된 env_cfg·agent_cfg를 읽고 CLI override를 반영한다. gym.make(task, cfg=env_cfg)는 네 환경 모두 InspireSweepEnv를 생성한다.
  3. InspireSweepEnv.__init__()가 sensor·target 버퍼를 준비하고 부모 생성자를 호출한다. Isaac Lab이 Scene, SimulationContext와 Manager를 구성하며 startup Event를 적용한다.
  4. Wrapper 생성 시 env.reset()를 먼저 호출한다. Runner 생성 시 관측 그룹과 PPO 설정으로 actor·critic·rollout storage를 구성한다. 두 초기화의 내부 호출은 그림에서 묶었다.

Rollout과 PPO 업데이트

  1. runner.alg.act(obs)가 Action 8D를 샘플링한다. 36 step 동안 wrapper.step(actions) → InspireSweepEnv.step() → 부모 ManagerBasedRLEnv.step()를 반복한다.
  2. 부모 step 순서: Action 처리 → 물리 step 2회 → Termination → Reward → 종료된 환경 reset → Command/interval Event → Observation. Reward는 step_dt=0.02를 적용한다.
  3. Wrapper가 terminated | truncated를 done으로 합치고 TensorDict 관측을 반환한다. Runner는 alg.process_env_step()으로 transition을 저장한다.
  4. 36 step 뒤 alg.compute_returns(obs) → alg.update()를 실행한다. 기본 8 epoch·4 minibatch이며 50 iteration마다 checkpoint를 저장한다. ACT/PPO UPDATE는 같은 RSL-RL 참여자 안의 PPO 호출을 요약한다.
