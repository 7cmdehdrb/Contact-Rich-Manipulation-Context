환경 상속과 구성 함수

UML 클래스 다이어그램. Isaac Lab 기반 설정에서 네 환경이 파생되는 구조와 주요 callable 연결을 보여준다. 클래스 박스는 실제 환경 Cfg이며, 모듈 박스는 재사용 함수와 term을 묶었다.

상속과 호출을 구분해 읽기

속이 빈 삼각형은 자식 → 부모 상속이다. super().__post_init__()는 그 부모 구현을 먼저 호출한다. CALLS 점선은 설정 생성 시 직접 호출하는 함수, OBS TERM·GOAL TERMS 점선은 Manager가 이후 실행할 callable을 설정에 연결하는 의존성이다.

Omni → Baseline은 직접 상속이다. Realistic Physics Cfg를 상속하지 않고 apply_realistic_physics()와 Event Cfg를 재사용한다. Initial-Privileged → Realistic Physics → Baseline은 실제 설정 상속 체인이다.

아래 기호 사전은 UML의 여섯 관계를 설명한다. 본문에서는 상속과 의존만 사용했다. 오른쪽 MDP 박스는 여러 모듈의 주요 term을 모은 것이며 별도 환경 클래스가 아니다. 모든 task의 실행 클래스는 InspireSweepEnv(ManagerBasedRLEnv)로 같다.

구성 함수가 실행되는 시점

apply_realistic_physics()는 질량 기본값을 설정하고 로봇·선반·실린더의 spawner를 교체한다. 재질 생성과 바인딩은 PhysX 환경 복제 전에 실행되며, 매 reset마다 USD를 변경하는 방식이 아니다.

RealisticPhysicsEventsCfg(EventsCfg)의 startup은 initialize_realistic_materials()로 버퍼를 준비하고 reset은 randomize_episode_physics()로 질량·마찰을 적용한다. 후자는 초기화 함수도 안전하게 재호출한다.

ObservationManager는 InitialObjectPositionInRoot를 호출해 초기 물체 위치를 저장하고 live_object_state_in_root()로 critic용 13D를 만든다. Omni의 goal term은 Event·Reward·TerminationManager에서 실행된다.
