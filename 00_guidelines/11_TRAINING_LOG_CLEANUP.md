# 학습 로그 폴더 정리 지침

[Workspace 안내](10_WORKSPACE_GUIDE.md) · [개발 지침](09_DEVELOPMENT_GUIDE.md)

## 실행 조건과 범위

**사용자가 명시적으로 정리를 요청한 경우에만 실행한다.** 일반 개발·테스트·Git 동기화·디스크 공간 부족이나 이 지침의 존재를 이유로 임의로 정리하거나 자동화·주기 실행하지 않는다.

기본 입력은 workspace의 `logs/TEMP`, 목적지는 `logs/backup`이다. **`logs/rsl_rl`은 이동·삭제·이름 변경·내용 수정 대상에서 제외한다.** 다른 경로는 별도 명시적 요청 없이 정리하지 않는다. 이 지침은 사용자가 요청한 학습 로그 정리에만 적용하며, 일반 Git 동기화에서 gitignore 파일 삭제를 허용하는 규칙이 아니다.

## 분류와 학습 진행 기준

1. 현재 `src/inspire_sweep_baseline`의 실제 Gym 등록 ID 목록을 확인한다. 오래된 문서의 환경 수나 폴더 이름만으로 판단하지 않는다.
2. 각 실행 폴더의 `params/env.yaml`, `params/agent.yaml`, 실행 기록과 환경 등록·실험 이름의 대응을 대조한다. 사용자 지정 experiment_name은 환경 ID와 다를 수 있다. 과거 설정과 현행 설정의 수치 차이만으로 미등록 판정을 내리지 않는다.
3. 삭제 판단은 환경 전체가 아니라 **개별 학습 실행(run)** 단위로 한다. 같은 환경의 짧은 실행을 삭제해도 충분히 학습된 다른 실행은 보존한다.
4. **500 iteration 미만인 실행은 삭제하고 500 이상은 보존한다.** `model_N.pt` 번호는 저장 간격 때문에 실제 진행보다 작을 수 있으므로 삭제 후보는 TensorBoard의 iteration 기반 `Loss/*` step 또는 신뢰할 수 있는 학습 기록까지 확인한다. 시간·누적 timestep 기반 지표와 혼동하지 않는다. 0부터 시작하는 iteration 인덱스 499는 500회 완료이므로 보존한다.
5. 등록 여부와 무관하게 위 진행 기준을 적용한다. 진행 근거가 없거나 로그가 손상된 경우 임의로 0으로 간주해 삭제하지 말고 보존하고 보고한다.
6. 보존 대상 중 등록된 환경은 정확한 환경 ID 폴더로, 미등록 또는 식별이 확정되지 않은 환경은 `Unregistered`로 이동한다. 식별이 불확실한 경우 그 사실을 기록한다.

## 결과 구조와 이동

```text
logs/
├── TEMP/                          # 정리 후 빈 입력 폴더
├── backup/
│   ├── Isaac-Inspire-...-v0/
│   │   └── <원래 학습 실행 폴더>/  # checkpoint, params, TensorBoard, git 등 전체
│   └── Unregistered/
│       └── <원래 학습 실행 폴더>/
└── rsl_rl/                        # 정리 대상 제외
```

복사가 아닌 `mv`에 해당하는 디렉터리 이동을 사용한다. 원래 실행 폴더 이름과 내부 파일을 유지하며 중간 experiment_name 폴더는 남기지 않는다. 목적지에 동명 실행이 있으면 덮어쓰기·병합하지 말고 원래 실험 이름 등을 접두사로 붙여 충돌 없이 보존하고 대응표를 남긴다.

실행 중인 학습 폴더, 범위를 벗어나는 심볼릭 링크, 판정이 불확실한 파일은 임의 삭제하지 않는다. 이동·삭제 목록과 근거를 먼저 확정한다. 완료 후 이동 파일 보존·중복·누락, 입력 잔여 항목, `logs/rsl_rl` 변경 여부를 검증한다. 실제 명령·결과·미검증 범위와 원래 경로→새 경로 대응은 개발 로그에 남긴다.
