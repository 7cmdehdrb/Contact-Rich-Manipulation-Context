# 초기 부분 관측 OBB — 최종 환경 통합 인계

관측 원리만 독립적으로 이해하려면 [초기 부분 관측 OBB의 구성 방법](INITIAL_PARTIAL_OBSERVATION_OBB_METHOD.md)을 읽는다. 해당 설명은 코드·외부 문서 참조 없이 완결된다.

기준일: 2026-11-18. 현재 코드와 확정 요구사항을 정리한 인계 문서다. **최종 환경에는 아직 연결하지 않았다.** 구체적인 통합 대상 환경 ID·버전과 정책 입력 형식은 확정되지 않았다.

근거: [개발 명세](../../01_plan/environments/2026-11-16_observed_obb_visualization_spec.md) · [구현·검증 로그](../logs/2026-11-18_observed_obb_implementation.md) · [도메인 용어](../../GLOSSARY.md) · [패키지 실행 안내](../../../../src/observed_obb/README.md).

## 1. 현재 구현과 적용 범위

현재 학습·정책·checkpoint·제어 연결은 없다. 사용자의 지시에 따라 변경은 커밋하지 않았다.

## 2. 유지할 관측 의미

1. **타겟과 활성 장애물 모두** 관측 대상이며 서로를 가린다. 로봇·손·선반은 가림 계산에 넣지 않는다.
2. 관측 방향은 고정 정면의 평행 시선이다. 현재 선반 +X에서 -X를 바라보며 좌우 폭은 선반 Y 방향이다. 검토용 카메라 회전과 독립적이다.
3. 실제 mesh 대신 물체 방향을 따르는 전체 회전 박스로 근사한다. 이미지·depth 렌더링·점군 샘플링을 사용하지 않는다.
4. 가리는 물체의 Z 높이는 무한으로 취급한다. 낮은 앞 물체 때문에 뒤 물체 윗부분이 추가로 보이는 결과를 만들지 않는다.
5. 남은 좌우 가시 구간에서 **원본 박스의 전체 앞뒤 깊이와 실제 물체 높이**를 유지한다. 정면의 얇은 표면만 피팅하는 방식이 아니다.
6. 떨어진 가시 조각은 독립 관측 물체다. 같은 실제 물체에서 나왔다는 이유로 합치지 않는다.
7. 각 조각의 노출 폭이 **2cm 이상**, 원본 물체의 가림 전 정면 전체 폭 대비 비율이 **20% 이상**이어야 한다. AND 조건이며 경계값을 포함한다. 서로 떨어진 조각의 폭·비율을 합산하지 않는다.
8. 관측에서 탈락한 물체도 가림 계산에는 남는다. 전체가 가려지면 관측 OBB를 생성하지 않는다. 전체 폭이 2cm 미만이면 완전 가시여도 제외된다.
9. 통과한 조각의 XY 절단 형상에 최소 면적 직사각형을 피팅하고 실제 높이를 결합한다. 수직축은 유지하며 원본 yaw를 강제로 유지하지 않는다.
10. 독립 관측 ID에는 타겟/장애물 의미 분류나 원본 물체 대응을 담지 않는다. 시간에 따른 동일 물체 추적도 없다. 동일 배치의 관측 기하는 결정적이며 노이즈·무작위 가시성 반전은 없다.

원본 전체 폭은 시뮬레이터 근사에 사용하는 GT 기하 정보다. 향후 실제 Perception에서 숨겨진 전체 폭을 어떻게 얻을지는 이번 구현에서 해결하지 않았다.

## 3. 계산 인터페이스와 좌표 계약

```python
from observed_obb import Box, observe

snapshot = observe(
    boxes,                    # 활성 타겟·장애물의 Box 시퀀스
    direction=(-1.0, 0.0),    # 관측자에서 장면 안쪽으로 향하는 XY 방향
    minimum_width=0.02,
    minimum_ratio=0.20,
)
```

| 항목 | 실제 코드 계약 |
| --- | --- |
| `Box.center` | 기하 중심 `(x, y, z)`, 미터. asset root 위치와 다를 수 있음 |
| `Box.size` | yaw 축을 따르는 가로·세로와 실제 높이. 양의 전체 길이이며 half extent가 아님 |
| `Box.yaw` | 입력 좌표계에서 Z축 회전, 라디안 |
| `direction` | Box와 같은 좌표계의 고정 XY 관측 방향 |
| 반환값 | 불변 `Observation` 튜플. 각 항목은 `observation_id`와 `box` |
| 관측 개수 | 가변. 빈 결과가 가능하며, 분리 조각 때문에 물리 물체 수보다 많을 수 있음 |
| ID | 현재 스냅샷 내부 식별자. 번호·순서는 의미 라벨이나 시간상 동일성을 보장하지 않음 |

현재 구현은 단일 장면을 처리하는 NumPy CPU 계산이다. batched tensor·GPU 커널·정책용 고정 길이 tensor를 제공하지 않는다.

입력 연결 시에는 다음 정보를 보존한다.

- 스포너에서 이미 스케일된 local bounds를 받는다. 스케일을 다시 곱하지 않는다.
- local bounds의 중심 오프셋을 물체 방향으로 회전한 다음 root 위치에 더한다. root 좌표를 그대로 OBB 중심으로 사용하는 오류를 피한다.
- 물체 크기는 local bounds의 상한에서 하한을 뺀 전체 길이다. 높이 중심과 바닥 정렬도 함께 반영한다.
- 모든 물체와 관측 방향을 같은 좌표계에 둔다. 현재 어댑터는 회전하지 않은 선반을 전제로 한다. 선반이 회전하는 환경에서는 방향과 yaw도 함께 변환해야 한다.
- 평행 환경을 연결한다면 환경별 물체만 입력에 포함해야 한다. 다른 환경의 물체나 비활성 주차 후보가 가림을 유발하면 안 된다.

OBB의 동등한 방향 표현이 여러 개일 수 있다. 정책용 yaw 표현·정규화는 아직 정하지 않았으며, 현재 기하의 결정성과 정책 입력 표현의 연속성을 같은 것으로 간주하지 않는다.

## 4. 관측 스냅샷의 수명

현재 흐름은 `배치 완료 → observe → 스냅샷 저장 → 고정 표시`다.

| 동작 | 배치 | 관측 스냅샷 |
| --- | --- | --- |
| 최초 실행 | 생성 | 한 번 생성 |
| New placement | 새 후보 선택 | 갱신 |
| Reobserve current placement | 유지 | 같은 배치로 다시 계산 |
| 참고 박스 토글 | 유지 | 유지 |
| 뷰어 회전·일반 프레임 갱신 | 유지 | 유지 |

최종 환경에서는 해당 환경의 초기 배치가 확정된 시점과 스냅샷 생성을 연결해야 한다. 매 step마다 실시간 물체 pose로 다시 관측하는 동작은 현재 합의 범위가 아니다. 부분 reset이 있는 경우 어떤 환경의 스냅샷을 갱신하는지 별도 검증이 필요하다.

## 5. 후속 변경: 무제한 실행과 가림 배치

### 무제한 실행

`--frames` 옵션과 프레임 수에 의한 자동 종료 조건을 제거했다. 사용자가 뷰어를 닫을 때까지 실행하며, `--validate` 수행 후에도 유지한다. 이것은 독립 뷰어의 실행 수명 변경이다. 최종 RL 환경의 episode 길이·timeout·termination을 없애라는 요구로 해석하지 않는다.

### 가림을 확인하기 위한 배치 선택

기존 CircleResetLayout의 후보를 그대로 사용하되, 다음 조건을 만족하는 후보를 선택한다.

- 활성 물체가 적어도 2개다.
- 어떤 두 물체의 정면 좌우 투영이 적어도 2cm 겹친다.
- 겹침 바깥에 최소 폭·비율을 만족할 여유가 남도록 겹침의 상한을 둔다. 두 구간 중 하나가 다른 구간에 완전히 포함되는 쌍은 이 선택 조건을 만족하지 않는다.
- 최대 256회 확인하고 실패 시 오류를 알린다. 조건을 무시한 배치를 조용히 반환하지 않는다.

실제 위치를 강제로 이동시키거나 물체를 관통시키지 않는다. 기존 배치의 충돌 여유·선반 경계 조건을 유지한다. 단, **후보를 골라 쓰므로 검토용 배치 분포는 기존 무조건 표본과 달라진다.** 이 변경은 사용자 후속 요청으로 적용했으며 학습 환경에는 연결하지 않았다.

추가 물체의 가림까지 고려한 최종 관측 개수나 모든 물체의 부분 노출을 보장하지 않는다. 관측 결과를 만들기 위한 피팅과 별도로 OBB 피팅을 반복하지 않고, 후보 선택에는 투영 구간만 사용한다.

## 6. 최종 환경 통합 시 남은 결정과 작업

아래는 기존 기능을 연결할 때 해결할 접점이다. 이번 문서에서 새로운 정책 구조나 수치를 확정하지 않는다.

| 접점 | 현재 상태 / 후속 확인 |
| --- | --- |
| 정확한 환경 ID·버전 | 미지정. Holding·Final 중 임의 버전을 골라 수정하지 않음 |
| 입력 기하 연결 | 대상 환경의 활성 물체 mask, scaled bounds, root pose, 좌표계와 대응 필요 |
| reset 연결 | 최초 배치·부분 reset·스냅샷 유지 시점을 실제 runtime에 맞춰 검증 필요 |
| 정책 입력 | centroid를 어떤 필드로 교체하는지, Actor/Critic 반영 범위 미확정 |
| 가변 개수 처리 | padding·mask·상한·정렬·overflow 처리 미확정. 기존 물체 슬롯 수를 그대로 관측 상한으로 가정하지 않음 |
| 의미 정보 | 관측 ID만으로 타겟을 식별할 수 없음. 기존 목표·타겟 입력과 결합 방식 미확정 |
| 입력 좌표·표현 | world/shelf/EEF 변환, 크기·yaw 인코딩과 정규화 미확정 |
| 병렬 처리 비용 | 단일 CPU 결과만 있음. 목표 환경 수에서 reset 계산·전송 비용 확인 필요 |
| 검토용 후보 선택 | 학습 배치에도 적용할지는 미확정. 관측 계산과 독립적으로 판단 |
| 디버그 표시 | 관측 계산과 분리해 연결. 학습 중 표시 여부·비용은 별도 판단 |

통합 작업을 시작할 때는 대상 환경을 먼저 특정하고, 현재 관측 계산 테스트를 유지하면서 입력 변환·reset 수명·정책 입력 형식을 검증하는 순서가 적절하다. 아직 보상·종료·제어·학습 설정을 바꿀 근거는 없다.

## 7. 실행·검증과 남은 한계

workspace 루트, Isaac Lab 실행 환경에서 사용한다.

```bash
python src/observed_obb/scripts/show.py --seed 0

PYTHONPATH=src/observed_obb python -m pytest src/observed_obb/tests -q
```

| 확인 항목 | 확인된 결과 |
| --- | --- |
| 관측 계산 | 22개 테스트 통과. 가림·분리·임계값·회전 피팅·결정성 포함 |

| CPU USD 장면 | 선 표시의 물리 스키마 부재, 토글·재관측·배치 변경 확인 |
| 가림 후보 선택 | 합성 8cm 정사각형 bounds, 시드 0–49의 50개 장면 모두 잘린 OBB 생성 |
| 실제 Simple 자산·렌더·UI | GPU 드라이버 부재로 미검증 |
| 최종 환경·병렬 학습 | 미연결·미실행 |

기존 100개 합성 장면의 관측 계산 중앙값 약 1.49ms·p95 약 4.29ms는 실제 자산이나 다중 환경의 성능 보장이 아니다. 후보 재선택 추가 전 측정이므로 현재 배치 선택 전체 비용으로도 사용하지 않는다.

GPU가 사용 가능한 환경에서 원본 선반·YCB 자산 접근, 실제 표시, 카메라·버튼 조작, 기하 대조 및 실제 비용 측정을 완료해야 한다. Isaac Sim 초기화 실패가 종료 코드 0으로 끝난 사례가 있으므로 `[ObservedOBB] Live validation passed` 출력과 실제 뷰어 확인 없이 라이브 검증 통과로 기록하지 않는다.
