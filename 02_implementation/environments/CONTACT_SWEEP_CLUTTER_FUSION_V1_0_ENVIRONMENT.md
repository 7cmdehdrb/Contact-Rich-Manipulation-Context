# Contact Sweep Clutter Fusion v1_0 환경 설명

[구현 문서 안내](../README.md) · [활성 환경](../08_ACTIVE_ENVIRONMENTS.md)

**대상:** `Isaac-Inspire-Contact-Sweep-Clutter-Fusion-v1_0`  
**기준일:** 2026-10-22  
**문서 범위:** 현재 설정에 따른 환경의 목적, 입력과 출력, 보상, 종료, 학습 난이도 변화. 보상 수치는 별도 표시가 없는 한 수식으로 계산한 예시이며 학습 성과의 실측값이 아니다.

이 환경의 과제는 **선반 위의 지정된 물체를 목표 위치까지 밀고, 주변 물체와 선반을 크게 교란하지 않으면서 목표 부근에 유지하는 것**이다. 로봇은 episode 시작 시 얻은 타겟·주변 물체 정보를 사용하고, 실행 중에는 관절 상태·손끝 자세·촉각·손목 힘/모멘트로 조작한다. Actor에는 실행 중 타겟 위치를 다시 제공하지 않는다.

| 정책 입력 | 공통 policy 55D + 장애물 40D |

## 1. Scene 구성

### 1.1 구성 의도

Scene은 물체를 움직이는 능력과 접촉 과정의 안정성을 함께 학습하도록 구성한다. 타겟만 목표로 이동하면 되는 것이 아니라, 가려져서 관측하지 못한 장애물도 실제 공간에는 남아 있다. 따라서 초기 위치 정보만 따라 움직이는 것으로는 충분하지 않으며, 접촉 중 센서 신호를 이용하는 정책이 필요하다.

각 episode에서는 타겟의 초기 위치와 목표를 먼저 정하고 그 주변에 장애물을 배치한다. 로봇은 선반을 향한 고정된 초기 자세에서 시작하고 손은 열린 상태다. 이 환경에서 별도의 상위 물체 선택이나 이동 경로 계획을 학습하지 않는다. 타겟과 목표가 주어진 조건에서 근접 조작을 수행하는 것이 범위다.

### 1.2 Robot

UR5e의 여섯 관절로 손의 위치와 방향을 조절한다. 정책은 각 관절의 목표 위치를 지정하고, 관절 위치 제어기가 이를 추종한다. 손끝의 Cartesian 이동량을 직접 출력하는 구조는 아니다.

로봇 base는 고정되어 있다. 각 episode의 Arm 초기 관절각은 `[0, −2.2, 2.2, 0, 1.57, 0.785]` rad이며 순서는 shoulder pan, shoulder lift, elbow, wrist 1, wrist 2, wrist 3이다. 이를 일정하게 유지해 학습의 주요 변동이 물체 배치·목표 방향·접촉 물성에서 발생하게 한다.

Arm의 시뮬레이션 구동 속도 제한은 앞 세 관절 2 rad/s, 손목 세 관절 4 rad/s다. 이 값은 Action의 출력 범위와 별개이며, 빠른 움직임을 억제하는 보상과 과속 종료도 별도로 존재한다.

### 1.3 Hand

Inspire Hand는 손바닥과 여러 손가락으로 물체를 접촉한다. 목적은 정밀한 손가락별 자세를 모두 독립적으로 탐색하는 것이 아니라, **Arm의 이동과 손의 열림 정도를 함께 조절하여 밀기에 유효한 접촉을 만드는 것**이다.

물리 모델의 Hand 관절은 12개지만 정책의 Hand Action은 두 개다. 하나는 손가락 굽힘 관절들의 공통 열림 정도를, 다른 하나는 엄지의 대립 방향 관절을 조절한다. 손을 넓게 펴거나 굽히는 동작을 적은 입력으로 표현한다. Hand의 관절 구동 속도 제한은 1 rad/s다.

### 1.4 Sensor

**손목 F/T:** Arm과 Hand 사이의 6축 반력으로 손 전체에 전달되는 외부 접촉의 영향을 관측한다. Hand 자체의 중력 및 관성 하중을 모델로 추정하여 제거한 값을 사용하므로, 단순히 손을 지지하거나 움직이면서 발생하는 하중과 외부 접촉을 구분하려는 의도다. 센서는 특정 물체의 ID나 접촉 위치를 직접 알려주지 않는다.

관측은 EEF 기준점에서 표현한 힘 3축과 모멘트 3축이다. 부호는 Hand를 지지하는 쪽에서 Hand에 전달하는 반력 관례를 따른다. 따라서 이를 Hand에 가해진 외력과 같은 부호의 값으로 해석하지 않는다. 보정은 시뮬레이션의 Hand 물성·운동 상태에 의존하며, 실물 캔슬레이션 정확도를 보장하는 명세는 아니다.

**촉각:** 손바닥 1개, 엄지 4개, 나머지 네 손가락 각각 3개로 총 17개 영역을 사용한다. 각 영역은 힘의 크기를 연속값으로 전달하지 않고 접촉 여부를 bit로 전달한다. 해당 영역의 힘 크기가 0.01 N 이상이면 1이다. 힘 정보는 F/T가, 손의 어느 영역이 닿았는지는 촉각이 담당한다.

촉각 패드의 직접 접촉과 패드 영역에 해당하는 Hand 표면의 물체 접촉을 반영한다. 패드 바깥의 모든 Hand 접촉을 촉각이 감지하는 것은 아니다. 또한 채널은 접촉 상대가 타겟인지 장애물인지 구분하지 않는다. Scene에는 정책에 이미지를 제공하는 카메라 관측이 없으며, 초기 시각 정보는 기하학적 가시성 판정과 위치 오차로 모델링한다.

**손 전체 접촉력:** Hand base·손가락 링크·패드 등 30개 body의 월드 접촉력 벡터를 합해 손에 작용하는 합력을 계산한다. 손 전체 보상은 타겟·장애물·선반·바닥 등 접촉 상대를 가리지 않는다. 별도의 물체별 필터는 타겟을 제외한 활성 장애물과 손 사이의 힘만 모아 장애물 접촉 비용에 사용한다. 이러한 접촉 identity와 합력은 보상 계산용이며 Actor에 추가 관측으로 전달하지 않는다.

ContactSensor의 힘은 **법선 접촉력**이며 접선 마찰력을 포함한 완전한 접촉 wrench가 아니다. 여러 body·물체의 벡터를 먼저 더하므로 서로 반대인 힘은 상쇄될 수 있다. 각 힘의 크기를 더하는 방식과 다르며, 촉각 17개 bit 및 보정 F/T와도 별도의 값이다.

### 1.5 Shelf

작업 영역은 좌우 폭 1.0 m, 앞뒤 깊이 0.4 m인 선반 면이다. 초기 작업면 높이는 월드의 각 환경 원점 기준 1.05 m다. 선반은 물체를 지지하는 동시에 손목·손가락이 침범하지 않아야 하는 경계다.

선반의 움직임도 상태로 검사한다. 정책이 선반을 밀거나 손목을 지나치게 낮추는 행동은 비용 또는 종료로 연결된다. 바닥과 조명은 Scene의 지지·표시를 구성하며 정책의 이미지 입력은 아니다.

### 1.6 Object와 초기 배치

타겟과 장애물은 모두 반지름 4 cm, 높이 10 cm의 원기둥이다. 물체 위치로 사용하는 기준점은 **기하학적 중심이 아니라 밑면 중심**이다. 따라서 똑바로 선 물체의 위치 Z는 초기 작업면과 같은 1.05 m이고 기하학적 중심 높이는 1.10 m다.

질량의 80%는 아래쪽 높이 20%에, 나머지 20%는 위쪽 높이 80%에 분포한다고 모델링한다. 무게중심은 밑면에서 2 cm 위로 낮게 놓인다. 물체가 쉽게 넘어지기만 하는 과제가 되지 않게 하면서, 강한 접촉으로 발생하는 기울기와 전도는 계속 학습 대상으로 남기는 구성이다.

타겟은 선반 중앙을 중심으로 반지름 2 cm 원판 안에 면적 균일하게 배치한다. 목표는 타겟 초기 위치에서 최대 15 cm 떨어진 평면상의 점이다. 타겟 반지름과 추가 여유 2 cm가 선반 안에 남도록, 가장자리를 향하는 방향에서는 이동 거리를 줄인다. 목표 방향의 허용 범위는 6절의 curriculum이 정한다. 생성한 목표는 episode 동안 고정한다.

Zone은 장애물 **중심 위치**를 분류하는 평면 영역이다. Red는 타겟–Goal 경로의 반경 10.3 cm 캡슐을 로봇 쪽 선반 전면까지 확장한 장애물 금지 영역이다. 반경에는 물체 두 개의 반지름 합 8 cm와 여유 2.3 cm가 포함된다. Gray는 반경 14 cm의 넓은 경로 영역을 전면으로 확장한 공간과 타겟 뒤쪽 접근 직사각형에서 Red를 뺀 영역이다. 뒤쪽 직사각형은 밀기 반대 방향 16 cm, 좌우 각각 11 cm까지다. White는 물체 중심의 배치 가능 영역 중 Red와 Gray 밖의 공간이다.

장애물은 타겟·목표를 확정한 뒤 Gray Zone과 White Zone에 배치한다. Gray 중 첫 1개는 밀기 반대쪽의 후방 조건을 만족시키고, 추가 Gray는 일반 Gray 영역을 사용한다. White는 타겟 주변·밀기 경로의 Red 제외 영역 및 Gray 영역 밖에 둔다. 물체 사이 간격·밀집도·손과 손목의 접근 공간도 검사한다. 배치 실패를 이유로 타겟이나 목표를 다시 뽑지 않는다. 이 기하 조건이 로봇 IK나 접촉 성공을 보장하지는 않는다.

처음에는 Gray 1개·White 1개이고, 커리큘럼에 따라 각각 3개까지 늘어난다. Scene에는 최대 타겟 1개·장애물 6개를 준비하고 episode별 활성 mask로 실제 참여 물체를 정한다. 장애물 수의 변경은 다음 reset 때 적용하며 진행 중 episode의 물체를 추가하거나 제거하지 않는다.

비활성 물체는 선반 로컬 높이 100 m에 서로 떨어뜨려 두고 속도를 0으로 초기화하며 중력을 끈다. 가림·관측·물체 비용·장애물 접촉 비용·낙하/전도 종료에서 제외한다. 활성화할 때는 선반에 배치하고 중력을 켠다. **활성 상태지만 가려져 보이지 않는 장애물**은 계속 물리·보상·종료의 대상이므로 비활성 슬롯과 구분한다.

질량과 마찰은 episode마다 바꾼다. 질량은 중심 0.5475 kg, clamp 이전 표준편차 0.10125 kg의 분포를 사용하며 0.345–0.75 kg로 제한한다. 한 환경의 물체 컬렉션 전체에는 같은 질량·물체 마찰 표본을 적용한다. 물체마다 독립적인 물성을 주는 방식은 아니다.

| 재질 역할 | 정지 마찰계수 분포 중심 / 표준편차 | 동마찰계수 분포 중심 / 표준편차 |
| --- | --- | --- |
| 선반 | 0.315 / 0.051 | 0.252 / 0.041 |
| 물체 | 0.315 / 0.040 | 0.252 / 0.032 |
| Hand 접촉면 | 0.585 / 0.145 | 0.468 / 0.116 |

마찰 표본은 위 분포를 근사한 유한 후보군에서 선택하며 음수가 되지 않게 제한한다. 이 랜덤화의 의도는 같은 움직임이 항상 같은 미끄러짐과 접촉력을 만든다는 가정에 정책이 의존하지 않게 하는 것이다. 물성값은 Actor의 직접 관측에 포함하지 않는다.

## 2. Observation

### 2.1 기준 Frame

| Frame | 의미와 사용처 |
| --- | --- |
| World | 중력의 하늘 방향이 +Z인 공통 축. 목표 도달의 XY 거리, 속도·가속도·물체 이동 비용과 접촉력 합산에 사용 |
| Robot root | 고정된 로봇 base 원점과 축. 초기 타겟·장애물 위치, 현재 EEF pose, Critic 타겟 위치를 표현 |
| Shelf local | 선반 중앙을 기준으로 물체와 목표를 배치하는 축. 앞뒤 half extent 0.20 m, 좌우 half extent 0.50 m |
| EEF | 손목에 고정된 조작 기준점과 회전축. 손바닥 기준으로 정의한 위치이며 손가락만 굽혀도 기준점 자체는 움직이지 않음. F/T 관측의 축·모멘트 기준점 |

현재 배치에서 robot-root +X는 로봇에서 선반 안쪽으로 밀어 넣는 방향, −Y는 선반을 정면으로 바라볼 때 오른쪽, +Z는 위쪽이다. EEF 위치는 Hand base의 로컬 Z 방향으로 13 cm인 점과 일치한다. EEF +Z는 손바닥 법선의 반대 방향으로 해석하므로, EEF +Z가 위로 향하면 손바닥은 아래를 향한다.

### 2.2 공통 policy 관측 — 55D

Actor와 Critic은 다음 55차원 벡터를 공통으로 사용한다. 표의 순서가 입력의 순서다.

| 관측 | 차원 | 의미·단위·Frame | 갱신과 노이즈 |
| --- | ---: | --- | --- |
| Arm joint position | 6 | 초기 기본 관절각을 뺀 현재 Arm 관절각, rad. Cartesian Frame이 아닌 관절 좌표 | 매 step, 추가 노이즈 없음 |
| Arm joint velocity | 6 | 기본 속도 0을 뺀 현재 Arm 관절 속도, rad/s | 매 step, 추가 노이즈 없음 |
| Last action | 8 | 직전에 환경에 적용한 raw Arm 6D·Hand 2D 명령. Hand 처리 전 값 포함 | 매 step, 추가 노이즈 없음 |
| Initial target position | 3 | 타겟 밑면 중심의 초기 XYZ, m, robot-root 기준 | reset 때 저장. 축별 독립 균일 오차 ±0.01 m를 한 번 적용하고 episode 내 고정 |
| EEF pose | 7 | 현재 EEF 위치 XYZ(m) + 회전 quaternion(w,x,y,z), robot-root 기준 | 매 step, 추가 노이즈 없음 |
| Goal distance / theta | 2 | 초기 타겟→목표의 XY 거리(m)와 시계방향 각도(rad). 벡터의 축은 robot-root | episode 고정, 추가 노이즈 없음 |
| Tactile | 17 | 각 접촉 영역의 0/1 bit. 상대 물체 ID는 없음 | 매 step, 별도 랜덤 bit noise 없음 |
| Compensated F/T | 6 | `[Fx,Fy,Fz,Mx,My,Mz]`, 힘 N·모멘트 N·m. EEF 기준점 및 EEF 축 | 매 step, 별도 합성 노이즈 없음. reset 직후 유효 측정 전에는 0 |
| 합계 | **55** |  |  |

타겟의 폭·반지름 관측, 현재 타겟 위치, 현재 장애물 위치, Hand 관절의 개별 위치·속도는 이 55D 벡터에 없다. 센서와 proprioception은 현재값을 제공하지만, 물체 위치 정보는 초기값을 유지한다.

센서 관측은 각 제어 step의 현재 표본이며 여러 시점의 history를 쌓아서 입력하지 않는다. 기본 Actor/Critic 입력 정규화도 사용하지 않으므로 표에 적은 물리 단위와 스케일의 값이 입력된다.

초기 타겟 위치의 ±1 cm는 매 step 다시 흔드는 white noise가 아니라 **episode별 고정 측정 오차**다. Goal distance/theta에는 이 위치 오차를 다시 더하지 않는다. 따라서 목표 조건은 정확하게 제공하고 초기 위치 측정은 오차를 갖는 입력 구성이다. 추가 노이즈가 없다는 것은 해당 값에 합성 노이즈를 넣지 않는다는 의미이며, 물리 계산이나 보정 잔차까지 없다는 뜻은 아니다.

### 2.3 Goal distance / theta의 의미

distance는 현재 물체가 목표까지 남겨 둔 거리가 아니라 **episode 시작 시 요구된 밀기 거리**다. 물체를 밀어도 줄어들지 않는다. theta도 고정된 목표 방향이며 현재 손끝에서 목표를 바라본 각도가 아니다.

| 방향 | theta |
| --- | ---: |
| 로봇에서 선반 안쪽으로 밀기 | 0 |
| 정면에서 본 오른쪽 | π/2 ≈ 1.571 |
| 로봇 쪽으로 당기기 | π ≈ 3.142 |
| 정면에서 본 왼쪽 | 3π/2 ≈ 4.712 |

각도 범위는 `[0, 2π)`다. 원점의 의미는 초기 타겟이고 축의 기준은 robot-root다. 실제 목표점은 절대 위치로 고정되어 있으며 관측의 표현만 거리·방향이다. Actor는 이 입력으로 물체의 실제 이동 진척도를 직접 알 수 없다.

### 2.4 주변 장애물 관측 — 40D

장애물 관측은 10개의 슬롯이며 슬롯마다 `[present, x, y, z]` 네 값을 갖는다. XYZ는 robot-root 기준 초기 밑면 중심 위치다. 활성 장애물 수는 2→6개다. 관측 대상으로 남은 물체만 앞쪽에 연속 배치하고, 나머지 슬롯은 모두 0이다. 관측 슬롯은 Gray/White나 물체 ID에 고정 대응하지 않는다. 타겟은 이 그룹에 넣지 않는다.

reset 시 로봇이 있는 정면에서 선반을 보는 평행 투영으로 가시성을 계산한다. 타겟과 활성 장애물들이 다른 물체를 가릴 수 있다. 비활성 물체는 가림 판정에 참여하지 않는다. 원기둥의 정면 투영 폭 중 보이는 비율이 **35% 이상**이면 관측 대상으로 정한다. RGB 영상·카메라 거리·높이별 부분 가림을 렌더링하는 모델은 아니며, 같은 높이의 원기둥을 대상으로 한 초기 가시성 모델이다.

그다음 활성 장애물 각각의 가시성 판정을 1% 확률로 뒤집는다. 가려진 장애물이 관측되는 경우와 보이는 장애물이 누락되는 경우를 모두 만든다. 관측하는 장애물에는 XYZ 각 축에 독립적인 ±1 cm 균일 오차를 적용한다. 판정과 오차는 reset 때 한 번만 정하고 episode 동안 유지한다.

가시성 판정과 1% 반전 이후, 관측되는 물체를 **노이즈 포함 robot-root 초기 Y 좌표의 내림차순**, 즉 `−Y` 오름차순으로 정렬한다. 로봇이 선반을 바라볼 때 +Y가 왼쪽이므로 왼쪽→오른쪽 순서다. 같은 좌표는 기존 순서를 유지한다. 가려진 물체의 정답 좌표를 정렬 키로 사용하지 않는다.

정렬 후 마스크1인 물체들 사이에서 `(0,1) → (1,2) → (2,3) → …` 인접 쌍을 왼쪽부터 한 번씩 순회한다. 각 쌍은 독립적으로10% 확률로 전체 `[present,x,y,z]`를 교환하며, 다음 쌍은 직전 교환 결과를 사용한다. `A B C D`에서 첫 교환이 발생하면 `B A C D`이고, 다음 검사는 A와 C다. 모든 교환이 발생하면 `B C D A`가 된다. 한 물체가 여러 칸 이동할 수 있지만 빈 슬롯과는 교환하지 않는다.

이후 마스크는 항상 `1,1,…,1,0,…,0`이며 중간에0이 낄 수 없다. 스왑 후에는 완전한 좌우 정렬이 일부 흐트러질 수 있다. 순서도 reset 때 한 번 정해 Actor/Critic의 공통 장애물 입력으로 episode 동안 고정한다. 확률은 `events.object_spawn.params.observation_swap_probability=0.1`로 설정하며 가시성 반전 확률0.01과 별개다.

관측하지 않는 슬롯은 presence뿐 아니라 XYZ까지 모두 0이다. 비활성 슬롯과 padding은 반전으로 켜지지 않는다. 관측에서 빠진 장애물도 물리적으로 존재하며 충돌·전도·이동 비용에 계속 영향을 준다. 이미 가려진 물체도 다른 물체를 가리는 효과는 유지한다.

### 2.5 Actor와 Critic의 차이

| 구분 | 입력 그룹 | 원시 입력 합계 | 장애물 인코딩 후 입력 |
| --- | --- | ---: | ---: |
| Actor | policy 55D + obstacles 40D | **95D** | 55 + 16 = **71D** |
| Critic | policy 55D + 현재 타겟 3D + obstacles 40D | **98D** | 55 + 3 + 16 = **74D** |

장애물 40D는 학습 가능한 인코더를 통해 16D로 압축한다. Actor와 Critic은 각각 자신의 인코더를 학습한다. 16D는 추가 센서 측정이 아니라 주어진 40D 정보의 학습된 표현이다.

Critic 전용 3D는 **현재 타겟 밑면 중심의 robot-root XYZ**이며 추가 노이즈가 없는 시뮬레이션 상태다. 가치 추정 학습에는 실제 진척도를 사용할 수 있게 하고, 행동을 만드는 Actor에는 실행 중 시각적 타겟 추적을 제공하지 않는 비대칭 구성이다. Critic에도 실시간 장애물 위치가 추가되지는 않는다.

## 3. Action

### 3.1 8D 명령의 정의

| 채널 | 대상 | 명령의 의미 |
| --- | --- | --- |
| 0–5 | UR5e Arm 여섯 관절 | 기본 관절각에서의 목표 위치 offset |
| 6 | Hand 굽힘 관절 | 공통 열림 정도. 0은 닫힘, 1은 열림 |
| 7 | 엄지 대립 관절 | 엄지 대립 방향의 열림 정도. 0은 닫힘, 1은 열림 |

Arm 목표각은 다음과 같다.

```math
q_i^{\mathrm{target}}=q_i^{\mathrm{default}}+0.5a_i.
```

따라서 `a=1`은 기본각에서 +0.5 rad, `a=−1`은 −0.5 rad다. 이전 step의 목표각에 0.5a를 누적하는 명령이 아니다. 같은 action을 유지하면 같은 목표 관절각을 계속 추종한다.

Hand는 각 채널을 `[0,1]`로 제한한 뒤 열린 자세와 닫힌 자세 사이를 선형 보간한다. 엄지 대립을 제외한 11개 관절은 채널 6을 공유하며, 엄지 대립 관절 하나는 채널 7을 사용한다.

### 3.2 최대로 나올 수 있는 Action

**현재 기본 정책의 raw Action에는 유한한 최대 절댓값이 없다.** 정책은 Gaussian 출력을 사용하고 전체 action clipping 및 Arm action clipping을 설정하지 않는다. 그러므로 raw Action이 항상 `[-1,1]`이라고 가정하거나 Arm 최대 offset을 ±0.5 rad라고 표현하면 틀리다. 예를 들어 Arm `a=2`도 목표 offset +1.0 rad로 변환된다.

| 구분 | 실제 적용 범위 |
| --- | --- |
| Gaussian raw Action 8D | 수학적으로 상·하한 없음 |
| Arm 목표 offset | `0.5 × raw action` rad, Action 변환 자체의 상·하한 없음 |
| Hand 처리 후 Action 2D | 각 채널 0–1 |
| 실제 Arm 구동 속도 설정 | 앞 세 관절 2 rad/s, 손목 세 관절 4 rad/s |
| 실제 Hand 구동 속도 설정 | 각 관절 1 rad/s |

관절 가동 범위와 구동 속도·힘 제한은 물리 모델에 속하며 raw Action 범위를 뜻하지 않는다. Hand raw 출력은 처리 단계에서 범위 안으로 잘리지만, last action 관측과 action-rate 비용은 그 처리 전 값을 사용한다.

Hand의 열린 목표각은 모두 0 rad다. 닫힌 목표각은 엄지 대립 1.1641 rad, 나머지 엄지 세 관절 약 0.5864 / 0.4705 / 0.4464 rad, 다른 네 손가락의 두 관절은 각각 약 1.4381 / 1.5593 rad다. 이는 목표 자세의 끝점이며 모든 관절이 실제로 그 자세에 도달한다는 보장은 아니다.

## 4. Reward

### 4.1 계산 단위와 전체 항목

보상은 목표 이동·유지, 접근·접촉 형성, 물체·선반 보존, 동작의 급변 억제를 함께 평가한다. **활성 항은 17개**이며 고정된 우선순위 제어나 항별 비율 배분은 없다. RewardManager는 기본적으로 `weight × raw 값 × 0.02초`를 합산한다. `reaching`과 `goal_distance`는 함수에서 시간 배율을 상쇄하여 실제 개선 거리당 보상을 지급하고, `shelf_failure`도 종료 순간 비용을 한 번 지급하도록 시간 배율을 상쇄한다.

Net Force는 `sqrt(Fx²+Fy²+Fz²)`, Net Moment는 `sqrt(Mx²+My²+Mz²)`다. 보정 F/T와 ContactSensor는 측정량·힘 구성·목적이 다르므로 같은 Net Force라는 표현만으로 두 신호를 동일시하지 않는다.

| Term | Weight | 계산 대상 |
| --- | ---: | --- |
| `reaching` | +30 | EEF의 새로운 타겟 접근 거리 |
| `goal_distance` | +100 | 타겟의 새로운 목표 접근 거리 |
| `goal_hold` | +0.9 | 현재 목표 인정 반경 안의 체류 |
| `hand_contact` | +0.29 | 손 전체 합력 0.01 N 이상 × 목표 거리 계수 alpha |
| `arm_action_rate` | −0.03 | raw Arm Action 변화량의 제곱합 |
| `hand_action_rate` | −0.03 | raw Hand Action 변화량의 제곱합 |
| `arm_joint_velocity` | −0.03 | 실제 Arm 6관절 속도의 제곱합 |
| `hand_joint_velocity` | −0.01 | 실제 Hand 12관절 속도의 제곱합 |
| `object` | −30 | 활성 물체 기울기 + 2.5 × 장애물 변위 비용 |
| `shelf_collision` | −0.5 | 선반 교란 및 손·손목의 낮은 접근 |
| `pushing_speed` | −5 | 타겟의 3D 선속도 초과 비용 |
| `arm_speed_excess` | −1 | Arm 최대 절대 관절 속도 초과 비용 |
| `shelf_failure` | −3 | 선반 충돌 종료가 발생한 transition |
| `eef_linear_speed` | −1 | EEF 점의 3D 선속도 초과 비용 |
| `obstacle_contact` | −1 | 활성 비타겟 물체가 손에 가하는 합력 초과 비용 |
| `object_acceleration` | −1 | 활성 물체별 3D 선가속도 초과 비용의 합 |
| `wrench_change` | −0.1 | 보정 EEF Force/Moment 크기의 step 간 절대 변화 |

촉각 ON 개수에 따른 보상, 촉각 보상 weight 커리큘럼, EEF orientation 비용은 활성 항에 없다.

### 4.2 목표 이동과 체류

`goal_distance`는 타겟 밑면 중심과 목표의 world XY 거리에서 **1 cm 고정 tolerance**를 제외한 거리의 최단 기록을 관리한다. 그 기록을 새로 개선한 거리만큼 +100/m를 지급한다. 새롭게 1 cm 접근하면 +1이며, 멀어졌다가 같은 위치로 돌아와도 반복 지급되지 않는다. 초기 목표 거리가 15 cm이면 누적 상한은 +14다.

`goal_hold`는 현재 world XY 오차가 인정 반경 이하이면 +0.9/초, 즉 +0.018/step을 지급한다. 5초 체류는 +4.5다. 인정 반경은 3 cm에서 시작하여 1 cm까지 줄어든다. 속도·높이·연속 체류 시간은 이 보상의 조건에 들어가지 않는다. 목표 안에서 episode를 즉시 종료하지 않는다.

두 보상의 tolerance는 구분해야 한다. `goal_distance`의 진전 계산은 항상 1 cm를 기준으로 하고, `goal_hold`의 체류 인정 반경만 커리큘럼으로 변한다. 초기에는 체류 보상을 받으면서도 더 안쪽으로 이동해 진전 보상을 받을 수 있다.

### 4.3 손 전체 접촉 유지와 목표 근처 감쇠

`hand_contact`는 손 전체에 작용하는 법선 접촉력 벡터의 합을 구한 뒤 Net Force가 0.01 N 이상인 유효 표본에 지급한다. 접촉한 손가락 수나 접촉 상대 ID는 지급 조건이 아니다. 연속 유지 시간이 길어질수록 단가가 증가하지 않고, 매 step의 접촉 여부에 같은 단가를 적용한다.

`goal_contact_fade_width=0.0`은 거리 감쇠를 비활성화한다. 이때 alpha는 목표 안팎에서 항상 1이며, 유효 센서 표본·0.01 N 접촉 조건은 그대로 적용한다. 음수·NaN·Inf는 허용하지 않는다. 양수일 때는 아래 선형 감쇠와 Goal 반경 커리큘럼 동기화를 사용한다.

현재 타겟–Goal의 world XY 거리를 d, `goal_hold`의 현재 인정 반경을 r이라고 하면 다음과 같다.

```text
alpha = clamp((d - r) / 0.015, 0, 1)
reward rate = 0.29 × alpha × (hand Net Force >= 0.01 N)
```

| 거리 | alpha | 접촉 보상 |
| --- | ---: | ---: |
| d ≤ r | 0 | 0 |
| d = r + 0.75 cm | 0.5 | +0.145/초 |
| d ≥ r + 1.5 cm | 1 | +0.29/초 |

r은 매 계산에서 RewardManager의 실제 `goal_hold` 설정을 읽는다. 별도의 복사본을 사용하지 않으므로 커리큘럼 진행·checkpoint 복원과 함께 즉시 바뀐다. 목표에 가까워질수록 추가 접촉을 유지하려는 유인을 줄이고 목표 안에서는 체류 보상으로 평가한다.

5초 내내 접촉하고 alpha=1이면 누적 +1.45다. 이는 5초 접촉의 상한이며 목표 근처에서는 더 작다. 계수는 고정값으로, 실행 중 전체 보상을 읽어 항상 10%로 맞추는 구조가 아니다.

### 4.4 비타겟 접촉력

`obstacle_contact`는 **현재 타겟 이외의 활성 원기둥들과 손 사이의 접촉력만** 사용한다. 각 물체에서 손에 작용하는 월드 XYZ 힘을 구하고 벡터를 모두 합한 다음 그 크기를 계산한다. 타겟·비활성 물체·선반·바닥의 접촉은 이 항에 포함하지 않는다. 여러 장애물의 비용을 각각 계산해 더하는 방식이 아니므로 반대 방향 힘은 상쇄될 수 있다.

Net Force 20 N까지 무료이고 초과하면 4.7절의 지수 비용이 증가한다. Weight는 −1, raw 비용 상한은 100이다. 21 N에서는 약 −3.195/초, 약 22.652 N 이상에서는 −100/초로 포화한다. 초기 유효 센서 표본 전에는 지급하지 않는다. 센서가 제공하는 것은 법선력이라는 한계가 있다.

타겟 이외의 접촉도 `hand_contact` 조건을 만족할 수 있다. 이때 접촉 유지 보상과 장애물 접촉 비용이 함께 계산된다. 따라서 “접촉 보상을 받았다”가 “타겟과 올바르게 접촉했다”를 뜻하지 않는다.

### 4.5 물체와 선반 보존

`object`의 기울기 비용은 타겟을 포함한 모든 활성 물체의 축과 선반 법선 사이 각도를 사용한다. 5°까지 무료이며 0.9 rad(약 51.6°)에서 물체당 raw 비용 1이 된다. 중간은 두 임계값 사이를 정규화한 값의 제곱이다.

```text
tilt_i = clamp((angle_i - 5 degrees) / (0.9 rad - 5 degrees), 0, 1)^2
displacement = min(sum(||position_i - initial_position_i||^2 for active obstacles), 0.04)
object cost rate = -30 × (sum(tilt_i for active objects) + 2.5 × displacement)
```

변위는 타겟을 제외한 활성 장애물의 실제 초기 위치 대비 3D 거리 제곱이며 관측 노이즈를 사용하지 않는다. 장애물이 움직인 위치에 머물러도 비용이 계속 발생한다. 가려진 장애물도 비용 대상이다.

장애물 하나가 10 cm 이동하면 −0.75/초, 둘이면 −1.5/초이며 변위 부분 전체 상한은 −3/초다. 기울기는 활성 물체 수에 비례하므로 시작 3개에서 최대 −90/초, 최종 7개에서 최대 −210/초다. 변위를 포함한 수식상 최대 비용은 각각 −93/초·−213/초다. 큰 기울기는 종료도 유발하므로 이를 오래 유지하는 정상 episode를 가정하지 않는다.

`shelf_collision` 연속 비용은 선반 이동·속도와 가상 손가락 두 점·손목 점의 높이를 사용한다. 선반 움직임 판정은 초기 위치 이탈 거리와 6D root 속도 norm의 합이 0.005를 넘는지로 정하므로 해당 기준을 순수한 길이나 속도로 해석하지 않는다. 높이 비용은 EEF가 선반 기준점의 3D 반경 20 cm 안에 있을 때 적용한다. 기준면은 선반 root Z+1.06 m이며 손가락은 2 cm, 손목은 8 cm 이내 접근을 평가한다. Raw 상한 4, weight −0.5로 최대 −2/초다.

`shelf_failure`는 `shelf_collision` 종료가 참인 transition에 −3을 한 번 지급한다. 다른 종료가 단독 발생했을 때의 공통 실패 비용이 아니다. 선반 변위 종료만 발생해도 이 −3이 자동 지급되는 것은 아니다.

### 4.6 접근 지원과 관절 제어 비용

`reaching`은 현재 EEF–타겟 밑면 중심의 3D 거리에서 10 cm를 뺀 양수 부분의 최단 기록을 관리한다. 새 개선 1 cm당 +0.3, 10 cm당 +3이다. 초기 거리를 d₀라 하면 episode 누적 상한은 `30 × max(d₀−0.10, 0)`이다. 타겟 자체가 EEF 쪽으로 움직여도 진전이 생길 수 있다.

Arm/Hand Action 변화 비용은 각각 **raw Action 변화량의 제곱합**을 계산한다. 각 그룹의 출력 상한은 100이며 weight는 모두 −0.03으로 고정된다. 평균·정규화·dt 나눗셈·Hand 입력 clamp를 보상 계산에 넣지 않는다. 각 그룹 최대 −3/초이며 raw 채널 하나가 1만큼 변하면 해당 step 비용은 −0.0006이다.

실제 관절 속도 제곱합도 Arm 6개와 Hand 12개를 분리하고 각각 100으로 제한한다. Arm weight −0.03, Hand weight −0.01로 최대 −3/초·−1/초다. Arm 여섯 관절이 모두 1 rad/s이면 −0.18/초, Hand 열두 관절이 모두 1 rad/s이면 −0.12/초다. 네 항에는 weight 커리큘럼이 없다.

### 4.7 속도·가속도의 지수 비용과 상한

다음의 공통 함수는 입력 x가 무료 기준 t를 초과하면 비용을 증가시킨다. exp 계산 **전에** 입력을 제한하여 매우 큰 값에서도 overflow를 방지한다.

```text
excess = clamp(x - t, 0, 0.5 × log(201))
C(x, t) = min(0.5 × expm1(2 × excess), 100)
```

| Term | x | 무료 기준 시작 → 최종 | Weight | Raw 상한 |
| --- | --- | --- | ---: | ---: |
| `pushing_speed` | 타겟의 3D 선속도 norm | 0.10 → 0.03 m/s | −5 | 100 |
| `arm_speed_excess` | Arm 6관절의 최대 절대 속도 | 1.0 → 0.7 rad/s | −1 | 100 |
| `eef_linear_speed` | 현재 EEF 점의 3D 선속도 norm | 1.5 → 0.3 m/s | −1 | 100 |
| `object_acceleration` | 활성 물체 각각의 3D COM 선가속도 norm | 1.0 → 0.1 m/s² | −1 | 물체당 100 |

EEF 속도에는 손목 회전으로 EEF 점이 이동하는 효과가 포함된다. 타겟 속도 0.2 m/s의 비용은 초기 약 −0.554/초, 최종 약 −1.012/초다. 비용의 무료 기준과 타겟 과속 종료 0.8 m/s는 별개다.

가속도는 Isaac Lab `object_com_lin_acc_w`를 직접 읽는다. PhysX가 제공하는 **월드 좌표계 질량중심 선가속도, 마지막 물리 step의 값**이며 제어 주기의 속도 차분이나 substep 평균이 아니다. 벡터 norm이므로 급가속·급감속 모두 비용 대상이다. 물체마다 지수 비용을 계산한 뒤 활성 물체 전체를 합한다.

가속도 raw 비용 합의 상한은 시작 3개에서 300, 최종 7개에서 700이다. 물체당 포화점은 현재 무료 기준+약 2.65165 m/s²다. 0.5 m/s²에서 포화하는 설정이 아니다. 매우 큰 값·NaN/Inf는 유효 활성 샘플에 대해 물체당 상한으로 처리한다. 비활성 물체와 reset/활성화 직후 첫 샘플은 제외하며 부분 reset은 해당 환경의 유효 상태만 초기화한다.

### 4.8 EEF 힘·모멘트 크기 변화

`wrench_change`는 policy 관측과 **같은 보정 F/T 표본·EEF 기준점·EEF 축**을 사용한다. 힘과 모멘트 벡터의 크기를 먼저 계산하고 직전 제어 step과의 차이에 절댓값을 취한다.

```text
delta_force = abs(norm(F_current) - norm(F_previous))
delta_moment = abs(norm(M_current) - norm(M_previous))
```

이는 `norm(F_current−F_previous)`가 아니며 dt로 나누는 변화율도 아니다. 단위는 N과 N·m다. 크기만 같고 방향만 바뀌면 이 항의 비용은 0이다.

| 입력 | 시작 무료 기준 | 최종 무료 기준 | 포화 기준 |
| --- | ---: | ---: | --- |
| delta_force | 50 N | 10 N | 현재 무료 기준의 2.5배: 125→25 N |
| delta_moment | 5 N·m | 1 N·m | 현재 무료 기준의 2.5배: 12.5→2.5 N·m |

각 초과량을 무료 기준부터 포화 기준 사이에서 정규화하고, 둘 중 큰 값을 x로 사용한다. Raw 비용은 `expm1(3 × clamp(x,0,1)) / expm1(3)`으로 0–1 범위다. Weight −0.1로 최대 −0.1/초, −0.002/step이다. 추가로 episode 누적 비용은 이미 획득한 양의 보상 합의 5%를 넘지 못한다. 양의 보상이 없다면 비용 예산도 0이다.

첫 유효 표본은 기준만 만들고 reset 경계를 넘어 차분하지 않는다. 큰 힘을 일정하게 유지하는 것은 변화 비용을 만들지 않으므로 절대 힘의 안전 제한과 구분한다. 접촉 identity를 사용하는 장애물 힘 비용과도 계산 목적이 다르다.

### 4.9 설계상 의도한 보상 비중과 규모 예시

이 환경은 **목표 이동·유지를 보상의 중심으로 두고, 접근과 접촉은 이를 돕는 정도**를 의도한다. 현재 계수와 아래의 정상적인 조작 예시를 대략적인 비중으로 읽으면 다음과 같다. 분모는 페널티를 빼기 전 **양의 보상 합**이며, 엄밀한 배분 목표나 실측 통계가 아니라 설계의 상대적 중요도를 설명하는 값이다.

| 역할 | 관련 항 | 의도한 대략적 규모 | 설계 의도 |
| --- | --- | --- | --- |
| 타겟을 목표로 이동 | `goal_distance` | 약 60% | 접촉 자체보다 실제 물체 이동이 가장 큰 보상이 되도록 함 |
| 목표 부근에서 유지 | `goal_hold` | 약 20% | 목표를 잠깐 통과하는 것보다 도달 후 머무는 행동을 유도 |
| 접촉 가능한 위치로 접근 | `reaching` | 약 10–15% | 초기 접근을 돕되, 접근만 반복하는 행동이 과제의 중심이 되지 않도록 함 |
| 손과 물체의 접촉 유지 | `hand_contact` | 약 5–10% | 이동 중 접촉을 보조하고, 목표 근처에서는 alpha로 필요성을 줄임 |

즉, **목표 이동·유지가 약 80% 안팎, 접근·접촉 지원이 나머지 정도**라는 방향이다. 범위의 상·하한을 더해 정확히100%로 맞추는 표가 아니다. 접촉 보상의 초기 계수는 전체 보상의10% 안팎에 해당하는 보조 신호를 의도했지만, 현재는 목표 거리 alpha가 곱해지므로 목표 근처에서 보내는 시간이 길수록 비중이 더 작아질 수 있다.

페널티는 이 양의 보상 표에 일정 비율로 배분하지 않는다. 역할별 의도는 다음과 같다.

| 비용 그룹 | 의도한 상대적 역할 |
| --- | --- |
| 물체 기울기·장애물 이동, 선반 교란·실패 | 물체를 목표로 옮겨도 주변을 크게 망가뜨리면 좋은 행동으로 평가하지 않도록 하는 강한 제약 |
| 장애물 접촉력·물체 가속도 | 허용 구간에서는 부담을 주지 않고, 강한 충돌·급가속·급감속에서는 빠르게 커지는 억제 신호 |
| 타겟·Arm·EEF 과속, Arm/Hand Action 변화·관절 속도 | 정상 조작을 부드럽게 만드는 보조 비용. 실제 움직임이 크거나 빠르면 기여도도 커짐 |
| `wrench_change` | 작은 보조 비용. 누적 양의 보상의5% 이내라는 실제 예산 제한이 있으며, 5%를 반드시 사용하도록 설계한 것은 아님 |

따라서 정상적인 조작에서는 목표 달성이 주된 보상 신호가 되기를 기대하지만, 충돌·전도·급격한 움직임에서는 비용이 양의 보상보다 커질 수 있다. 특히 장애물 수가 늘면 물체별로 합산하는 비용의 영향도 달라진다. 여기서의 기대 비중은 코드가 자동으로 유지하는 비율이 아니며, 학습 결과에서 확인해야 할 설계 의도다.

**구체적인 규모 예시:**

초기 목표 거리 15 cm에서 고정 진전 반경 1 cm까지 이동하고, 목표 체류 5초, alpha=1인 접촉 5초, 새로운 EEF 접근 진전 10 cm를 가정하면 양의 보상은 각각 +14, +4.5, +1.45, +3으로 합계 **+22.95**다. 접촉의 비중은 이 가정에서 약 6.3%이며 항상 10%가 아니다. 목표 체류 동안에는 alpha=0이므로 접촉 5초는 목표 바깥에서 이뤄진 시간으로 해석해야 한다.

비용은 실제 궤적에 따라 추가된다. 장애물 두 개가 각각 10 cm 이동한 상태를 5초 유지하면 변위 비용만 −7.5다. 이 숫자는 수식 예시이며 정책의 실측 수익·성공률이나 통계적 기대값이 아니다.

## 5. Termination

목표 도달 자체로 종료하지 않는다. 다음 **6개 조건**이 episode를 끝내며, 종료 transition의 보상 계산 후 reset한다.

| Term | 조건 |
| --- | --- |
| `time_out` | 최대 10초, 500 control step |
| `object_drop` | 활성 물체 중 하나라도 밑면 기준점이 환경 원점 기준 1.04 m 미만이거나 선반 법선 대비 기울기 0.9 rad 이상 |
| `push_fast` | 타겟의 3D 선속도 norm > 0.8 m/s |
| `shelf_collision` | 선반 root의 선속도·각속도 6D norm > 0.1, 또는 손목 점이 선반 root Z+1.05 m+0.03 m보다 낮음 |
| `hand_velocity` | 이름과 달리 **Arm 6관절** 중 절대 관절 속도 > 5 rad/s |
| `shelf_displacement` | 선반 root의 초기 위치 대비 3D 이동 거리 > 0.05 m |

가려진 활성 장애물은 낙하·전도 판정에 포함하고 비활성 물체는 제외한다. 선반 6D 속도 기준은 선속도와 각속도를 함께 쓰는 휴리스틱이다. 가상 손가락 높이만으로 종료하는 옵션과 물체의 선반 XY 범위 이탈만 검사하는 별도 항은 비활성이다. 가속도·wrench 변화·EEF 속도에는 독립적인 종료 항이 없다.

## 6. Curriculum

### 6.1 진행 단위와 적용 시점

단위는 0부터 시작하는 PPO learning iteration이다. 한 iteration에 환경당 36 control step(0.72초)을 수집한다. 현재 iteration에서 값을 직접 계산하므로 반복 reset이 일정을 추가 진행시키지 않는다.

활성 CurriculumManager 항은 **9개**다. 속도·가속도·wrench 임계값과 Goal hold 반경은 rollout 전에 갱신하여 진행 중 episode에도 적용한다. 목표 방향과 장애물 개수는 다음 reset부터 적용한다. 현재 목표점과 현재 episode의 물체 수를 중간에 바꾸지 않는다.

### 6.2 보상 기준 일정

| 기준 | 시작 | 첫 변경 iteration | 간격 | 변경량 | 최종 | 최종 도달 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 타겟 free speed | 0.10 m/s | 500 | 200 | −0.01 | 0.03 | 1700 |
| Arm free speed | 1.0 rad/s | 500 | 200 | −0.02 | 0.7 | 3300 |
| EEF free speed | 1.5 m/s | 500 | 200 | −0.02 | 0.3 | 12300 |
| Goal hold 반경 | 0.03 m | 1000 | 500 | −0.01 | 0.01 | 1500 |
| 힘 크기 변화 무료 기준 | 50 N | 1000 | 250 | −1 | 10 | 10750 |
| 모멘트 크기 변화 무료 기준 | 5 N·m | 1000 | 250 | −0.1 | 1 | 10750 |
| 물체 가속도 무료 기준 | 1.0 m/s² | 1000 | 250 | −0.02 | 0.1 | 12000 |

첫 변경 시점에 한 번 감소한다. 예를 들어 iteration 1000의 Goal 반경은 0.02 m, 힘 변화 기준은 49 N, 모멘트는 4.9 N·m, 가속도는 0.98 m/s²다. 각 값은 최종값에서 멈춘다. 접촉 alpha의 r은 이 Goal hold 반경과 자동으로 일치하며 별도 curriculum 항을 두지 않는다.

### 6.3 Goal 방향

앞·뒤 축 각각의 목표 제외 반각은 30°로 시작한다. 처음부터 좌우뿐 아니라 대각선 성분이 있는 목표도 허용한다. 이 방향은 선반 평면상의 앞뒤·좌우를 뜻하며 월드 Z 방향으로 물체를 들어 올리는 목표가 아니다.

| Iteration | 앞·뒤 각 deadzone 반각 |
| --- | ---: |
| 0–3499 | 30° |
| 3500 | 25° |
| 4000 | 20° |
| 4500 | 15° |
| 5000 | 10° |
| 5500 | 5° |
| 6000 이후 | 0° |

`hold_iterations=3000` 뒤 완료된 500 iteration 구간마다 5°를 줄이는 규칙이므로 첫 감소는 3000이 아니라 **3500**이다. 0°에서는 평면 360° 방향을 허용하되 선반 가장자리에 따른 목표 거리 제한은 계속 적용한다.

### 6.4 장애물 수

| Iteration | Gray | White | 타겟 포함 활성 물체 |
| --- | ---: | ---: | ---: |
| 0–2999 | 1 | 1 | 3 |
| 3000–4499 | 1 | 2 | 4 |
| 4500–5999 | 2 | 2 | 5 |
| 6000–7499 | 2 | 3 | 6 |
| 7500 이후 | 3 | 3 | 7 |

White는 3000부터 3000마다, Gray는 4500부터 3000마다 1개씩 늘고 각 3개에서 멈춘다. 이 두 일정을 한 `obstacle_population` 항이 관리한다. 부분 reset에서는 해당 환경만 새 개수로 바뀐다.

최대 용량은 EnvCfg의 `max_gray_obstacles`, `max_white_obstacles`, 시작·최종 개수와 일정은 `curriculum.obstacle_population.params`로 조정한다. 합계 장애물 용량은 고정 40D 관측의 10개 슬롯 이하이며 실제 수는 용량 이하로 제한된다. 예를 들어 학습 명령에 `env.max_white_obstacles=2`를 붙이면 White는 최대 2개다.

## 7. 정책과 학습 실행

Actor와 Critic은 각각 장애물 인코더 `40→32→16`(ReLU)을 갖고, 결합된 입력을 `256→128→64` hidden MLP(ELU)로 처리한다. Actor 출력은 초기 표준편차 1.0의 Gaussian이며 입력 정규화와 전역 Action clipping은 사용하지 않는다.

| 학습 설정 | 값 |
| --- | --- |
| 기본 병렬 환경 | 4096, 환경 간격 2.5 m |
| Runner | `CurriculumOnPolicyRunner` |
| Iteration당 rollout | 환경당 36 step |
| 전체 목표 | 90000 iteration |
| Checkpoint 저장 간격 | 50 iteration |
| PPO epoch / mini-batch | 8 / 4 |
| Learning rate / schedule | 0.001 / adaptive |
| Gamma / GAE lambda | 0.98 / 0.95 |
| PPO clip / desired KL | 0.2 / 0.02 |
| Entropy coefficient / max gradient norm | 0.005 / 1.0 |
| Value loss coefficient | 1.0, clipped value loss 사용 |

자동 복구 학습은 Workspace 루트에서 다음과 같이 시작한다. 아래 예시는 병렬 환경 수를 2048로 지정한다.

```bash
./IsaacLab/isaaclab.sh -p src/inspire_sweep_baseline/scripts/train_resilient.py \
  --task Isaac-Inspire-Contact-Sweep-Clutter-Fusion-v1_0 \
  --num_envs 2048 --headless --max_iterations 90000
```

`--max_iterations`는 재시도마다 추가하는 양이 아니라 전체 절대 목표다. 목표 이전에 오류 또는 완료 표식 없는 조기 종료가 발생하면 최신 저장 iteration에서 500을 뺀 값 이하의 가장 큰 유효 checkpoint를 찾는다. 모델·optimizer와 커리큘럼을 복원한 **뒤 reset**하므로 첫 rollout부터 복원 단계의 Goal 반경·목표 방향·장애물 수·비용 기준을 사용한다.

예를 들어 iteration 2500에서 재개하면 Gray1/White1, Goal 반경 0.01 m, deadzone 30°, 힘 변화 기준 43 N, 모멘트 4.3 N·m, 가속도 0.86 m/s²다. 전체 목표가 90000이면 남은 87500회를 실행한다. Runner의 index 관례에 따라 마지막 저장 iteration은 목표−1이다.

기본 재시작 상한은 10회이며 `--max-restarts`로 바꾼다. Ctrl+C/SIGTERM은 의도적 중단으로 처리한다. `--resume-checkpoint <파일>`로 최초 복원 지점을 지정할 수 있다. 로그는 새 `logs/resilient/<task>/<UTC시각_uuid>/attempt_*`에 분리하고 되돌린 이후의 오래된 분기는 삭제하지 않되 재선택하지 않는다. `--job-dir <새 경로>`로 위치를 지정한다.

일반 학습은 `scripts/train.py`를 사용하며 experiment 이름은 `inspire_contact_sweep_clutter_fusion_v1_0`, 기본 로그 위치는 `logs/rsl_rl/inspire_contact_sweep_clutter_fusion_v1_0`이다. 정책 재생은 다음과 같다.

```bash
./IsaacLab/isaaclab.sh -p src/inspire_sweep_baseline/scripts/play.py \
  --task Isaac-Inspire-Contact-Sweep-Clutter-Fusion-v1_0 \
  --num_envs 1 --checkpoint /absolute/path/model_2500.pt
```

자동 복구는 유효 checkpoint로 학습을 재시도하는 기능이며 PPO 발산의 원인 자체를 제거했다는 의미는 아니다.
