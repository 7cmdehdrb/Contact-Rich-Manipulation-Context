# Relative-v0 F/T 관측 한도 계획 문서 작성

2026-11-07. 사용자 요청: 실제 수정 없이 수정 방안 문서 작성. Relative-v0를 기준으로 하위 환경에 전파하며 F 각 축±150N, M 각 축±8N·m로 clipping한다.

## 변경과 의도

- 변경 전: 학습 분석에는 F/T 입력 처리 등 수정 후보가 있었으나 사용자 지정 한도와 적용 범위를 정리한 계획 문서는 없었다.
- 변경 후: [F/T 관측 한도 수정 계획](../../01_plan/RELATIVE_V0_FT_OBSERVATION_LIMIT_PLAN.md)을 추가했다.
- 사용자 확정 요구인 한도·부모 적용과, 최종 EEF 관측 경계에 적용한다는 구현 설계 방향을 구분했다. 실제 센서 원본 좌표에서 먼저 제한하는 모델과 같다고 주장하지 않았다.
- 노이즈 이후 최종 한도, 노이즈 비활성 시 제한 유지, v2 Critic 포함, 차원·기존 구성 보존, 미실행 검증 항목을 기록했다.
- 영향: 문서만 추가했다. 환경 코드·설정·학습 로그·checkpoint·서브모듈의 기존 사용자 변경은 수정하지 않았다.

## 최종 대조와 검증

요청한1번 항목만 확정 요구사항으로 기록했다. normalization, action/reward/PPO 수정은 자동 추가하지 않았다. 실제 구현·학습·물리 시뮬레이션 및 센서 제조사 사양 검증은 수행하지 않았다. 코드 대조로 Relative-v2 Critic의 공통 PolicyCfg 상속과 ObservationManager의 modifier → noise → clip → scale 순서를 확인했다.

문서 검증: 변경2문서 `check_markdown_math.py` 통과, 전체 문서 `check_document_links.py` 오류0, `git diff --check` 통과. 별도 렌더링 검사는 수행하지 않았다.

## 후속: Action Rate 그룹별 최대100 복원 계획

2026-11-07 사용자 추가 요청에 따라 같은 계획 문서에2번 항목을 추가했다. raw 정책 action 기반을 유지하고 Arm·Hand 변화량 제곱합을 각각 최대100으로 제한한다. 기존 Hand[0,1] 처리, 그룹별 계수0.03, weight-1, dt 적용은 유지한다.

변경 전에는 Action Rate 수정이 계획 범위 밖이었으나, 이번 명시적 요청으로 그룹별 cap만 확정 범위에 포함했다. 제목·범위 제외 항목·검증 목록·현재 상태를 함께 수정하여1번만 확정됐다는 기존 표현을 제거했다. 실제 Hand 비용은 입력 한도로 제곱합 최대2임을 구분했고, 공유 함수를 쓰는 상위 Refactor 환경에 변경이 전파되지 않도록 Relative-v0에서 설정하는 방향을 기록했다.

코드·설정·학습 로그는 변경하지 않았다. 실행 검증은 미수행이며, 문서 검증만 수행한다.
