사용자가 확정 요구를 기반으로 기능별 요구사항·구현 방향·테스트 기준·제외 범위를 명시한 개발 명세서를 요청했다. `to-spec`을 읽고 적용했다. 기존 기준 문서를 같은 위치에서 스킬의 Problem Statement / Solution / User Stories / Implementation Decisions / Testing Decisions / Out of Scope / Further Notes 형식으로 재구성해 병렬 명세를 만들지 않았다. 질문·정정 이력과 ADR은 보존했다.

35개 사용자 요구를 FR-01–FR-09와 T01–T15에 연결했다. 기존 기능 계약의 수식·수치·관측·상속 독립성·reset 제한·종료 조건을 유지하고, 모듈별 책임과 입출력을 파일 경로 없이 기술했다. 기준 문서의 기존 구현 위치 표는 역할별 연결 계약으로 바꿨으며, 실제 코드 경로는 기존 분석 이력에서 계속 확인할 수 있다.

현재 Simple/Finger/ForceDirection 테스트에서 구성 격리, reset·step lifecycle/RNG/부분 reset, clip/Last Action, Gate/timeout, packed friction/force sampling, 모델 gradient/export, 메쉬 실제 교점·가림 사례를 확인했다. 스킬이 요구한 테스트 경계 확인에 사용자가 “권고 구성으로 정리”라고 답했다. 등록된 환경의 reset·step 외부 동작을 주 검증 지점으로 삼고, 물리 계측·수식 경계와 PPO forward/export를 보완하는 구성이다. 새 제품 요구사항이나 공개 테스트 전용 API를 추가하지 않았다.

신규 weight와 성능 목표 수치는 확정하지 않았다. 이슈 게시 대상은 대화 및 확인한 프로젝트 설정에 없었으며 Git remote로 게시 대상을 임의 결정하지 않았다. 스킬의 `/setup-matt-pocock-skills` 안내를 명세에 기록했다. 이슈 생성·ready-for-agent 라벨 적용은 미수행이다. 환경 구현·등록·학습과 기존 사용자 변경·학습 로그에는 손대지 않았다.

검증 결과: 변경3문서 수식 검사 통과, 링크153개 오류0, workspace와 문서 저장소의 diff 공백 검사 통과. 이전 명세의 기능 계약 본문(FR-01–FR-08)은 제목 수준과 성공 경계 설명 문장만 정리했음을 자동 대조했고 모든 math block은 동일했다. 템플릿7개 섹션, 사용자 요구35개, FR/T 참조 연결을 확인했다. 추가 공백 검사에서 인계의 기존 Markdown 줄바꿈 공백을 발견했으나 이번 변경 범위가 아니므로 보존하고 변경한 본문만 재검사했다. 실제 신규 환경 실행·물리·성능·학습 검증은 여전히 미수행이다.

## to-tickets — 게시 전 분할 검토안

사용자는 작성된 Spec의 구현 작업을 독립적으로 구현·테스트 가능한 Ticket으로 나누고, 의존 관계와 병렬/순차 작업을 게시 전에 검토하도록 요청했다. `to-tickets`를 읽고 [검토안](../../01_plan/environments/2026-11-18_stabilize_sweep_ticket_review.md)을 작성했다. 확정 Spec은 수정하지 않았다.

독립 환경 생성·제어 경로를 먼저 확보한 뒤 초기 자세, 대표점→정책, 접촉→압착 비용, 공통 비용을 병렬 진행하도록 했다. reset 복구는 실제 로봇 영역과 관측 결과를, 안정화는 초기 자세와 접촉 계측을 선행 조건으로 둔다. Sweep은 Gate 이후, 통합은 reset·Sweep·공통 비용 이후로 연결했다. 최종 행동 평가는 통합뿐 아니라 사용자의 미정 weight 결정이 필요함을 별도로 기록했다. 각 Ticket에 검증 가능한 완료 동작·수용 기준·제외 경계·Spec 참조를 포함했다. 새 기능이나 광범위한 공용 코드 리팩터링은 추가하지 않았다.

아직 사용자 분할 승인 전이며 이 문서는 하나의 검토안이다. 개별 Ticket 파일·외부 이슈·라벨을 생성하지 않았다. 게시 대상 미설정과 setup 스킬 안내를 유지했다. 구현·테스트 코드·학습 및 기존 사용자 변경에는 손대지 않았다. 검증 결과: Ticket10개에 완료 동작·수용 기준·경계·Spec 참조가 있으며 모든 blocker가 선행 번호를 가리키고 순환이 없음을 확인했다. T01–T15 참조를 모두 포함한다. 변경3문서 수식 검사와 링크152개 검사(오류0), 양 저장소 diff 공백 검사 및 새 검토안 공백 검사가 통과했다. 실제 구현·실행 검증은 미수행이다.
