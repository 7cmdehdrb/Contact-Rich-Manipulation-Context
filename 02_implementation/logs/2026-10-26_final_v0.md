## 구현

`envs/final_envs.py`의 `FinalEnvCfg`는 `ManagerBasedRLEnvCfg`를 직접 상속한다. Scene, Observation, Action, Command, Reward, Termination, Event, Curriculum, PPO·Model CFG를 역할별 `final.py`·`final_ppo_cfg.py`에 독립 선언했다. 개별 OSC·Hand·Goal term CFG도 이전 프로젝트 CFG 대신 Isaac Lab 기반 CFG를 직접 상속한다. 기존 CFG 인스턴스를 만들어 속성을 복사하는 방식은 사용하지 않는다.

`runtime/final.py`의 `FinalEnv`는 `ManagerBasedRLEnv`를 직접 상속하고 기존 runtime의 population 준비→공통 상태 생성→Manager 초기화, seed cache 초기화, 부분 reset snapshot, Hand action reset, step freshness, iteration callback 순서를 보존한다. MDP 함수·stateful term, 모델·runner, 로봇·물성·자산 생성 구성요소는 기존 구현을 재사용한다.

등록 ID와 클래스 이름 및 PPO experiment `inspire_final_v0`를 분리했다. 그 외 학습·환경 설정은 ObjectRandom-v3를 기준으로 유지했다. 입출력·제어·보상·종료·커리큘럼과 train/play 명령은 [환경 계약](../environments/FINAL_V0_ENVIRONMENT.md)에 기록했다. 이후 기존 CFG 변경이 Final로 자동 전파되지는 않으며 공유 함수 수정은 양쪽에 반영된다.

## CPU 검증

Workspace 루트, `/home/min/miniconda3/envs/env_isaaclab/bin/python`을 사용했다.

```bash
env -u PYTHONPATH -u ROS_PACKAGE_PATH -u AMENT_PREFIX_PATH \
  PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONDONTWRITEBYTECODE=1 \
  /home/min/miniconda3/envs/env_isaaclab/bin/python -B -m pytest -q -p no:cacheprovider \
  src/inspire_sweep_baseline/tests/test_final_configuration.py \
  src/inspire_sweep_baseline/tests/test_fusion_holding_v*.py \
  src/inspire_sweep_baseline/tests/test_fusion_holding_osc.py \
  src/inspire_sweep_baseline/tests/test_object_random_geometry.py \
  src/inspire_sweep_baseline/tests/test_clutter_fusion_models.py
```

이 시점의 결과는 **93 passed, 2 warnings in 8.42s**였다. 두 warning은 기존 ONNX export deprecation이다. 이후 Final 전용 OSC·Hand·Goal CFG 비교를 추가하고 아래 명령을 실행했다.

```bash
env -u PYTHONPATH -u ROS_PACKAGE_PATH -u AMENT_PREFIX_PATH \
  PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONDONTWRITEBYTECODE=1 \
  /home/min/miniconda3/envs/env_isaaclab/bin/python -B -m pytest -q -p no:cacheprovider \
  src/inspire_sweep_baseline/tests/test_final_configuration.py
```

**11 passed in 2.16s**. Final 전용 검사의 범위는 다음과 같다.

- 실제 원본/Final Manager 선언과 공식 configclass를 실행해 보상·종료·커리큘럼·events의 모든 값·dict 순서·callable과 인스턴스 격리를 비교한다. 관측 term 순서·함수·noise 설정도 비교한다.
- Scene builder와 `prop_variants`를 실행해 Gray/White 8/8·3/4·0/0의 자산·센서 설정과 friction 적용 후 재구성이 일치함을 확인한다. USD/Sim 자산 타입은 CPU 대역이다.
- PPO·encoder 설정을 비교하며 experiment_name만 예외로 둔다. framework 모델·algorithm 일부는 대역이다.
- 공식 OSC action/controller CFG 선언으로 원본 `configure_reach_osc` 결과와 Final OSC 설정을 비교한다. Hand·Goal CFG도 비교한다. 실제 PhysX action 인스턴스는 생성하지 않는다.
- 기존/Final runtime의 실제 메서드를 CPU Manager 대역에서 실행하여 상태 tensor, seed, 부분 reset, Hand action 초기값, sensor freshness, curriculum callback과 잘못된 iteration 거부를 확인한다.
- AST로 기존 task CFG/runtime 상속과 이전 task CFG import가 없음을 검사하고 Gym 등록 경로를 확인한다. 공통 자산 spawner CFG는 재사용 대상이다.

중간 Scene 검사에서 configclass가 class-level 기본 필드를 제거하므로 `type(self).object_collection`을 읽을 수 없음을 발견했다. 이전 환경 CFG를 생성하는 대신 독립 `_target_spawn()` factory로 같은 pristine 물성 템플릿을 만들도록 수정하고 재검사를 통과했다. PPO 검사 대역의 누락된 필드·타입 선언도 보완했다. 이러한 중간 실패를 실제 simulator 실패와 혼동하지 않는다.

새 Python 13파일은 `ast.parse`로 구문 검사했다. 코드/문서 변경의 `git diff --check`도 통과했다.

## 실제 launcher 시도와 한계

```bash
env -u PYTHONPATH -u ROS_PACKAGE_PATH -u AMENT_PREFIX_PATH \
  PYTHONDONTWRITEBYTECODE=1 \
  /home/min/miniconda3/envs/env_isaaclab/bin/python -B \
  src/inspire_sweep_baseline/tests/_final_probe.py --headless --device cpu

nvidia-smi --query-gpu=name,memory.free --format=csv,noheader
```

`nvidia-smi`는 드라이버 통신 실패(exit9)를 반환했다. Isaac Sim launcher도 `NVML_ERROR_DRIVER_NOT_LOADED`, `cudaErrorNoDevice`, `No CUDA devices found`를 출력하고 검사 본문 이전에 종료했다. 프로세스 exit0이었지만 성공 report가 생성되지 않아 **검증 통과로 계산하지 않는다**. Kit 설정 파일 저장 실패 경고도 있었다. 로그는 workspace `outputs/final_v0_validation/launcher.log`에 보존했다. 시스템 드라이버·설정은 수정하지 않았다.

[실제 launcher probe](../../../../src/inspire_sweep_baseline/tests/_final_probe.py)는 registry import, 전체 Env/PPO 설정·순서·callable 동등성, 직접 기반 클래스, scene 재구성을 검사하도록 추가했다. `--smoke`를 붙이면 seed42·2환경 reset, 관측55/64/3D, 10step 유한성, 강제 timeout을 검사한다. GPU 사용 가능 환경의 후속 명령은 다음과 같으며 **이번에는 이 GPU 명령을 실행하지 않았다**.

```bash
./IsaacLab/isaaclab.sh -p src/inspire_sweep_baseline/tests/_final_probe.py \
  --headless --device cuda:0 --smoke
```

현재 실제 simulator 전체 import·EnvCfg snapshot 비교·USD spawn·접촉 물리·reset/step·PPO 학습·기존 checkpoint 재생·실물 성능은 미검증이다. CPU 동등성 검사가 물리 rollout의 수치적 동일성을 증명하지는 않는다.
