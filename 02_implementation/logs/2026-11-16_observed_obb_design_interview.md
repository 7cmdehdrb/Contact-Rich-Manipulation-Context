# 부분 관측 OBB 설계 인터뷰 기록

## 근거와 의도

사용자가 `grill-with-docs`를 명시적으로 요청했고, 구현 없이 질문을 통해 충돌 없는 관측 OBB 시각화의 요구사항을 확정하도록 지시했다. 확정된 용어와 결정만 기록하고 제안은 미승인으로 구분한다.

## 변경 전후와 영향

- 변경 전: 이번 인터뷰의 별도 용어집·요구사항 기록 없음.
- 변경 후: [용어집](../../GLOSSARY.md)에 확정된 관측 대상·시점·스냅샷 용어를 추가하고, [설계 인터뷰](../../01_plan/environments/2026-11-16_observed_obb_visualization_design.md)에 확정 사항과 미결 질문을 기록했다.
- 타겟만이 아니라 장애물도 포함한다는 정정과, 보이는 영역의 Depth는 온전히 관측한다고 가정한다는 정정을 반영했다. 깊이의 정확한 축/범위는 미확정으로 남겼다.
- 코드·환경 구성·관측 tensor·보상·제어·학습 로그는 변경하지 않는다. 기존 문서 작업트리 변경도 보존한다.
- 계획 문서는 설계 승인 또는 구현 완료 기록이 아니다. ADR 조건을 충족하는 확정된 비가역적 선택은 없어 ADR을 생성하지 않았다.

## 후속 응답 반영

- 사용자 근거: 직전 Q4/Q5에 예, Q6에 아니요 및 '가림을 유발하는 물체의 z는 무한', 마지막으로 초기 물체 간 가림만 고려한다고 답했다.
- 변경 전: 깊이의 정확한 뜻, 계산용 박스 근사, 높이 처리, 가림 참여 대상이 미결이었다.
- 변경 후: 남은 좌우 구간의 전체 깊이, 회전 박스 근사, 높이 무관 가림, 타겟·활성 장애물 간 상호 가림을 확정 사항에 반영했다. 관측 잔여 형상에 OBB를 다시 피팅하는 방향도 기록했다.
- Q7의 분리된 가시 영역 처리는 응답이 없으므로 미결로 보존했다. OBB 방향·피팅 방식과 완전 가림·미세 조각·노이즈도 다음 질문 대상이다.
- 영향 및 최종 대조: 인터뷰·용어집·이 로그만 갱신한다. 기존 코드와 사용자 문서 변경은 보존하며 구현·학습·제어 작업은 하지 않는다.

## 후속 응답 반영 — 분리 조각과 노출 기준

- 사용자 근거: Q7의 같은 물체 조각 병합을 거부하고 별개 물체 취급을 지시했다. 매우 작은 노출은 제외하되 기존 35%를 유지할 필요가 없고, 가시성과 OBB 계산을 통합해 빠르게 계산하도록 요청했다. Q9의 수직축 유지 OBB와 Q11의 노이즈 제외는 승인했다.
- 변경 전: 분리된 조각 처리, OBB 방향, 미세 조각, 노이즈가 미결이었다.
- 변경 후: 조각별 독립 관측·작은 조각 제외·XY 최소 면적 OBB·무노이즈를 확정으로 기록했다. '가시 조각'과 '관측 물체'를 구분하는 용어를 추가했다.
- 계산안: 구간 가시성 결과와 절단 기하를 공유하고 작은 조각을 먼저 제외한 뒤 OBB를 계산하는 방안을 제안했다. 최소 노출 지표와 값은 미확정이며, 절대 노출 폭은 추천안일 뿐이다.
- 영향·최종 대조: 설계 관련 세 문서만 갱신했다. 코드·기존 환경·사용자 문서 변경·학습 로그는 보존한다. 속도 개선을 측정하거나 구현을 완료했다고 주장하지 않는다.

## 후속 응답 반영 — 폭과 비율 조합·시각화 범위

- 사용자 근거: Q12에 폭과 비율을 조합하라고 지시하고, Q13/Q14/Q15의 독립 관측 ID·관측 OBB 기본 표시/전체 박스 토글·Simple 단일 검토 장면을 승인했다.
- 변경 전: 절대 폭은 추천안이었고 ID/표시/기준 장면은 미결이었다.
- 변경 후: 조각별 폭·비율의 두 조건, 독립 관측 ID와 역할 판별 제외, 비교용 전체 박스 토글, 정책 없는 Simple 단일 장면을 확정했다. 노출 폭과 노출 비율의 정의를 용어집에 기록했다.
- 계산안: 노출 폭을 최소 절대 폭과 최소 비율×전체 폭 중 큰 값에 비교하여 OBB 계산 전 조각을 거르는 방안을 기록했다. 최소 5mm/20%는 다음 질문의 제안일 뿐 확정값이 아니다.
- 영향·최종 대조: 설계 세 문서만 갱신했다. 소스 구현·시뮬레이션·학습·제어는 수행하지 않았으며 기존 사용자 변경은 보존한다.

## 후속 응답 반영 — 기준값과 정지 검토 확정

- 사용자 근거: 최소 폭을 2cm로 변경하고 노출 비율 20%를 승인했다. 정지 장면에서 수동 재배치·재관측하는 방식도 승인했다.
- 변경 전: 5mm/20%는 추천값이었고 정지 장면 여부는 미결이었다.
- 변경 후: 폭 2cm 이상 AND 노출 비율 20% 이상, 경계 포함, 정지 배치 검토를 최종 요구사항에 반영했다. 같은 물체에서 떨어진 조각들은 각각 판정한다.
- 최종 대조: 타겟+장애물, 회전 박스 근사, 높이 무관 가림, 전체 깊이 유지, 조각별 독립 관측, 수직축 유지 OBB, 무노이즈, 역할 판별 제외, 충돌 없는 표시, Simple 단일 정지 장면이라는 누적 결정과 대조했다.
- 후속 검증 조건을 기록했지만 실행하지 않았다. 개별 질문은 해소된 상태로 기록하되, 전체 설계 공동 이해 확인과 구현 지시는 구분했다.
- 영향: 이번 턴은 인터뷰 문서와 이 로그만 변경했다. 구현 코드·기존 환경·사용자 문서 변경·학습 로그는 보존한다.

## 개발 명세서 작성 — to-spec

- 사용자 근거: 전체 설계를 확정하고 `to-spec`으로 개발 명세서를 작성하라고 요청했다. 새 요구사항을 추가하지 말고, 구현은 기존 패키지가 아닌 src 아래 새 패키지에서 수행하도록 지정했다.
- 검증 접점: 스킬의 확인 절차에 따라 '배치된 물체 정보 → 독립 관측 ID와 OBB 스냅샷' Interface 하나를 주 검증 Seam으로 삼고 표시·토글·재관측은 뷰어에서 별도 확인하는 안을 제시했다. 사용자가 동의했다.
- 변경 전: 인터뷰 문서가 최종 설계 확인 대기 상태였고 별도 개발 명세서는 없었다.
- 변경 후: [개발 명세서](../../01_plan/environments/2026-11-16_observed_obb_visualization_spec.md)를 추가하고 인터뷰 상태를 확정으로 갱신했다. 스킬의 일곱 섹션에 문제·해결·32개 사용자 이야기·구현 결정·검증 결정·제외 범위·참고 사항을 기록했다.
- 최종 대조: 높이 무관 가림, 전체 깊이 유지, 조각별 독립 관측, 폭 2cm AND 비율 20%, 수직축 유지 OBB, 무노이즈, 역할 판별 제외, 정지 장면과 수동 갱신, 충돌 없는 표시, Simple 자산·배치 재사용, 새 패키지 위치를 모두 대응시켰다. 이름·조작 키·성능 숫자·추가 기능은 요구사항으로 만들지 않았다.
- 참고 검증 선례: 직접 의존하는 scene randomization의 가시성 경계·제외 물체 가림 유지 테스트, 활성 패키지의 독립 다각형 OBB 배치 검증과 초기 스냅샷 유지 테스트를 소스로 확인했다. 테스트를 실행한 것은 아니다.
- 게시 상태: 로컬 지침과 설정에서 게시 대상 이슈 트래커를 확인하지 못했다. main과 문서 저장소의 GitHub remote만으로 게시 대상을 임의 결정하지 않았다. 스킬 지침에 따라 `/setup-matt-pocock-skills` 설정이 필요하다고 안내하며 이슈 생성·라벨 적용은 수행하지 않는다.
- 영향: 개발 명세서 추가와 인터뷰·이 로그 갱신만 수행한다. 새 코드·새 패키지·새 테스트를 작성하거나 시뮬레이션·학습을 실행하지 않는다. 기존 사용자 변경과 학습 로그를 보존한다.

## 최종 대조와 검증

추가한 세 문서를 대상으로 `check_markdown_math.py` 통과, `check_document_links.py` 오류 0을 확인했다. 문서 저장소 전체 링크 검사도 593개 Markdown에서 오류 0이며 `git diff --check`가 통과했다. 새 파일은 별도로 행 끝 공백을 확인한다. 기하 알고리즘 구현·시뮬레이션·시각화·성능·학습은 미검증이다.

최종 기준값 반영 후 inline math의 간격 escape가 수식 검사에서 한 번 검출되어 단위를 수식 밖으로 옮겼다. 해당 두 문서의 수식 검사를 재실행하고, 링크 검사 오류 0 및 세 문서의 공백 검사 결과와 함께 확인한다.

개발 명세서 작성 후 변경한 세 문서의 수식 검사가 통과했다. 전체 링크 검사는 Markdown 594개에서 오류 0이며 `git diff --check`와 새 문서를 포함한 별도 공백 검사가 통과했다. 명세서의 스킬 템플릿 일곱 섹션과 32개 사용자 이야기 형식을 확인했고, 폐기된 5mm 제안이 명세서에 남지 않았음을 확인했다. 기능 테스트·뷰어·성능 검증은 수행하지 않았으며 이슈 게시도 수행하지 않았다.
