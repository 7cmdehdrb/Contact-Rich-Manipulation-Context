## 요청과 변경 의도

사용자는 Inspire-Sweep-Simple 계열의 베이스 환경을 구성·관측·액션·종료·커리큘럼 등 누락 없이 설명하고, 파생 환경은 변경 내용과 실험 의도를 비교표로 정리하도록 요청했다.

기존 설명서는 상속 대응과 변경점 중심이었다. 같은 문서를 확장해 베이스의 Scene/물리, startup/randomization/reset, 관측/센서/오차, 액션/OSC/손 제어, Command, 활성·비활성 보상, 종료, 활성·비활성 curriculum, 메트릭, PPO를 설명했다. 여섯 환경 비교표에 직접 부모·변경 내용·검증하려는 가설을 함께 기록했다.

## 코드 대조와 주의점

역할별 `sweep_simple` 설정과 공유 계산 함수의 실제 구현을 확인했다. 특히 다음 혼동을 방지했다.

- 베이스 Reach는 최고 접근 기록 개선분만 보상한다. 과거에 받은 보상이 후퇴 중에도 매 step 지급되는 것은 아니다.
- 정책 입력은 초기 물체 위치 스냅샷이지만 보상·종료는 현재 물체 상태를 사용한다.
- 접촉 유지의2-of-3 인정과 Prof의 현재 순간 접촉 조건을 구분했다.
- timeout/success 종료 항목은 중첩되며, 최근N개 창의 timeout 성공률과 별도다.
- 목표 점유 비율은≤3cm, timeout 성공 판정은<3cm다.
- Prof와 Hard는 각각 여러 요소를 묶어 변경하므로, 결과 차이를 단일 요인의 효과로 단정하지 않도록 비교 해석을 명시했다.

기존 Hard 설명의 anchor와 기존 검증 기록을 유지했다. 실험 의도는 가설로 표시하고 학습 성능 검증 결과로 표현하지 않았다. 생산 코드·환경 설정·학습 로그는 수정하지 않았다.

## 검증

설정에 정의된 Observation·Reward·Termination·Curriculum term 이름을 설명서와 대조하여 누락0건을 확인했다. 변경 Markdown4개 수식 검사, 문서 링크 검사(errors0), `git diff --check`를 통과했다. 링크 검사에서 MLP 크기/활성함수 표기가 링크로 해석된 문제를 수정 후 재검사했다. 문서 작업이므로 학습/물리 테스트를 다시 실행하지 않는다. 기존 구현 검증 결과와 GPU 미검증 범위는 설명서에 보존했다.
