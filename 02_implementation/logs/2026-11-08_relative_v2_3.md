# Relative-v2_3: 목표 반대편 Reaching 기준점

## 요청과 기준

v2_1을 직접 상속하여 Contact 유지 보상을 보존하고, 목표→현재 물체→Reaching Point 순으로 XY 직선 위에 놓인 물체 뒤쪽5cm 지점을 Reaching 기준으로 사용한다. Z는 선반 작업면+물체 높이 절반이다. 사용자 후속 답변에 따라 기준점 주변 무보상 반경도 기존10cm에서 **5cm**로 변경했다.

workspace 기준 `0c3e8d9`, 문서 저장소 기준 `bc61a24`. 기존 IsaacLab 작업트리 표시와 미추적 왼쪽 접근 진단 문서를 보존했다. 학습 로그·체크포인트는 변경하지 않았다.

## 최종 계약

| 항목 | v2_1 대비 v2_3 |
| --- | --- |
| Gym ID | `Inspire-Wrench-Refactor-Relative-v2_3` |
| EnvCfg | `WrenchRefactorRelativeV2_3EnvCfg(WrenchRefactorRelativeV2_1EnvCfg)` |
| runtime | 동일 `WrenchRefactorEnv` |
| Reaching 함수 | `DexReachProgress` → `OppositeReachProgress` |
| Reaching 기준 | 현재 물체 link 원점 → 목표 반대편 XY5cm, 선반 바닥면+물체 높이/2 |
| Reaching params | frame_name 유지, offset0.05 추가, near_radius0.10→0.05 |
| Reaching weight | 기존30 유지 |
| PPO | v2_1 runner 직접 상속, experiment_name만 `inspire_wrench_refactor_relative_v2_3` |
| Contact 유지 | 활성 상태·함수·weight0.1·params 모두 보존 |
| 나머지 Reward | 거리 cosine·거리 증가 페널티·Hold·최초 진입·성공 및 모든 비용 그대로 |
| Scene·Event·reset·Command·Observation·Action | 부모 그대로 상속 |
| Termination·Curriculum | 부모의 모든 term·계수·임계값·일정 유지 |

현재 물체 위치를 p, 목표를 g, Reaching 기준점을 q라 하면 다음을 사용한다.

```math
\mathbf{q}_{xy}=\mathbf{p}_{xy}+0.05\frac{\mathbf{p}_{xy}-\mathbf{g}_{xy}}{\|\mathbf{p}_{xy}-\mathbf{g}_{xy}\|},\qquad
q_z=z_{\mathrm{shelf\ surface}}+\frac{h}{2}.
```

물체 높이는 startup에서 확보한 scale 반영 bounds의 z최댓값−최솟값이다. 고정된 선반 초기 위치와 작업면 높이1.05m를 사용하며, 물체 link 원점의 Z나 물체 기울기로 기준점 높이가 흔들리지 않는다. XY는 매step 실제 현재 타겟 위치를 따른다. 목표와 타겟의 XY 거리가1e-8m 이하이면 직선 방향이 정의되지 않으므로 초기 sweep 방향의 반대 방향을 사용한다. 초기 sweep도0인 초기화 단계는 +X로 안전하게 정의한다.

EEF와 q 사이의 **3D 거리에서5cm를 뺀 값**을0 이상으로 제한하고, 에피소드 최단거리 기록을 개선한 양에만 보상한다. weight30, dt상쇄, 대기·후퇴·기존 최단거리로 복귀 시 추가 지급 없음은 부모와 같다. 기준점은 움직이므로 물체 이동으로 거리가 줄어도 보상에 기여할 수 있으며 이는 부모의 live-target 방식과 같다. 목표 반경·성공 판정은 변경하지 않았다.

이 기준점은 **보상을 통한 접근 유도**에 사용한다. Actor에 현재 물체 GT나 Reaching Point 관측을 추가하지 않았고, 기존 Actor 초기 타겟/ Critic 현재 타겟 입력을 보존했다. 학습 효과는 아직 입증하지 않았다.

## reset 순서와 부모 보존

Reward reset은 scene reset 이후, command reset 이전에 실행된다. 이전 에피소드 goal을 사용하지 않도록 reset 기준점은 현재 물체 위치+새 `sweep_dir`로 계산한다. 실제 step에서는 command의 현재 goal을 사용한다. 부분 reset 시 해당 환경의 기준거리만 갱신한다. 신규 reward는 기존 함수 본문을 바꾸지 않고 기존 파일에 별도 helper·파생 클래스로 추가했다.

실제 Isaac Lab 설정 사전 전체 대조에서 부모·자식 차이는 `rewards.target_reaching`만 확인했다. 부모 인스턴스와 새 부모 인스턴스도 작업 전 사전과 같았다. runner 사전의 유일한 차이는 experiment_name이다. 기존 v2_2는 여전히 Contact 제거 전용이며 v2_3의 부모가 아니다.

## 후속: Reaching Point 시각화

사용자가 임시 접근점을 눈으로 확인하도록 물리 효과 없는 마커를 요청했다. 기준 workspace commit은 `263dba1`이며 기존 IsaacLab 변경 표시를 보존했다.

- v2_3에 `debug_reaching_point=True`를 추가했다. 기존 버전에는 이 설정이 없으므로 마커를 만들지 않는다.
- 공통 runtime의 표시 전용 helper가 초기화·public reset·step 완료 후 `opposite_reaching_point`의 실제 보상 좌표를 재사용한다. 자동 episode reset 뒤에도 새 목표의 기준점으로 갱신한다.
- `/Visuals/InspireWrenchRefactor/reaching_point`의 자홍색 구, 반지름8mm(직경1.6cm)다. 구의 크기는 접근 허용 반경5cm를 뜻하지 않는다.
- `VisualizationMarkers`를 사용하고 SphereCfg의 rigid_props/collision_props는 None이다. 마커 생성기는 물리 API도 제거한다. 실제 USD 하위 prim에 RigidBodyAPI/CollisionAPI가 없음을 검사했다.
- 표시를 끄려면 `env.debug_reaching_point=False` 설정을 사용할 수 있다. 보상·관측·동작·접촉·PPO·종료·커리큘럼 수치는 변경하지 않았다.
