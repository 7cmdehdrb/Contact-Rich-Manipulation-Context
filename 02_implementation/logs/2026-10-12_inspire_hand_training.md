## 1. 배경 및 검증 전략

초기에는 [Contact-Rich-Manipulation](https://github.com/7cmdehdrb/Contact-Rich-Manipulation)에서 **Inspire Hand, Tactile 및 F/T 센서, OSC 제어기를 통합한 환경의 Sweeping 정책을 학습**하려 했다. 기존 Sweeping 환경의 보상 구조를 계승하면 변경된 로봇 구성에서도 학습이 가능할 것으로 예상했으나, 물체 옆에서 정지하거나 접촉 과정에서 물체를 넘어뜨리는 등 안정적인 Sweeping으로 이어지지 않는 양상이 나타났다.

통합 환경에서는 Hand 형상, 센서 장착, 제어 방식, 접근 기준점 등 여러 조건이 함께 달라져 **실패 원인을 구분하기 어려웠다.** 이에 **기존에 정상적인 학습이 확인되었던 김태호의 기준 환경으로 돌아가, 변경 요소를 단계적으로 도입하는 방식으로 검증 전략을 전환**하였다.

단계별 검증은 다음 순서로 진행하였다.

1. **Hand 교체:** 기존 제어기와 보상 구조를 유지하면서 Inspire Hand 도입의 영향을 확인한다.
2. **손가락 제어 추가:** Hand를 고정하지 않고 제어할 때에도 학습이 가능한지 확인한다.
3. **센서 추가:** Tactile과 F/T를 포함한 구성에서도 학습이 가능한지 확인한다.
4. **현재 물체 위치 관측 제거:** 초기 위치와 실시간 로봇 상태·접촉 피드백을 사용하는 조건으로 확장한다. **학습 중.**
5. **Critic 전용 특권 정보 추가:** Actor의 관측 제한을 유지하면서 학습 시 현재 물체 상태를 활용한다. **학습 대기 중.**

이하의 학습 성공·실패와 행동 양상은 제공된 실험 기록을 기준으로 한다. 코드 검토로 확인한 설정과 학습 결과의 원인에 대한 해석은 구분하여 기술한다.

## 2. 초기 통합 환경: Isaac-Sweep-Inspire-Right-OSC

### 공통 목적

기존 보상 구조를 활용하여 **Inspire Hand와 접촉 센서를 포함한 OSC 환경에서도 Sweeping을 학습할 수 있는지** 확인하였다.

### v2 — 기존 보상 구조의 적용

영상 파일명: `Isaac-Sweep-Inspire-Right-OSC-v2.mp4`

**검증 목적**

Hand 및 센서 구성이 변경된 환경에서도 기존 보상 구조로 Sweeping을 학습할 수 있는지 확인한다.

**관찰 결과**

- 일부 학습에서는 물체를 미는 행동이 나타났다.
- 다른 경우에는 물체 옆까지 접근한 뒤 정지하여, Sweeping으로 이어지지 않았다.
- 손가락으로 물체를 치는 과정에서 전도가 발생하고 실패 종료로 이어지는 사례가 관찰되었다.

**해석**

접촉 과정에서 전도가 발생하면 성공적인 밀기까지 진행하기 어려우므로, **접근·정렬 보상에 머무르는 소극적인 정책**이 형성되었을 가능성을 주요 가설로 설정하였다.

### v3 — Reaching Point 및 Gate 위치 검증

영상 파일명: `Isaac-Sweep-Inspire-Right-OSC-v3.mp4`

**검증 목적**

Hand 형상 변경으로 인해 기존 Reaching Point와 Sweeping 보상의 Gate 기준점이 실제 접촉 위치와 맞지 않는지 확인한다.

**변경 사항**

Reaching 목표점과 Gate 기준점을 물체에 더 가깝게 이동하였다. 현재 코드에서는 Y 방향 접근 offset을 물체 폭에 기반한 값에서 **0.005 m**로 변경한다.

**관찰 결과**

- 물체에 가까이 접근하는 행동은 나타났으나, 안정적인 Sweeping으로 이어지지 않았다.

**해석**

v2와 v3의 결과를 종합하면, 밀기 실패의 주요 원인은 Reward Formulation 자체보다는 **Gripper 교체에 따른 접촉 특성 변화**에 있는 것으로 추정된다.

## 3. 기준 환경으로 복귀: Isaac-Sweep-Object-UR5e-Random-Single-Inspire-Open

### 공통 목적

초기 통합 환경의 실패 원인을 분리하기 위해, 기준 환경인 [Sweeping-Policy-DRL-Sim-Train](https://github.com/IROL-SSU/Sweeping-Policy-DRL-Sim-Train/tree/min)에서 변경 범위를 줄여 실험하였다.

먼저 **Joint Position Controller와 기존 보상 구조를 유지하면서 Gripper를 Inspire Hand로 교체**하였다. 이 단계에서는 Axia80 및 Tactile 센서를 추가하지 않았으며, 이후 손가락 제어·물체 조건·센서·관측 제한을 차례로 도입하였다.

### v0 — Hand 교체 및 Arm 관절속도 종료 조건 확인

영상 파일명: `Isaac-Sweep-Object-UR5e-Random-Single-Inspire-Open-v0.mp4`

**검증 목적**

Inspire Hand의 도입이 기존 Sweeping 학습에 미치는 영향을 확인한다.

**구성**

- Inspire Hand를 최대로 펼친 상태로 고정한다.
- 손가락 제어 Action을 제외하고 Arm 6D Joint Position Action을 사용한다.
- Axia80 및 Tactile 센서는 포함하지 않는다.
- 기존 보상 구조를 사용한다.

**관찰 결과**

초기 학습에서는 물체로 접근하지 않고, 초기 관절 자세 부근에서 정렬 보상만 획득하는 양상이 나타났다.

학습 로그를 확인한 결과, `hand_velocity` 종료 조건이 접근 과정의 병목으로 작용하는 양상이 확인되었다. 이에 현재 Inspire 환경의 종료 임계치를 원본 **1.0 rad/s에서 3.0 rad/s**로 완화하였다. 해당 임계치를 완화한 이후에는 Reaching 행동이 나타났으나, 전체 Sweeping의 성공은 간헐적으로 관찰되었다.

### v1 — 손가락 제어 도입

영상 파일명: `Isaac-Sweep-Object-UR5e-Random-Single-Inspire-Open-v1.mp4`

**검증 목적**

Hand를 고정한 조건에서 벗어나 손가락 제어를 추가해도 Sweeping을 학습할 수 있는지 확인한다.

**변경 사항**

v0을 기반으로 손가락 공통 개폐 및 엄지 제어를 위한 2D Action을 추가한다. Arm 6D와 합쳐 전체 Action은 **8D**가 된다.

**관찰 결과**

- Sweeping에 성공하는 행동이 간헐적으로 나타났다.
- 실패 사례에서는 기존과 달리 **손목의 틸팅을 유발하는 Action이 출력되는 경향**이 관찰되었다.

**해석**

앞선 환경의 간헐적 성공과 손목 틸팅을 함께 고려하여, 정책이 **물체의 전도를 줄이는 방향의 행동을 학습했을 가능성**을 후속 가설로 설정하였다.

### v1-mass — 전도에 덜 민감한 물체 조건에서 검증

영상 파일명: `Isaac-Sweep-Object-UR5e-Random-Single-Inspire-Open-v1-mass.mp4`

**검증 목적**

앞선 실패에 물체 전도와 접촉 불안정성이 영향을 주는지 확인한다.

**변경 사항**

- v1을 기반으로 대상 물체를 **전도에 덜 민감하도록 형상과 질량 분포를 조정한 1 kg 실린더**로 교체한다.

**관찰 결과**

**이 환경부터 정상적인 Sweeping 정책의 학습이 확인되었다.**

**해석**

이 결과는 물체의 물리적 특성과 접촉 안정성이 학습 성패에 영향을 주었을 가능성을 보여준다. 즉, **안정적인 물체 조건에서는 기본 Sweeping 방식을 사용할 수 있음을 의미한다.**

### v2-mass — Tactile 및 F/T 센서 추가

영상 파일명: `Isaac-Sweep-Object-UR5e-Random-Single-Inspire-Open-v2-mass.mp4`

**검증 목적**

v1-mass에서 학습이 가능했던 구성을 기반으로, **접촉 센서를 포함한 환경에서도 Sweeping을 학습할 수 있는지** 확인한다. F/T 센서 추가에 따른 Tool Pose 변화와 관측 차원 증가가 학습 수렴에 영향을 줄 수 있으므로, 이를 검증한다.

**변경 사항**

- Tactile 및 F/T 센서를 추가하고 센서값을 정책 관측에 포함한다.
- **손바닥 패드 한 영역의 접촉 여부 1D와 F/T 6D**를 사용한다. 기존 34D 관측과 합쳐 Actor 관측은 **41D**, Action은 **8D**이다.

**관찰 결과**

**센서를 포함한 해당 구성에서도 정상적인 Sweeping 정책의 학습이 확인되었다.**

**해석**

이 결과는 **센서가 포함된 환경의 학습 가능성**을 확인한 것이다. 센서가 성능을 높였는지, 현재 물체 위치 관측 없이도 접촉 피드백을 활용해 수행할 수 있는지는 후속 비교에서 확인해야 한다.

## 4. 현재 물체 위치 관측 제거 및 Privileged Critic 검증

기본 Sweeping이 가능한 구성을 확보한 이후에는 **정책 실행 중 현재 물체 위치를 제공하지 않는 조건**으로 확장한다.

### v3 — 초기 물체 위치만 사용하는 Actor·Critic

**검증 목적**

현재 물체 위치를 계속 관측하던 조건에서, 초기 위치와 로봇 상태·접촉 센서 등을 사용하는 조건으로 변경했을 때 학습이 가능한지 확인한다.

**변경 사항**

- Reset 시 물체 위치를 한 번 취득하여 저장한다.
- 에피소드 동안 물체가 이동해도 해당 위치 관측을 갱신하지 않는다.
- Actor와 Critic 모두 동일한 **41D** 관측을 사용한다.

**현재 상태**

> **학습 중인 환경**

### v4 — Critic에만 현재 물체 상태 추가

**검증 목적**

Actor의 제한된 관측 조건을 유지하면서, **학습 시 Critic에 현재 물체 상태를 제공**하는 것이 학습에 도움이 되는지 확인한다.

**변경 사항**

Actor는 v3와 동일한 **41D** 관측을 사용한다. Critic에는 다음 **13D**를 추가하여 총 **54D**를 제공한다.

| Critic 전용 정보 | 차원 |
| --- | ---: |
| 현재 물체 위치 | 3D |
| 현재 물체 자세 — Quaternion | 4D |
| 현재 물체 선속도 | 3D |
| 현재 물체 각속도 | 3D |
| **합계** | **13D** |

**현재 상태**

> **학습 대기 중인 환경**

## 5. 남아 있는 이슈 및 후속 검증

### 5.1. Inspire Hand 교체 이후 Arm 관절속도 종료가 발생하는 원인

현재는 원본의 관절속도 종료 임계치를 완화한 상태로 학습을 진행한다. **속도가 임계치를 초과하는 이유는 확인되지 않았다. 이를 확인한 뒤, 원래 기준을 복원할 수 있는지 판단**해야 한다.

또한, 해당 임계치를 변경한 이후 로봇 **Arm에서 진동이 발생하는 현상**이 관찰되었다.

### 5.2. 물체–선반 및 Hand–물체 마찰 검증

기존 환경에는 마찰 파라미터를 명시적으로 설정하는 항목이 없다. 따라서 Hand 교체 이후 발생한 물체의 전도가 **물체–선반 마찰이 실제 조건보다 크게 설정되어, 물체가 미끄러지기 전에 Hand 접촉에 의해 전도되는 현상**인지 검증할 필요가 있다.

이를 확인하기 위해 **Friction Test에서 확인한 실제 마찰 계수와 Randomization을 적용하고 검증**한다.

### 5.3. 기존에 검증한 내용의 재검증

동규 & 재훈 학습 기록에서 사전에 검증한 내용은 **현시점에서 재검증하지 않는다.** 다른 환경 구성이 완전히 고정된 후 기존에 상정한 구성을 적용하고, **이후 학습이 되지 않을 경우 Ablation을 수행**한다.

- Operational Space Control의 사용
- Relative Observation의 사용
- Initial Joint State 변경 — Object Pose-Dependent
