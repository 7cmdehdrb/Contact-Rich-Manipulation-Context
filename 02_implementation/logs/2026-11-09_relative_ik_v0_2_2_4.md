## play 전용 영역 표시

`play.py`가 새 설정 `debug_spawn_regions`를 True로 설정한다. `train.py`는 같은 속성이 있는 환경에서 False를 강제하므로 viewer·video 사용 여부와 관계없이 학습 중에는 마커 생성/기하 분류/갱신이 없다. 기존 환경에는 이 속성이 없으므로 동작이 달라지지 않는다.

첫4개 환경만 기본 표시한다(`debug_spawn_max_envs=4`). 초기 배치 reset 시만 갱신하며, 부분 reset은 해당 환경 그림만 바꾼다. 선반 표면 위2mm에 두께1mm 비물리·비충돌 반투명 타일을 표시한다. 부모 sampler의5mm 셀과 scale별 외접원·1cm 여유·중심 offset·선반 frame을 재사용한다.

- RED: 타겟 외접원 sweep을 로봇 쪽 선반 앞 경계로 연장한 금지 영역.
- WHITE: 선반 안에서 RED 및 기존 장애물 점유 영역을 제외한 공간.
- 주황: 이미 배치된 장애물의1cm 확장 원 점유 영역.

WHITE는 물체의 확장 원 전체가 들어가야 하는 물리 영역이다. 물체 크기별로 다른 중심 좌표 가능 마스크를 뜻하지 않는다. 셀 경계는 기존 cell_margin으로 보수적으로 색칠하므로 최대 셀 크기 수준의 시각적 근사다. 그림은 에피소드 초기 스폰 규칙의 스냅샷이며 물체가 움직일 때 따라 변하지 않는다. 표시 제한은 시각화에만 적용하며 물리/관측/배치에는 영향을 주지 않는다.

## 성공 종료 분류와 TensorBoard

`success_at_timeout`은 timeout 시점에만 타겟 root와 목표 command의 XY 거리 **<0.03m**를 검사한다. 정확히0.03m는 성공이 아니며 Z 오차는 이 거리 조건에 포함하지 않는다. 기존 물체 낙하/기울기·선반 실패·팔 속도 실패가 같은 step에 있으면 성공으로 세지 않는다. 실패 term 다음에 success를 평가한다. 사용자 지정 엄격 부등호가 일반 목표 반경의 inclusive 규칙보다 우선한다.

조기 성공 종료는 없다. 기존10초 timeout term은 그대로며 success는 그 부분집합으로 `time_out=True`를 사용한다. 따라서 성공 표시는 추가되지만 terminated/truncated 분류와 PPO timeout bootstrap은 부모와 같다. 이는 성공률 확인만 원한다는 사용자 목적에 따른 결정이다. 성공에도 timeout과 success 두 term이 함께 표시된다.

- `Metrics/timeout_success_rate`: 세션 시작 이후 성공 timeout 수 / 전체 timeout 수.0–1 비율이며 분모0일 때0.
- `Metrics/timeout_success_count`: 세션 누적 성공 timeout 수.
- `Metrics/timeout_episode_count`: 세션 누적 timeout 수.
- `Episode_Termination/success`: Isaac Lab 기본 성공 term 통계. timeout 전용 분모가 아니므로 위 전용 지표와 구분한다.

조기 실패는 timeout 비율 분모에서 제외한다. deadline과 동시 실패는 timeout 분모에 들어가지만 성공 분자에는 들어가지 않는다. 리셋 전에 terminal mask를 읽고, reset 후 pose/goal로 성공을 재평가하지 않는다. 최초 reset·길이0 재리셋은 세지 않는다. 세션 카운터는 checkpoint 복구 시 새로 시작한다. 일반 logger는 rollout에서 수집한 scalar들을 요약하므로 표시 rate는 누적 비율 추세이며 해당 iteration만의 성공률이 아니다.
