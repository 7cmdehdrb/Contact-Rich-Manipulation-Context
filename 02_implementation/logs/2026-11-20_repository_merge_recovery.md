# Sweep v0와 원격 촬영 도구의 병합 충돌 복구

## 요청과 최종 범위

사용자는 `git pull origin main` 후 문서 서브모듈 충돌을 해결하고 양쪽 저장소를 커밋·푸시하도록 요청했다. 이후 Git 전송 인증이 이 도구 세션에 없음을 확인한 뒤 **사용자가 직접 푸시하겠다고 정정**했다. 최종 범위는 충돌 해결·검증·양쪽 로컬 커밋 완료이며, 원격 푸시는 사용자에게 넘긴다.

## 시작 상태와 보존 대상

- 상위 저장소 HEAD=`3db65a6`, `origin/main` 및 진행 중인 MERGE_HEAD=`2c3480c`였다. 로컬 Sweep v0 구현과 원격 촬영 도구가 분기되어 있었다.
- gitlink 충돌은 base=`5074b42`, ours=`db140e6`, theirs=`a142510`였다. 상위 README는 자동 병합되어 stage에 있었고, 촬영 Python3개도 원격 변경으로 stage에 있었다.
- 문서 서브모듈 HEAD=`db140e6`, `origin/main`=`a142510`이었다. Sweep v0 인계·안내·계약·개발 로그와 wr7 진단 기록6개 파일이 미커밋 상태였다.
- 사용자 오류의 `14c9dd5`는 검사 시 문서 저장소에 존재했으며 원격 main의 조상이다. 문서 원격은 기존 `db140e6`을 포함한다. 객체를 임의로 삭제·교체하거나 원격 이력을 강제 변경하지 않았다.

## 복구 내용과 최종 대조

1. 미커밋 Sweep v0 문서·wr7 진단6개 파일을 `00d6ee7`로 먼저 커밋해 보존했다.
2. 문서 `origin/main`을 정상 merge했다. 현재 인계와 활성 환경 안내는 자동 병합되었고, 원격 촬영 기록·기존 동기화 기록과 로컬 Sweep v0 문서가 함께 남았다.
3. 이 개발 로그를 포함하여 문서 병합을 커밋한 뒤, 상위 gitlink를 해당 문서 HEAD로 stage하여 서브모듈 충돌을 해결한다. 상위 기존 MERGE_HEAD를 유지해 정상 merge commit으로 완료한다.
4. 상위 README의 Sweep v0 안내와 원격 촬영 안내를 모두 유지한다. 촬영 Python3개는 원격 `2c3480c`와, 기존 로컬 Sweep v0 구현 파일은 `3db65a6`과 동일한지 대조한다.
5. 다른 서브모듈의 지정 커밋·사용자 변경·학습 로그·산출물은 수정하지 않는다. 소스·수치·보상·상속을 새로 변경하는 작업이 아니다.

## 인증과 전달

HTTPS Git 전송은 `could not read Username for 'https://github.com'`로 실패했고 SSH agent에는 identity가 없었다. 연결된 GitHub 앱의 읽기로 두 원격 main의 SHA가 로컬 원격 추적 ref와 같음을 확인했다. 앱 API로 다른 SHA의 대체 커밋을 만들거나 기존 로컬 이력을 재작성하지 않았다. 사용자의 직접 푸시 정정 이후 추가 원격 변경은 수행하지 않는다.

푸시 순서는 문서 서브모듈 main, 상위 저장소 main이다. 최종 로컬 HEAD와 origin/main의 일치는 사용자 푸시 전에는 기대하지 않는다. GPU·Isaac Sim·학습·촬영은 실행하지 않았다.
