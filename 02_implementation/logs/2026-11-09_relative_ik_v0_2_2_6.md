# Relative-IK-v0_2_2_6 및 최근 에피소드 메트릭 변경

2026-11-09. 기준 HEAD4bd36f2. 사용자는 예약된 메트릭 변경을 카운터 도입 환경부터 적용하고, 이어서 v0_2_2_4의 자식 v0_2_2_6에서 Reach만 바꾸도록 요청했다. 기존 문서 submodule의 사용자/인계 변경은 보존했다. 커밋·학습·학습 로그 정리는 수행하지 않았다.

## 1. 기존 환경에 적용한 메트릭 변경

v0_2_2_4 EnvCfg에 `timeout_metric_window=10000`을 추가했다. N은 사용자 확정 숫자가 아니며 이전 논의의 제안값을 개발 기본값으로 채택한 것으로 설정에서 변경 가능하다. v0_2_2_4 runtime의 세션 누적 카운터를 고정 길이 ring buffer로 대체했다. 따라서 **같은 이름의 v0_2_2_4를 직접 수정한 작업**이며 이를 사용하는 v0_2_2_5·v0_2_2_6도 같은 변경을 받는다. v0_2_2_3-Fast-Test 이하에는 카운터를 추가하지 않는다.

창은 병렬 환경 전체에서 최근 완료된 N개 에피소드다. 조기 실패도 창을 차지하지만 timeout/success 개수는0이다. 동일 step의 종료는 env ID 오름차순으로 처리한다. 한 배치가N보다 크면 마지막N개를 유지한다. N개 미만일 때는 지금까지 완료된 에피소드만 집계한다. 초기 reset, 길이0의 재reset, 종료하지 않은 에피소드의 수동 reset은 제외한다.

| 지표 | 새 의미 |
| --- | --- |
| Metrics/timeout_episode_count | 최근N개 완료 에피소드 중 timeout 개수 |
| Metrics/timeout_success_count | 같은 창의 성공 timeout 개수 |
| Metrics/timeout_success_rate | 같은 창의 success 수 / timeout 수. timeout0이면0 |

이전 기록이 창 밖으로 나가면 count가 줄어들 수 있고 count는N을 넘지 않는다. ring은 long tensor[N,2]와 합계2개로 고정 메모리를 사용하며 기본N에서 약160KB다. 새 배치에 들어오는 값과 밀려나는 값만 합계에 반영한다. 카운터는 실행 재시작 시 초기화되며 checkpoint에는 저장하지 않는다. TensorBoard logger의 rollout 평균은 별도로 적용될 수 있다.

성공은 여전히 timeout의 부분집합이다. `Episode_Termination/timeout`과 `success`는 겹치며 서로 배타적인 분류로 변경하지 않았다. XY<3cm·동시 실패 제외·10초 timeout·bootstrap 의미와 보상/학습 동작도 유지한다.

## 3. Reach 수식과 보상 규모

사용자가 요구한 거리값은 현재 타겟의3차원 중심과 EEF 프레임 사이 거리에서10cm를 뺀 뒤0 이상으로 제한한 값이다. 자산 root/COM과 혼동하지 않도록 **scaled local BBOX의 중심을 현재 물체 quaternion으로 회전하고 root world position에 더한 기하 중심**을 사용한다. 불규칙 형상의 부피 중심/질량 중심을 계산하는 것은 아니다.

```math
g_t = \max(\|\mathbf{p}_{\mathrm{eef},t}-\mathbf{p}_{\mathrm{center},t}\|-0.1,0)
```

0에서 발산하는1/g 대신 완화된 역수 함수를 사용한다. softening `distance_scale=0.1m`는 개발 기본값이다. 과거 최소 거리/접촉/목표 도달 gate는 사용하지 않는다.

```math
f(g_t)=\frac{0.1}{0.1+g_t}
```

기존 Reach는 초기 root 기준10cm 바깥 거리를 g0라 하면 에피소드에서 최대30×g0까지 지급했다. 새 보상에 동일 weight30을 단순 적용하면 지속 지급 때문에 총액이 크게 증가하므로, **초기 최대 보상량을 episode_length_s로 나누어 초당 지급률을 정한다.** 초기 g0만 부모 `ReachProgress.reset`과 동일하게 root/EEF에서 계산하여 기존 최대량과 맞추고, 현재 근접도는 요청된 BBOX 중심으로 평가한다.

```math
R_{\mathrm{reach},t}=30\frac{g_0}{T}\frac{0.1}{0.1+g_t}\Delta t
```

T=10초, policy dt=0.02초. term weight는30을 유지하고 함수는 g0/T×f를 반환한다. RewardManager의 dt를 그대로 적용하며 /step_dt로 상쇄하지 않는다. episode 내 충분한 접근을 했던 과거 이력은 현재 지급량을 바꾸지 않는다. 물체가 멀어지면 현재 보상이 감소하고 EEF가 따라가면 회복한다. 회전/이동한 물체 중심을 매step 사용한다.

| 현재 중심–EEF 거리 | 근접도 f | g0=0.25m일 때 step 보상 | 해당 거리를10초 유지한 총보상 |
| --- | --- | --- | --- |
| 10cm 이하 | 1 | 0.015 | 7.5 |
| 20cm | 0.5 | 0.0075 | 3.75 |
| 30cm | 1/3 | 0.005 | 2.5 |

동일 예시에서 기존 Reach를 끝까지 달성한 총보상도7.5다. 새10초 최대 총보상≤기존 최대 총보상으로 맞췄지만 **학습 중 평균·분산·시간적 지급 패턴이 같음을 보장하지는 않는다.** 조기 실패/늦은 접근에서는 지급액이 작아진다. 초기 root 기준10cm 안에서 시작하면 기존 예산도0이므로 새 항도0이다. 현재 Fast 초기 배치는 선반 앞 바깥에서 시작하여 이 경우를 기본으로 사용하지 않는다. 향후 접촉 시작 환경으로 바꾸면 예산 산정도 재검토해야 한다.
