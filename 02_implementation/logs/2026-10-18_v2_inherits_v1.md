## 요청과 변경

사용자는 v2가 v0 대신 v1을 상속해 v1의 비용 상한·손목 높이·스폰 관련 변경을 받고, 기존 성공/유지 보상을 추가한 환경이 되도록 요청했다. OSC v2는 수정된 v2를 상속하고 Arm controller만 교체한다.

변경된 환경 Cfg 체인:

```text
InspireDexTactileSweepOmniRenewalEnvCfg       (v0)
  → InspireDexTactileSweepOmniRenewalV1EnvCfg
    → InspireDexTactileSweepOmniRenewalV2EnvCfg
      → InspireDexTactileSweepOmniRenewalV2OSCEnvCfg
```

[v2 Cfg](../../../../src/inspire_sweep_baseline/inspire_sweep_baseline/envs/sweep_omni_renewal_envs.py)의 import와 부모 클래스를 v1로 바꿨다. v2는 여전히 자신의 양의 보상 Cfg와 성공 종료 비활성 Cfg를 선언하지만, 상속된 v1 `__post_init__`가 이 실제 인스턴스의 비용 함수·종료 params·event params를 후처리하므로 v1 변경이 누락되지 않는다. v2 PPO runner도 v1 runner를 상속하도록 연결했으며 수치 설정은 같고 experiment 이름만 v2로 덮어쓴다.

OSC Cfg는 기존대로 v2를 직접 상속한다. 중복 설정을 추가하지 않고 부모 변경을 받으며, 기존 OSC stiffness 100·5 mm/0.025 rad 명령 상한·Arm implicit PD 해제만 추가한다. task ID와 실행 명령은 그대로다.

## 최종 적용값

| 항목 | v2와 OSC v2의 현행 값 |
| --- | --- |
| 물체 지수 속도 비용 | `exponential_pushing_speed_cost_limit`, `max_cost=100.0`, weight −1.0 |
| Arm 지수 속도 비용 | `exponential_joint_speed_cost_limit`, `max_cost=100.0`, weight −1.0 |
| 손목 종료 높이 | 선반면 상대 `wrist_clearance=0.03` m |
| 목표 방향 | 선반 로컬 ±X 각각 ±15° 제외, 남은 300°에서 균등 샘플링 |
| 물체 스폰 위치 | 기존 반경 0.02 m 원판 분포 유지 |
| 목표 거리 | 기존 최대 0.15 m 및 가장자리 단축 유지 |
| 최초 달성 보상 | 기존 안정 조건 0.5초 연속 만족 시 episode당 +100 한 번 |
| 유지 보상 | 기존 최대 +20/초, 성공 후에도 계속 지급 |
| 성공 종료 | 비활성, 기존 실패 또는 10초 timeout에서 종료 |

사용자의 ‘스폰 위치 변경점’은 실제 v1 코드의 `excluded_x_half_angle` 설정을 그대로 상속하는 것으로 적용했다. v1은 물체의 위치 분포 자체를 바꾸지 않으며 목표 방향을 제한한다. 이 차이를 사용자에게 안내했다. 새로운 위치 분포는 임의로 추가하지 않았다.

관측 57D·행동 8D, Hand·촉각·F/T·물성·성공 자격·보너스 latch·reset·나머지 기존 비용은 유지한다. 네 필수 운동 비용의 함수·raw 제곱합·그룹·계수 및 앞서 추가한 출력 상한 100도 유지한다. v1 지수 속도 비용 두 항의 상한과 공통 제곱합 비용의 상한은 별개다.

**321 passed, 17 subtests passed in 17.25s**. v2 최종 설정 전체를 v1과 비교해 두 양의 보상 및 비활성 success 필드 외 차이가 없음을 검증했다. v1의 두 제한 비용 callable·상한 100·손목 높이 0.03·목표 방향 제외가 실제 적용되는지 별도로 확인했다. 부모 인스턴스 오염 방지와 runner의 v1 상속도 확인했다.
