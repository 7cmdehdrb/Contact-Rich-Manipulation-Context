# Single Contact 보상 수정안 정정과 방향 함수 그래프

## 요청·범위

사용자는 직전 제안의 고정 접근 영역·최소 오차 기록 Reaching을 거절했다. 물체가 움직인 뒤 따라갈 동기를 위해 현재 손–물체 거리의 10cm 초과분 감소를 보상하고 증가를 같은 크기로 벌주는 안을 요청했다. 팔 관절 속도 종료 페널티는 일회 -3.0, 손끝/주먹 강제는 추가하지 않는다. 거리별 방향 가중·근거리 정밀도 결합(직전 제안 5번)은 보류한다. 방향 함수는 그래프로 검토하는 단계다.

이번 작업은 실제 코드 확인·제안 정리·그래프 산출만 수행했다. 환경/보상/PPO/관측 변경이나 학습을 수행하지 않았다. [교수님 지침](../../../../docs/instruction.md)의 목적·함수 특성 검토 단계이며 수정 후 성능 검증이 아니다.

## Reaching 수정 방향

현재 코드의 EEF–실시간 타겟 bounds 중심 3D 거리 정의를 기준으로 제안한다.

```math
e_t=\max(\|\mathbf{p}_{eef,t}-\mathbf{p}_{target,t}\|-0.10,0),\qquad
r_{reach,t}=w_R(e_{t-1}-e_t)
```

기존 상태 기반 양의 지속 지급을 대칭 거리 변화 신호로 교체하는 안이다. 최소 기록은 사용하지 않으며 10cm 내부에서는 0이다. 물체가 멀어지면 비용, 따라가면 보상이 발생한다. 같은 오차로 돌아온 왕복의 할인 전 합은 0이나, 할인된 return의 왕복 이득까지 제거하는 보장은 아니다. 동일 속도로 따라가 거리가 일정하면 이 항은 0이며 실제 밀기의 양의 이득은 Sweep이 담당한다. 타겟이 손에서 멀어지는 정상적인 밀기와 Reaching 비용의 상충을 timeline으로 검사해야 한다. 새 함수의 단위는 거리 변화이므로 기존 weight 0.8의 효과를 그대로 기대하지 않는다. 계수는 미확정이다.

## 좌우 범위 확인

[실제 구역·선호 코드](../../../../src/inspire_sweep_baseline/inspire_sweep_baseline/mdp/reward_functions/sweep_contact_preference.py)의 독립 함수 `sweep_region`을 AST로 추출해 CPU에서 13개 방향으로 실행했다. 구역 배열이 예상과 일치했다. 각도는 로봇이 선반을 바라보는 기준의 앞쪽(-shelf X)을 0도로 하고 오른쪽(+shelf Y)이 양수다.

| 구역 | 각도 범위 | 선호 면 |
| --- | --- | --- |
| 1 전방 | -30도 이상 +30도 이하 | 손등 |
| 2 오른쪽 | +30도 초과 +150도 미만 | 손등 |
| 3 후방 | 절댓값 150도 이상 | 손바닥 |
| 4 왼쪽 | -150도 초과 -30도 미만 | 손바닥 |

좌우 각각 120도, 정측면은 각각 +90도/-90도다. 정확한 경계 소유는 코드 조건으로 확인했으며 실행 probe는 경계의 양쪽을 검사했다. preferred 1.5/other 0.7/unclassified 1.0과 초기 episode 의도 방향으로 구역을 고정하는 코드도 확인했다. 이는 보상 설정 확인이지 실제 모든 rollout의 면 사용 보장이 아니다. 방향별 Reaching 접근 영역은 현 코드에 없다.

## 종료 페널티·방향 함수

실제 `arm_joint_velocity` 종료 flag에 일회 -3.0을 부과하는 제안이다. 기존 종료 조건은 팔 관절 하나라도 절댓값 1rad/s 초과다. 이 사건 비용만으로 0.8rad/s를 직접 경계로 학습시키지는 않는다. RewardManager dt 적용과 자동 reset 전 마지막 step 지급을 구현 시 확인해야 한다.

```math
A(\theta)=2\exp[-\ln(2)(\theta/\theta_0)^p]-1
```

예시 theta0=30도, p=4. 0/10/15/20/30/45/60도에서 각각 1/0.983/0.915/0.744/0/-0.940/약 -1이다. theta0=20/45도 대조와 p=2/8 대조 수치도 CSV에 보존했다. 각도는 수평 힘과 현재 목표 방향 사이를 제안하며, 그래프의 회색 cosine은 수직 힘이 0일 때의 참조다. 현재 코드의 3D 힘 분모와 일반적으로 동일하지 않다.

음수 방향 계수는 양의 거리 진행량에 적용하는 후보이며, 기존 후퇴 비용과 곱해 부호를 뒤집으면 안 된다. 진행량이 0인 접촉에는 이 곱셈만으로 방향 비용이 발생하지 않는다. 또한 기존 면 계수 1.5를 음수 보상에 그대로 곱하면 선호 면의 비용이 커지므로 음수 부분의 면 계수 처리는 별도 명세가 필요하다. 이번에는 결합식이나 기존 후퇴 계수를 변경하지 않았다.

## 검증·미검증

곡선 유한성·[-1,1] 범위·단조 감소·0도 값 1·30도 값 0을 검사했다. 구역 함수 13개 방향 probe 통과, PNG 시각 확인으로 제목·축·범례 표시를 확인했다. 변경 문서 2개의 수식 검사 통과, 내부 링크 175개·외부 링크 7개 검사 오류 0, 문서 저장소 diff 검사 통과다. 새로운 보상 계수, rollout 변화, 성공률, 물체 추종 개선, 관절 속도 종료 감소는 미검증이다.
