# 실제 가시 메쉬 대표점과 자유 검토 카메라

## 요청·원인·의도

사용자는 실제 환경에서 YOLO/SAM 등의 가시 segmentation 영역에서 2D 대표점을 선택한 뒤 RGB-D로 3D 복구할 계획이며, 시뮬레이션에서는 더 효율적인 대응 방법을 원한다고 명시했다. 기존 벤치의 병 대표점이 가림 경계에 붙는 현상을 제시했고, 이를 반영한 코드 수정과 자유로운 사선 검토 뷰를 요청했다. 검증 뒤 시뮬레이터를 남겨두지 말라는 이전 지시도 유지했다.

이전 `src/surface_point` 기본은 원본 OBB를 실제 형상으로 간주했다. 병 위쪽이 앞 상자보다 약 9.154 mm 높아, 직육면체 근사에서 병목의 빈 공간까지 상단 노출로 계산됐다. 가시 bbox 중심이 가려져 가장 가까운 경계로 보정되면서 몸통 노출 구간 중앙보다 약 20.619 mm 왼쪽에 점이 놓였다. 저장된 seed 0의 네 번째 배치를 CPU에서 재생하고 두 물체로 줄여 재현했다. 단순히 가림 높이를 무한으로 바꾸면 현실의 유한한 가시 mask와 달라지므로, 이번 요청에 따라 실제 시각 메쉬를 사용하도록 바꿨다.

## 변경 전후 계약

| 항목 | 이전 | 현재 |
| --- | --- | --- |
| 가시 형상 | 원본 전체 OBB 직육면체 | 실제 USD 시각 메쉬, native primitive의 명시적 삼각형 근사 |
| 가시성 계산 | YZ 해석적 박스 셀 | 고정 정면 GPU 병렬 광선의 첫 메쉬 교점 |
| 대표 위치 | 가시 bbox 중앙, 가려지면 경계 보정 | 기본 가시 mask 면적 중심에 가장 가까운 유효 픽셀; bbox 중앙 방식은 옵션 |
| 관측 깊이 | 박스 앞면 | 선택 광선과 실제 시각 메쉬의 교점 |
| 검토 카메라 | 직교 시점 프리셋 | 기본 사선 원근, 자유 마우스 조작 및 방위각/고도각/거리 입력 |
| 관측 설명 | 박스 비교 패널 | 가시 mask·영역 bbox·선택 픽셀 별도 창 추가 |

새 경로는 RGB를 렌더링하거나 segmentation 모델을 실행하지 않는다. 메쉬 소유자 배열은 이상적인 instance segmentation을 기하적으로 대체한다. 광선 간격은 기본 1 mm이며 픽셀에 대응하는 유한 해상도 샘플링이다. 해상도 없는 정확한 연속 가시성이라고 표현하지 않는다.

같은 소유자의 4방향 연결 영역은 각각 독립 ID를 갖는다. 서로 분리된 가시 조각을 원본 ID로 합치지 않는다. 기존 2 cm·20% 횡폭 필터를 유지하며 기준 폭은 실제 메쉬의 Y 투영 폭이다. 다른 물체와 선반은 가리지만 선반은 출력 관측을 갖지 않는다.

기본 대표 규칙은 가시 영역의 모든 픽셀에 동일한 가중치를 주어 2D 좌표 평균을 구한 뒤 해당 영역 내부의 가장 가까운 픽셀을 선택한다. 얇은 병목의 영향은 실제 가시 면적만큼이다. `--representative bbox-center`는 가시 영역 bbox 중앙에 가장 가까운 내부 픽셀을 선택한다. 두 규칙은 실물 mask에도 동일하게 적용할 수 있다. 이 대표 규칙 선택은 사용자가 요청한 2D 대표점의 구현 선택이며, 기존 bbox 방식과 동일한 출력이라고 주장하지 않는다.

원본 OBB는 새 mask/대표점 계산에 사용하지 않으며 기존 방식과의 비교에만 사용한다. 기존 `observed_obb`의 높이 무한 가림과 출력은 그대로다. OBB 중심 거리와 같은 YZ의 앞면 깊이 차이를 표시하고, 대응이 없으면 unmatched로 남긴다. source index와 메쉬 교점 소유자는 벤치 내부 정보로 최종 관측 ID/점과 구분한다.

## 구현·효율

`usd_mesh.py`는 USD instance proxy, 하위 geometry 변환과 루트의 크기·회전·이동을 반영한다. 로컬 시각 메쉬를 캐시하고, 숨겨진 collision 전용 메쉬와 guide는 제외한다. 활성 물체와 선반의 시각 메쉬만 사용하므로 관측 마커가 관측을 가리지 않는다. 메쉬 포인트/face 연결은 캐시하고 배치 시 변환한다.

`mesh.py`는 Warp Mesh BVH를 이용한다. 활성 topology/소유자가 같으면 points 갱신 후 refit, 다르면 다시 BVH를 구성한다. 고정 +X → −X 직교 광선의 첫 hit에서 owner와 월드 XYZ를 얻고, CPU에서 연결 영역·대표점을 계산한다. 기본 CUDA 사용 가능 시 GPU, 아니면 CPU이며 `--ray-device`로 지정할 수 있다. 최대 200만 광선 제한 초과는 간격을 키우라는 오류를 반환한다.

현재 native Cylinder/Cone은 128분할, Cube는 정확한 면, USD Mesh는 triangle/볼록 polygon의 fan 분할을 사용한다. 미지원 primitive를 OBB로 조용히 대체하지 않는다. material alpha/투명도, subdivision/displacement로 바뀐 최종 렌더 표면, 원근 관측, RGB-D 잡음·실제 segmentation 오류는 구현하지 않았다. 자유 원근 카메라는 검토용이다.

## 카메라 계약

별도 `SurfaceInspectionCamera`를 활성 뷰포트에 설정한다. 기본 사선 원근이며 정면 직교/사선 원근 버튼과 방위각·고도각·거리 입력이 있다. 뷰포트 Alt+왼쪽 드래그 회전, Alt+가운데 드래그 이동, 스크롤 확대/축소를 안내한다. 매 프레임 또는 재관측·재배치에서 검토 카메라를 강제로 재설정하지 않는다.

고정 정면 관측과 검토 시점은 독립적이다. 검토 시점을 바꿔도 새로 카메라 방향으로 관측을 만들지 않는다. 마스크 창은 항상 고정 정면 결과다. 모든 표면점·OBB 마커는 충돌/강체 스키마가 없다.

## 검증 결과

- 병 몸통+좁은 병목+앞 상자로 구성한 실제 삼각형 입력 회귀 테스트에서 점이 노출 몸통 중앙에 놓이는지 검사했다. 다른 물체가 앞에 있는 픽셀을 반환하지 않는지, 메쉬 첫 교점과 결과가 같은지 검사했다.
- 대표 규칙 두 종류, 가림 전용 환경 geometry, USD 중첩/루트 변환·스케일과 숨겨진 충돌 메쉬 제외, 캐시 후 이동을 검사했다. 기존 observed_obb 회귀 포함 총 33개 테스트 통과(0.48초), 신규/변경 10개 Python 소스 mypy 통과.
- RTX 3090 GUI에서 Simple seed 0의 6개 배치를 재관측하고, 문제가 있던 네 번째 배치부터 추가 6개 배치를 검증했다. 정면/사선 프리셋과 방위각 42°·고도 31°·거리 1.25 m 조절 후 재관측해도 카메라 변환이 유지되고 관측 값이 동일함을 assert했다. 표시 토글과 비충돌도 검사했다.
- 첫 GPU 실행: 초기 Warp 컴파일 포함 관측 계산 352.44 ms. 이후 11회 기하 계산 18.12~30.45 ms, 중앙값 24.78 ms. 그중 광선 질의 0.86~3.16 ms, 중앙값 1.20 ms. 77,854~140,292개 광선을 사용했다. 최초 USD 추출과 새로운 자산 캐시 구성·뷰어/앱 시작 시간은 별도다. 전체 Reset 시간으로 이 수치를 표현하지 않는다.
- 같은 문제 배치에서 병의 이전 박스 점 Y는 −0.177097 m, 새 실제 메쉬 면적 중심 기반 점 Y는 −0.167500 m로 약 9.597 mm 이동했다. 새 점 XYZ는 약 (−0.753126, −0.167500, 1.114500) m다. 화면상 오른쪽 노출 몸통 안에 있으며 실제 가시 병목도 면적에 따라 기여한다.
- 저장한 실제 메쉬를 Isaac Sim 없이 CPU로 재생해 1 mm와 0.5 mm 격자를 비교했다. 병 점 차이 약 0.368 mm, 해당 장면 6개 점의 최대 차이 약 0.850 mm. 이는 이 장면의 수렴 비교이며 일반 정확도 보장은 아니다.
- 실제 뷰포트 정면/사선 캡처와 기하 mask를 직접 확인했다. 첫 정면 캡처가 렌더 준비 전 검게 저장되는 문제를 발견해 warmup·비어 있지 않은 캡처 확인 후 재실행했다. 최종 캡처는 정상이다.
- Isaac Sim 내장 Warp 1.8.2와 외부 CPU Warp 1.15의 배열 타입 annotation 차이 및 카메라 API 인자명을 실행에서 확인해 수정했다. 두 경로 모두 최종 검사에 포함했다.

## 실행·산출물

Workspace 루트에서 실행한다. 시뮬레이터는 검증용 실행 후 종료하며, 사용자가 아래 명령으로 필요할 때 시작한다.

```bash
OPENBLAS_NUM_THREADS=1 /home/min/miniconda3/envs/env_isaaclab/bin/python src/surface_point/scripts/show.py --scene simple --seed 0

# 문제의 병 가림 배치
OPENBLAS_NUM_THREADS=1 /home/min/miniconda3/envs/env_isaaclab/bin/python src/surface_point/scripts/show.py --scene simple --seed 0 --placement 3

# bbox 중앙 규칙 비교
OPENBLAS_NUM_THREADS=1 /home/min/miniconda3/envs/env_isaaclab/bin/python src/surface_point/scripts/show.py --scene simple --placement 3 --representative bbox-center

# 자동 검증, 메쉬/마스크 저장 및 종료
python src/surface_point/scripts/show.py --scene simple --validate
WARP_CACHE_PATH=/tmp/surface_point_warp python src/surface_point/scripts/evaluate_mesh.py
```

[패키지 README](../../../../src/surface_point/README.md)에 API·옵션·가정·카메라 조작을 기록했다. 새 결과는 `outputs/surface_point_mesh/`의 mask PNG·메쉬 NPZ·GPU JSON이며 `review/simple_front.png`, `review/simple_oblique.png`는 문제 배치의 실제 검토 화면이다. `replay/comparison.json`은 해상도·대표 규칙 비교다. 이전 `outputs/surface_point/` 결과는 박스 근사 기록으로 보존했다.

## 최종 대조·미검증

수정 범위는 독립 `surface_point`의 새 메쉬 관측/변환/마스크 모듈, 뷰어, 회귀 테스트, CPU 메쉬 재생 스크립트, 의존성·README 및 문서다. 기존 박스 알고리즘·관측 OBB·Gaussian·baseline·학습 로그와 사용자 변경은 보존했다. 별도 모델 학습, 최종 환경 삽입, policy/control, 실제 센서 보정은 수행하지 않았다. 커밋하지 않는다.

## 사용자 확인 및 후속 작업 기준

2026-11-18 사용자가 “괜찮네. 방금 내역을 잘 기록해놔.”라고 응답했다. 현재 구현 결과를 수용한 것으로 기록한다. 이는 실센서 정확도나 최종 환경 통합이 검증되었다는 의미는 아니다.

후속 작업은 다음 상태를 기준으로 이어간다.

- 관측 목표는 전체 물체 중심 추정이 아니라 **실제로 보이는 표면을 대표하는 3차원 좌표**다. 현실의 segmentation → 2D 대표점 → 해당 픽셀의 depth 복원에 대응하도록, 시뮬레이션에서는 실제 시각 메쉬 첫 교점으로 가시 mask와 깊이를 함께 얻는다.
- 기본값은 1 mm 정면 직교 광선과 `mask-centroid`다. 2D 면적 중심에 가장 가까운 동일 연결 영역 내부 픽셀을 고르고 그 광선의 실제 표면 교점을 반환한다. `bbox-center`는 비교 옵션이다. OBB 앞면이나 전체 물체 중심으로 대체하지 않는다.
- 기존 3D 관측 OBB는 비교 표시로 유지한다. 새 표면 관측의 가림은 실제 유한 높이 메쉬에 따르며, 기존 OBB의 높이 무한 가림 규칙을 새 경로에 적용하지 않는다.
- 자유 검토 카메라와 고정 정면 관측을 분리한다. 사선 검토·재관측·재배치가 고정 관측 방향을 바꾸거나 사용자가 조정한 검토 카메라를 덮어쓰지 않는다.
- 현재는 독립 테스트 벤치다. 최종 환경 삽입, 정책 관측 구성, Gaussian 연결은 이번 작업에 포함되지 않았다. 향후 통합 시 이 기록의 좌표·대표점·가림 계약과 미검증 범위를 함께 확인한다.
- 검증용 시뮬레이터는 확인 후 종료한다. 사용자가 직접 실행할 수 있도록 위 명령을 제공하며, 커밋 없이 변경을 유지한다.

이번 기록 요청에서는 기존 개발 로그에 사용자 확인과 후속 기준을 추가하고 현재 인계·로그 목록에서 연결했다. 코드·관측 동작은 변경하지 않았으며 시뮬레이터도 다시 실행하지 않았다. 앞선 실행 검증과 이번 문서 검증을 구분한다.
