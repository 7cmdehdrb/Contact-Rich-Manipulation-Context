# Sweep-v0 상세 문서와 계통 문서 정리

## 요청과 근거

사용자는 `Inspire-Sweep-v0`의 환경 설명1건과 이 계통의 설명1건을 요청했다. 기존 환경은 Pull·Push 외에서 상당한 성공을 보였지만 항상 손등으로 밀려는 경향이 있었고, 방향별 손바닥·손등 선호를 유도하려는 목적을 설명했다. 현재 `.180`은 Sweep-v0, `.250`은 Contact-v0 학습 중이라고 보고했다.

대화의 직전 구현과 등록을 기준으로 Contact-v0를 `Inspire-Sweep-Single-Contact-v0`의 약칭으로 명시했다. 별도 task나 학습 실행을 추가하지 않았다. 기존 성공의 정확한 이전 task/run·정량 성공률은 미제공으로 두고 새 환경의 검증 결과에 섞지 않았다.

시작 workspace HEAD는 `f3059f3`, 문서 HEAD는 `8dfcb81`이었다. 문서 작업트리는 깨끗했고 상위 저장소에는 문서 submodule ref 차이만 있었다. 이 ref와 사용자 커밋은 보존한다.

## 문서 변경 전후

| 대상 | 변경 전 | 변경 후 |
| --- | --- | --- |
| `environments/SWEEP_V0.md` | 접촉면 선호·고정 비용·F/T 정규화 중심의 구현 계약 | 기존 파일을 기준으로 보완하여 과업·장면/reset·관측66+64D·Actor/encoder/Critic·제어·15개 보상·누적 접촉·종료·성공률·PPO·실행을 독립적으로 설명 |
| `environments/SWEEP_FAMILY.md` | 없음 | 손등 편향이라는 개발 배경, 기능 기준/상속 구분, 두 환경의 접촉 계수 비교, 공통 조건, 현재 서버 배치, 결과 평가 관점을 정리 |
| 인계·활성 환경 안내 | 개발 당시 학습 미실행 및 이전 서버 배치가 선두 | 최신 사용자 보고와 새 계통 문서 링크를 선두에 추가 |
| 기존 Sweep Only 계열 안내 | 이전 서버 배치를 현재 현황으로 읽을 여지 | 과거 배치임을 알리고 현재 현황의 기준을 새 Sweep 계통으로 연결 |

기존 상세 문서를 복제하여 두 개의 Sweep-v0 기준을 만들지 않았다. Single Contact의 기존 anchor와 설명을 보존하여 README·기존 개발 로그 링크가 깨지지 않게 했다. 계통 문서는 변화의 이유와 비교에, 상세 문서는 현재 실제 구성에 중점을 두었다.

## 코드 대조와 기록 원칙

EnvCfg·runtime·PPO·Scene·Action/Observation/Reward/Termination/Event Cfg, 실제 접촉 state·접촉면 보상·reset·F/T 비용을 읽었다. 문서에는 다음을 구분했다.

- Sweep-v0에는 누적 카운트0–20이 남는다. Single Contact에는 `contact_count`가 없고 boolean을 보상 계수1/0으로 변환한다.
- 이력의2-of-3 조건과 현재 접촉·힘·정렬·높이 조건을 구분한다.
- 구역은60°/120°/60°/120°, Deadzone0°, 구역1/2 손등·3/4 손바닥 선호1.5/반대0.7이다.
- 양면 접촉의 혼합과 미분류 중립1을 명시한다. 선호는 양의 Sweep에만 적용된다.
- F/T 관측만 clip 후 정규화한다. 페널티는 물리 단위를 유지한다.
- 실제 success 비교는 timeout의 거리 `<0.03`임을 코드 그대로 적었다. 정책 입력과 현재 물체 GT 보상·평가를 구분했다.
- 사용자 기존 관찰, 개발 smoke 검사, 현재 사용자 학습 진행, 아직 미측정인 선호도 개선을 분리했다. 평가 관점은 제안이며 새 telemetry 구현으로 설명하지 않았다.

소스·설정·학습 프로세스·원격 서버·로그·산출물은 변경하지 않았다. 이번 작업은 문서만 수정하므로 GPU·학습·촬영·기존 테스트를 재실행하지 않는다. 문체는 제공된 연구 설명과 관련 개인 연구 자료의 서술 구조를 참고하되, 외부 자료의 사실·실험 결과는 가져오지 않았다.
