# Relative-v2_6: one fixed straight-left goal

## Request and baseline

2026-11-08: directly inherit v2_1 and change only the goal distribution, to investigate whether left pushing is structurally difficult or training is biased toward right pushing. User selected **9cm** from the initial object position. Left means shelf-local -Y, equivalent to world -Y for this unrotated shelf.

Workspace baseline: `894cfc9`, with existing uncommitted v2_5 work and IsaacLab state preserved. Training logs and checkpoints were not changed.

## Final contract

- Gym ID: `Inspire-Wrench-Refactor-Relative-v2_6`.
- EnvCfg: `WrenchRefactorRelativeV2_6EnvCfg(WrenchRefactorRelativeV2_1EnvCfg)`.
- Runtime: unchanged `WrenchRefactorEnv`.
- Only EnvCfg difference: `events.object_spawn.params.fixed_goal_offset = (0.0, -0.09)`.
- Goal XY equals initial target XY plus that offset; goal Z handling remains the parent's. This is one fixed relative point, not an absolute world point shared across randomized initial positions.
- Initial target spawn disk, target/obstacle physics and obstacle count distribution remain unchanged. Obstacles are placed relative to the new fixed route using the existing layout algorithm.
- Existing direction curriculum remains configured, but fixed offset takes precedence at every stage. It cannot broaden the goal distribution.
- All v2_1 rewards are retained, including cosine distance weight5, contact maintenance, inverse-distance cost, Reaching at the object link origin with radius10cm and weight30, Hold and entry/success bonuses. Observations, actions, termination and other curriculum settings remain unchanged.
- Runner: `WrenchRefactorRelativeV2_6PPORunnerCfg(WrenchRefactorRelativeV2_1PPORunnerCfg)`; only experiment_name changes to `inspire_wrench_refactor_relative_v2_6`.

The existing sampler accepts an optional fixed_goal_offset, passed through reset_scene to fixed_pool_layout before obstacle placement. Default None preserves the original sampling code path. Fixed mode retains the original four random draws and target spawn calculation, validates finite XY offset and distance limits, and checks shelf safety. It does not move the goal after obstacle generation.

## Final comparison and validation

- Full parent/child EnvCfg dictionaries differ only in the one event parameter. Existing and freshly instantiated v2_1 parent dictionaries remain unchanged.
- CPU **85 passed in 9.65s**. Tests cover all deadzones 0/5/10/15/20/25/30 degrees, 4096 fixed-goal samples per stage, exact X preservation, -9cm Y, unchanged target samples and RNG state, invalid offsets, all obstacle counts, geometric separation, parking, and partial reset propagation to sweep_dir.
