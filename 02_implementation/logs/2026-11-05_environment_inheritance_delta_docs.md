# 2026-11-05 환경별 상속 변경점 중심 문서 재구성

## 요청·의도

사용자는 [환경 문서](../../../../docs/environments/README.md)의 공통 구성별 표 묶음으로는 계열 안에서 무엇이 바뀌었는지 이해하기 어렵다고 지적했다. 베이스는 전체 표를 유지하되 파생은 환경별로 직접 부모 대비 변경점을 서술하도록 요청했다.

## 변경 전후

- 전: 베이스 요약과 파생 요약표 다음에 여러 버전이 공유하는 전체 Manager 표를 관측·보상·터미네이션·커리큘럼별로 모았다. 독자가 각 환경에 해당하는 표를 찾아 직접 비교해야 했다.
- 후: 13개 계열의 베이스는 관측·보상·터미네이션·커리큘럼 설명 바로 아래 전체 표를 둔다. 나머지 62개 환경은 개별 절로 나누고 직접 부모 링크, 환경 설정 코드, 그 환경에서 바뀐 점, 변경 항목표를 배치했다.
- 변경표는 항목명·추가/삭제/수정·부모 값·이 환경 값·의미로 구성한다. 함수 교체는 전후 의미와 구현 링크를 함께 적고, 계수·차원·문턱·커리큘럼 일정의 전후 값을 표시한다. 수정하지 않은 Manager 종류는 부모와 동일하다고 표시한다.
- 장면·제어·reset·runtime/PPO 변경은 해당 환경의 설명에 보존했다. 기존의 여러 버전 공통 설명은 변경을 도입한 환경 절로 옮겼다. OSC와 ObjectRandom은 같은 문서의 베이스가 아니라 실제 Holding/OSC 직접 부모와 비교한다.
- 각 계열의 환경 바로가기, 직접 부모 링크 및 통합 등록 ID 색인은 해당 환경의 개별 절로 연결한다. 기존 여러 버전을 묶은 표와 구성 번호를 제거했다.

## 근거·최종 대조

현재 EnvCfg의 직접 부모를 AST로 확인하고, Manager 설정 상속과 EnvCfg 후처리를 반영한 유효 설정으로 변경 항목을 계산했다. 이전 작업에서 함수 구현과 대조한 항목 의미·전체 표를 보존해 재배치했다. Clutter 및 Holding OSC의 실제 EnvCfg도 다시 읽어 계열 내부 직렬 상속과 다른 계열에서의 분기를 구분했다.

완성된 Markdown을 다시 읽어 75개 환경의 300개 Manager 종류 조합을 검사했다. 베이스 13개의 전체 항목 468행과 파생 62개의 변경 항목 280행을 확인했다. 모든 직접 부모 표기가 실제 클래스 상속과 일치하며, 부모의 항목 집합에 추가·삭제를 적용하면 각 자식의 전체 항목 집합이 복원된다. 모든 설정 변경 항목이 변경표에 포함되어 있다. 차원·목표 반경·높이 조건·GT 라우팅처럼 Manager 항목 밖의 조건도 반영했다.

## 영향·검증

환경 문서 14개와 이 기록만 수정했다. 활성 패키지 Python 소스 217개의 SHA-256 대조 결과 변경 없음. 기존 미추적 개발 로그는 보존했다. 학습 로그·백업·체크포인트는 변경하지 않았다. 보조 작성·검사 파일은 `/tmp`에 두었다.

Markdown 수식 검사와 외부 workspace 경로 포함 문서 링크 검사 오류 0건. 개별 환경·직접 부모의 HTML anchor를 별도로 대조했다. 양 저장소 공백 검사와 문서 저장소 전체 링크 검사도 수행했다. 미검증 범위는 GUI Markdown 렌더링, Isaac 초기화·rollout·GPU 학습이며 이번 작업은 문서 구조 변경이다.
