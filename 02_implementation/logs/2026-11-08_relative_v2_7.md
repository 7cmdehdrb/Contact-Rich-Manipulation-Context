# Relative-v2_7: 목표 방향에 따른 IK 초기 Arm 자세

## 요청과 기준

사용자가 `v6_7`을 **v2_7, v2_1 직접 상속**으로 확정했다. 초기 자세는 좌/우 두 분기로 나눈다. 정확한 밀기·당기기처럼 목표와 물체의 좌우 좌표가 같으면 왼쪽 밀기로 취급한다. 목표 반대편에서 시작하도록 EEF 위치를 정하고 IK로 Arm 관절각을 계산한다. 기존 초기 손 방향을 유지하고 translation에만 랜덤화를 적용한다.

Workspace 기준 `96f95f5`. 작업 시작 시 기존 IsaacLab 작업트리 표시를 보존했다. 학습 로그·체크포인트를 변경하지 않았다.

현재 선반은 회전되지 않았으므로 local −Y는 world −Y다. 좌우 분기는 이전 에피소드 command를 읽지 않고, 방금 배치한 물체와 새 `sweep_dir`를 사용한다. 목표 분포 자체는 v2_1 그대로이며 v2_6의 왼쪽 고정 목표를 상속하지 않는다.

보상 전체(Contact·cosine Distance·inverse-distance·Reaching·Hold·최초 진입·성공), Termination, Curriculum, Scene 물성, Command, Observation, Action 및 PPO 수치를 보존했다. Reaching은 물체 link 원점/10cm/weight30 그대로다. v2_3의 반대편 Reaching Point를 추가하지 않았다. 관측 정의는 같지만, 초기 로봇 자세 변경에 따른 상대 좌표 값은 자연히 달라진다.

## IK와 reset 처리

새 공통 모듈 `mdp/common/wrench_refactor_ik.py`는 실제 spawn된 USD의 joint-local position/rotation으로 base_link→axia80_link 체인을 구성한다. scene의 실제 EEF offset을 포함하여 FK와 geometric Jacobian을 계산한다. 임의 DH 길이나 과거 자산의 링크 치수를 사용하지 않는다.

기존 default Arm 관절각을 seed로 하는 batched damped least-squares IK를 수행한다. 실제 관절 한계 내에서 최대80회, 한 iteration당 최대 관절 변화0.15rad, damping0.02다. 위치 오차0.5mm 및 회전 오차0.003rad 미만을 확인한 해만 PhysX에 기록한다. 수렴 실패 시 잘못된 방향의 default 자세로 조용히 대체하지 않고 해당 env ID와 오차를 포함해 실패한다.

IK 중간 자세를 simulator에 쓰거나 physics를 step하지 않는다. 최종 Arm position과 0 velocity, 제어 target을 기록하고 link kinematics를 갱신한 다음 EEF sensor를 무효화한다. 이에 따라 후속 observation/reward/action reset은 새 자세를 본다. Hand 초기 상태는 부모 그대로다. 부분 reset은 지정 env만 변경한다.

초기 위치 RNG는 layout RNG와 분리하여 `seed+1707`로 생성한다. 명시적 reset seed는 첫 초기화 및 재초기화 모두 같은 결과를 만든다. 다른 환경은 신규 event가 없으므로 runtime의 해당 seed 분기에 들어가지 않는다.

## 발견·수정한 문제

1. 첫 FK 검증 probe는 joint write 직후 frame sensor를 먼저 읽어 이전 자세를 비교했다. articulation link pose를 먼저 갱신하면 실제 FK 오차가 약0.00051mm로 줄었다. runtime event에도 manager reset 전에 명시적 kinematic refresh를 넣었다.
2. 최초 전면 여유4–7cm에서는 EEF가 밖에 있어도 손끝이 안으로 뻗어 장애물과 접촉했다. seed55/env1에서 zero action 중 큰 접촉력과 Arm 속도 종료가 재현됐다. 다른 조건은 그대로 두고 전면 여유를10–13cm로 넓혔으며, 동일 seed를 포함한 원래 검사를 다시 통과했다. 선반 전면 밖이라는 조건은 EEF 위치에 대한 것이며, 손끝 길이 때문에 여유를 확보했다.
3. CPU Jacobian 유한차분 검사에서 float32의 0.001rad 차분 오차가 나타났다. 차분 폭0.005rad로 변경하여 roundoff 영향을 줄였고 해석 Jacobian과 일치했다.

## 최종 대조와 검증

- 실제 Isaac Lab EnvCfg 사전 전체 대조: 부모 대비 `events.robot_initial_pose` 추가만 존재. 기존 부모 인스턴스와 새 부모 인스턴스의 사전도 불변이다.
- 실제 PPO 사전 전체 대조: experiment_name만 다르다. Gym 등록으로 새 환경을 생성했다.
- CPU **91 passed in 10.05s**: 기존 Refactor 회귀, 전체 구성 대조, 좌/우·정확한 밀기/당기기 분기, seed 재현성, 위치 랜덤화, Jacobian 유한차분, IK 수렴 및 도달 불가능 판정.
- GPU 4096개 IK batch 전부 수렴. 해당 RTX4070 측정 약0.187초, 최대 내부 위치 잔차0.4996mm. 이는 전체 학습 속도 측정이 아니다.
- GPU 8환경×16회 reset, seed42–57: 왼쪽61개/오른쪽67개. 실제 EEF 오차 최대 **0.4765mm**, 회전 오차 최대 **0.0084도**. 선반 바깥/물체 반대편/zero joint velocity/finite observations 검사 통과.
- 각 reset 후4 control step zero Arm/open Hand로 진행:128 초기 상태 모두 종료 없음. 추가32 step도 선반 실패·Arm 속도·물체 실패 등 모든 종료0.
- Reaching의 초기 최단거리 버퍼가 IK 후 실제 EEF 기준으로 초기화됨을 검사했다. 부분 reset은 다른 환경의 관절·목표·초기점에 영향을 주지 않았다. 첫 reset seed가 cfg.seed와 다른 경우도 재현성 검사 통과.
- 최종 marker: `CONFIG_PARENT_PPO_OK`, `IK_BATCH_4096_OK`, `GPU_RESET_IK_PARTIAL_RESET_FINITE_OK`.

PPO 학습 및 좌우 밀기 성공률 개선은 아직 검증하지 않았다. 위 검사는 초기 자세의 구성·IK·초기 물리 안정성을 확인한 것이며 모든 가능한 배치의 무충돌을 보장하는 검사는 아니다.
