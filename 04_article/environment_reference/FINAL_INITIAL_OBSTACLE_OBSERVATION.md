# Final 환경의 초기 주변 물체 관측

2026-11-01 현재 `Isaac-Inspire-Final-GoalAccuracy-v0_2_2` 구현을 기준으로 한다. 주변 물체 관측은 **에피소드 시작 시 정면에서 관측 가능한 장면 정보를 구성하고, 그 결과를 에피소드 동안 고정하는 방식**이다. 실행 중 물체가 이동해도 이 정보를 갱신하지 않는다. Actor와 Critic은 같은 초기 주변 물체 관측을 사용한다.

| 항목 | 현재 구현 | 수정 예정 |
| --- | --- | --- |
| 관측 용량 | 20슬롯 × 4 = 80D | **16슬롯 × 4 = 64D** |
| 슬롯 구성 | `[present, x, y, z]` | 동일 |
| 실제 장애물 요청 수 | 커리큘럼에 따라 2~9개 | 기존 일정 유지 |
| 갱신 시점 | 해당 환경의 reset | 동일 |

16슬롯 고정은 [수정 예정 사항](../../01_plan/FINAL_YCB_SIZE_RANDOMIZATION_FIX.md)에 기록된 요구이며 아직 코드에 반영되지 않았다. 아래 규칙은 슬롯 용량과 별개로 현재 동작을 설명한다.

## 1. 보이는 물체만 관측하는 이유

이 구성은 **초기 시각 정보는 사용할 수 있지만, 조작 중에는 시각 정보를 새로 받지 않는 과업**을 표현한다. 시뮬레이터가 알고 있는 모든 물체 위치를 초기 입력에 넣으면 정면에서 가려진 물체까지 정책에 알려주게 된다. 가시성 필터는 이 차이를 줄이기 위한 관측 제한이다.

가려진 물체도 실제 장면에 남아 접촉·충돌·보상에 영향을 준다. Actor는 초기 관측만으로 모든 주변 물체를 알 수 없으며, 실행 중에는 촉각·F/T와 로봇 상태를 이용해 행동한다. Critic도 현재 장애물의 전체 상태를 별도로 받지 않는다.

다만 **“보이는 물체만 포함”은 노이즈 적용 전의 기본 원칙**이다. 현재 구현에는 1% 가시성 반전 노이즈가 있으므로, 보이는 물체가 누락되거나 가려진 활성 물체가 보고될 수 있다. 실제 영상 검출기의 성능을 측정해 적용한 값이라는 의미는 아니다.

## 2. 정면 가시성 판정

### 2.1 시선 방향과 물체 근사

물체 위치를 선반 좌표계로 옮긴 뒤, 가시성 계산용 평면 좌표를 다음과 같이 둔다.

```math
c_i=(y_{s,i},-x_{s,i}).
```

이 좌표에서 시선은 **음의 두 번째 축 방향에서 양의 방향으로 진행하는 평행 광선**이다. 선반 정면에서 안쪽을 바라보는 상황을 표현하며, 특정 카메라의 위치·화각·원근 투영을 사용하지 않는다.

각 물체는 scale이 적용된 local bounds를 둘러싸는 원으로 근사한다. local bounds의 각 축 최솟값·최댓값을 사용해 반지름을 계산한다.

```math
h_x=\max(|b_{\min,x}|,|b_{\max,x}|),\qquad
h_y=\max(|b_{\min,y}|,|b_{\max,y}|),\qquad
r_i=\sqrt{h_x^2+h_y^2}.
```

원 중심은 물체 link 원점의 XY 위치다. 비대칭 형상의 bounds 중심을 따로 옮기는 방식이 아니라, 원점에서 bounds 끝까지의 최대 거리를 사용한다. yaw에 따라 원을 회전시키지는 않는다. 실제 mesh의 손잡이·구멍·높이 차이와 같은 세부 형상은 판정에 들어가지 않는다.

타겟과 활성 장애물을 함께 넣어 가림을 계산한다. **타겟도 뒤쪽 장애물을 가릴 수 있지만, 최종 장애물 관측 슬롯에는 타겟을 넣지 않는다.** 비활성·주차 물체는 가리는 물체에서도 제외한다.

### 2.2 보이는 폭을 계산하는 알고리즘

1. 각 원의 가로 투영 구간 `[중심 X − 반지름, 중심 X + 반지름]`을 구한다.
2. 모든 구간의 좌우 끝점을 모아 정렬하고, 이웃한 끝점 사이를 작은 구간으로 나눈다.
3. 각 구간의 중점에서 안쪽으로 광선을 보낸다. 해당 광선과 만나는 원 중 앞면 깊이가 가장 작은 물체를 고른다.
4. 그 물체에 해당 구간의 폭을 더한다. 모든 구간에서 누적한 값이 물체별 가시 폭이다.
5. 가시 폭을 전체 지름으로 나눈 비율이 **0.35 이상**이면 기본적으로 보이는 물체로 판정한다.

```math
\rho_i=\frac{w_i^{\mathrm{visible}}}{2r_i},\qquad
v_i=\mathbf{1}[\rho_i\ge0.35].
```

예를 들어 원 근사의 전체 투영 폭이 100mm라면 가시 폭 35mm는 통과하고, 30mm는 통과하지 못한다. 이는 **투영 폭 비율**이며, 실제 카메라 영상에서 보이는 픽셀 면적이나 물체 표면적 비율은 아니다.

### 2.3 현재 근사의 한계

이 가시성 함수는 서로 겹치지 않는 원형 footprint에서 구간별 깊이 순서를 정확히 계산하도록 작성되어 있다. 그러나 Final은 다양한 물체의 OBB로 배치를 검사하고 가시성에는 외접 원을 사용한다. **OBB 사이에 간격이 있어도 외접 원끼리는 겹칠 수 있다.** 현재 호출은 `check_inputs=False`이므로 원 겹침 검사를 수행하지 않는다.

따라서 Final의 결과는 **정면 가시성의 기하학적 근사**로 해석해야 한다. 외접 원이 겹치는 경우에는 구간 중점 하나로 전체 구간의 가림 순서를 대표하는 가정이 정확하지 않을 수 있다. 높은 물체가 낮은 물체 위로 보이는 경우, 선반·로봇에 의한 가림, 원근 효과도 이 함수에서 계산하지 않는다. 배치 검사에 쓰는 OBB와 가시성 원 근사를 구분해야 한다.

## 3. 슬롯별 마스크와 좌표

슬롯 하나는 다음과 같다. $B$는 로봇 root 좌표계다.

```math
o_j=[m_j,\widetilde x_j^B,\widetilde y_j^B,\widetilde z_j^B].
```

| 성분 | 의미 |
| --- | --- |
| `present` 또는 $m_j$ | 이 슬롯에 보고된 물체가 있으면 1, 없으면 0 |
| `x, y, z` | 초기 물체 link 원점의 로봇 root 기준 좌표, 단위 m; 위치 노이즈 포함 |
| 빈 슬롯 | 네 성분 모두 0, 즉 `[0,0,0,0]` |

`present`는 **관측 마스크**다. 실제 물체 존재 여부를 완전하게 나타내는 물리 활성 mask와 다르다. 따라서 0인 슬롯만 보고 “실제 장면에 물체가 없다”거나 “가려진 물체가 없다”고 판단할 수 없다. 좌표가 원점 근처인지 여부도 마스크를 대체하지 않는다.

슬롯에는 물체 종류·크기·자세·질량·속도·Gray/White 역할·물리 ID가 들어가지 않는다. 정렬 후 슬롯 번호는 물리 객체 번호가 아니다. 마스킹된 슬롯은 좌표까지 0으로 지워 숨겨진 위치가 입력에 남지 않게 한다. 모델의 장애물 인코더에서도 `present <= 0.5`인 슬롯을 다시 0으로 마스킹한다.

## 4. 정렬과 빈 슬롯 처리

관측에 보고될 물체들을 **노이즈가 포함된 로봇 root Y 좌표의 내림차순**으로 정렬한다. 현재 좌표 설정에서는 선반을 마주 보았을 때 왼쪽에서 오른쪽 순서다. 코드에서는 `−Y`를 오름차순으로 정렬한다.

| 단계 | 처리 |
| --- | --- |
| 유효 슬롯 정렬 | 보고된 좌표의 `−Y`로 stable sort |
| 빈 슬롯 정렬 | 정렬 키를 무한대로 두어 유효 슬롯 뒤로 이동 |
| 순서 노이즈 | `(0,1)`, `(1,2)`, … 순서로 이웃 슬롯 검사; 둘 다 유효하면 10% 확률로 교환 |
| 최종 결과 | 유효 슬롯이 앞에, `[0,0,0,0]` 슬롯이 뒤에 연속 배치 |

정렬은 물리 ID 순서의 영향을 줄이고 초기 위치에 따른 일관된 입력 순서를 만든다. 정렬에 참 위치 대신 보고된 noisy 위치를 사용하므로, 위치 오차만으로도 가까운 두 물체의 순서가 바뀔 수 있다.

인접 교환은 순차적으로 수행한다. 예를 들어 `[A,B,C]`에서 첫 교환으로 `[B,A,C]`가 된 뒤 두 번째 교환도 발생하면 `[B,C,A]`가 된다. 따라서 각 물체가 반드시 한 칸만 이동하는 것은 아니다. 빈 슬롯과 유효 슬롯은 교환하지 않으므로 빈 슬롯은 계속 뒤에 남는다.

## 5. 관측 노이즈와 생성 순서

| 종류 | 기본값 | 적용 대상·시점 |
| --- | --- | --- |
| 위치 오차 | XYZ 각각 독립 `U(-0.01,0.01)m`, 즉 ±10mm | reset에서 좌표 생성 시 한 번 |
| 가시성 오류 | 물체별 독립 1% 확률로 가시성 비트 반전 | 기본 기하 판정 이후; 활성 장애물에만 최종 적용 |
| 순서 오류 | 유효 인접 슬롯 쌍마다 10% 확률로 교환 | 정렬 후 한 번 |

물리 장면을 배치한 뒤 다음 순서로 관측 캐시를 만든다.

```text
초기 장애물의 실제 위치 → 로봇 root 기준 XYZ 변환 → 위치 노이즈 추가
실제 장면의 위치·bounds·활성 mask → 기하 가시성 판정 → 1% 비트 반전
두 결과 결합 → 보고되지 않는 슬롯 전체를 0으로 설정
noisy Y 기준 정렬 → 유효 인접 슬롯 10% 교환 → 고정 캐시 저장
```

좌표 노이즈를 먼저 생성하더라도 **가시성 판정은 noisy 좌표가 아닌 실제 장면 위치로 따로 계산**한다. 물리 물체를 노이즈만큼 옮기지 않는다.

가시성은 논리적으로 `active AND (visible XOR flip)`으로 적용된다. 보이는 활성 물체를 누락하거나 가려진 활성 물체를 보고할 수는 있지만, 비활성 물체를 가짜 장애물로 생성하지는 않는다. 기본 visible이 아닌 물체도 가림 계산에서 미리 제거하지 않으며, 활성 물체 전체가 기하 판정에 참여한다.

완성된 관측은 해당 에피소드 동안 유지된다. 장애물이 밀리거나 새로 드러나도 좌표·마스크·순서를 갱신하지 않으며, 매 step 위치 노이즈나 가시성 오류를 새로 뽑지도 않는다. 부분 reset에서는 지정된 환경의 캐시만 다시 만든다.
