## Problem Statement

연구자는 초기 시각 관측과 실행 중 F/T·촉각을 사용하는 접촉 조작 환경에서, 물체를 밀기 전에 안정적인 접촉 자세를 준비하는 행동을 학습하고자 한다. 기존 ForceDirection 환경의 물체 중심 관측과 별도 접촉·방향 보상만으로는 이번에 요구한 초기 대표 표면점 관측, 안정화 통과 조건, 접촉·방향과 결합한 거리 보상을 표현할 수 없다.

새 환경은 기존 환경들의 상속 관계와 분리해 구성과 동작을 명확히 관리해야 한다. 초기 로봇 배치와 장애물 배치가 충돌하지 않아야 하며, reset 실패에 대한 반복 재추출로 학습 iteration 시간이 과도하게 늘어나지 않아야 한다. 안정화 점수를 얻기 위해 Gate 통과를 회피하는 직접적인 보상 유인도 제거해야 한다.

## Solution

기존 ForceDirection 환경을 기능 기준으로 삼되, 기존 환경 Cfg/runtime을 상속하지 않는 `Inspire-Stabilize-Sweep-v0`를 추가한다. 하나의 정책이 총10초 안에서 Stabilize → Sweep을 수행한다. 초기 대표 표면점만 시각 관측으로 제공하고, 실제 형상 중심과 질량중심은 환경 내부의 과업·물리 계산에 사용한다.

로봇을 목표 밀기 방향의 반대편에 배치하고 기존 RED ZONE과 초기 로봇 공간을 장애물 배치 금지영역으로 확보한다. 안정화 조건을 연속0.3초 만족하면 Sweep으로 한 번만 전환한다. Gate 이후에는 안정화 완료 보상을 유지하고, 거리 감소량·정규화 접촉 유지·힘 방향의 곱으로 밀기 행동을 보상한다. 초기화 실패는 합의한 후보·관측 횟수 안에서 처리한다.

## User Stories

각 항목의 괄호는 아래 기능 계약과 테스트 기준의 연결이다. 연구자·환경 개발자·학습 운영자는 이 환경을 설계·검증·사용하는 역할이다.

1. 연구자로서 기존 환경 상속과 분리된 새 환경을 사용하여, 기존 실험의 동작을 보존하면서 안정화 후 밀기를 연구하고 싶다. (FR-01, T01)
2. 연구자로서 기존 로봇·손·센서·자산·물성 분포를 유지하여, 요청한 과업 변경을 기준 환경과 비교하고 싶다. (FR-01, T01)
3. 연구자로서 단일 정책이 총10초 안에 안정화와 밀기를 수행하게 하여, 별도 정책이나 추가 접근 단계 없이 접촉 조작을 학습하고 싶다. (FR-01, FR-06, T07, T11)
4. 연구자로서 기존12D 행동과 Runner clip을 유지하여, 기존 제어 계약을 그대로 사용하고 싶다. (FR-01, T12)
5. 연구자로서 실제 형상 중심과 질량중심을 구분하여, 목표 거리와 접촉 모멘트를 각각 올바른 기준점에서 평가하고 싶다. (FR-02, FR-05, T02, T06)
6. 연구자로서 정책에 현재 실제 물체 위치 대신 초기 대표 표면점을 제공하여, 초기 시각 이후 F/T·촉각 기반 조작을 학습하고 싶다. (FR-02, FR-04, T04)
7. 연구자로서 초기 월드 표면점을 현재 EEF 좌표로 관측하여, 로봇의 이동은 반영하면서 실제 물체 이동을 시각으로 추적하지 않게 하고 싶다. (FR-02, T04)
8. 연구자로서 Actor와 Critic에 같은 센서 정보를 제공하여, Critic에도 현재 물체 GT가 추가되지 않게 하고 싶다. (FR-02, FR-04, T04, T12)
9. 연구자로서 실제 메쉬의 보이는 표면에서 대표점을 얻어, 완전한 물체 중심이나 포괄 박스 표면을 관측값으로 대체하지 않게 하고 싶다. (FR-04, T04)
10. 연구자로서 타겟의 가장 큰 유효 가시 조각 하나를 사용하여, 현실에서 하나의 관측 타겟을 선택하는 가정을 반영하고 싶다. (FR-04, T04)

12. 연구자로서 기존 최소 노출 폭과 노출 비율을 유지하여, 인식 가능한 물체만 관측한다는 가정을 보존하고 싶다. (FR-04, T04)
13. 환경 개발자로서 기존 valid+XYZ 슬롯과 장애물 인코더를 유지하여, 위치 값 변경과 단계 관측 추가만 모델 입력에 반영하고 싶다. (FR-04, T04, T12)

18. 학습 운영자로서 IK 후보 수를 제한하고 실패 원인을 기록하여, 불가능한 초기 자세를 무한히 재시도하지 않게 하고 싶다. (FR-03, T03, T14)
19. 환경 개발자로서 부분 reset이 선택한 환경에만 영향을 주게 하여, 다른 에피소드의 시간·상태·관측 이력을 보존하고 싶다. (FR-03, T05)
20. 연구자로서 손–타겟 접촉의 법선·마찰 합력과 COM 기준 모멘트를 사용하여, 다른 물체나 선반 반력을 안정화 신호로 섞지 않게 하고 싶다. (FR-05, T06)

22. 연구자로서 힘·모멘트·이동·회전·속도·압착 조건을 연속 만족해야 Gate를 통과하게 하여, 순간 접촉이나 단일 종합점수만으로 밀기 단계에 진입하지 않게 하고 싶다. (FR-06, T07)
23. 연구자로서 Gate를 한 번 통과하면 Sweep에 남고 단계 관측을 받게 하여, 정책이 현재 수행할 과업을 구분하게 하고 싶다. (FR-04, FR-06, T07)
24. 연구자로서 Gate 후 같은 weight의 안정화 완료 보상을 받아, setup 보상의 소실 때문에 통과를 늦추는 직접 유인을 제거하고 싶다. (FR-07, T08)
25. 연구자로서 초기 이동·회전 비용은 Stabilize에만, 압착 비용은 두 단계에 적용하여, 밀기 이동을 허용하면서 과도한 압착은 계속 억제하고 싶다. (FR-07, T08)
26. 연구자로서 Stabilize 동안 거리 항을 비활성화하고 전환 시 이력을 초기화하여, 안정화 중 이동을 밀기 보상으로 소급 지급하지 않게 하고 싶다. (FR-07, T09)
27. 연구자로서 이전 step의 거리 감소에 접촉 유지와 힘 방향 계수를 곱하여, 실제로 접촉을 유지하며 목표 방향으로 미는 행동을 보상하고 싶다. (FR-07, T09)
28. 연구자로서 실제 접촉 없는 목표 근처의 가산 예외를 제거하여, 목표와 가까워도 접촉·힘 조건이 그대로 적용되게 하고 싶다. (FR-07, T09)
29. 연구자로서 멀어짐 비용을 기존의1.5배로 적용하고 기존 기타 비용을 보존하여, 합의한 보상 차이만 도입하고 싶다. (FR-07, FR-08, T09, T10)
30. 연구자로서 F/T 변화 비용의 누적 양의 보상5% 상한을 제거하여, 해당 비용이 과거의 양의 보상 예산에 묶이지 않게 하고 싶다. (FR-08, T10)
31. 연구자로서 목표 방향 제외각30도를 고정하고 나머지 합의된 일정을 유지하여, 현재 범위 밖의 Push/Pull 동작 확장을 피하고 싶다. (FR-01, FR-08, T03, T10)
32. 연구자로서 timeout에서 Gate 통과와 현재 목표 거리를 함께 확인하여, 안정화만 달성했거나 일찍 목표를 지나간 에피소드를 성공으로 세지 않게 하고 싶다. (FR-01, T11)
33. 학습 운영자로서 요청·실제 장애물 수, 감축 이유, IK 횟수와 reset 시간을 기록하여, 계산 비용과 장면 분포 변화를 확인하고 싶다. (FR-03, FR-09, T14)
34. 환경 개발자로서 기존 환경과 모델 계약의 회귀 검증을 수행하여, 새 환경을 추가해도 기존 실험이 변하지 않았음을 확인하고 싶다. (FR-01, FR-09, T01, T12)
35. 연구자로서 신규 reward weight를 추후 조정 항목으로 남겨, 아직 합의하지 않은 계수를 임의로 고정하거나 정책 성공을 미리 보장하지 않게 하고 싶다. (FR-07, T15, Further Notes)

## Implementation Decisions

다음 FR 항목은 확정된 기능 계약이다. 기존 역할별 모듈 구조를 유지하며 파일명이나 내부 helper 수는 기능 요구사항으로 고정하지 않는다.

### FR-01. 범위와 보존 기준

기능 기준은 현재 작업트리의 `Inspire-Sweep-Simple-Finger-ForceDirection-v0`다. 기존 환경 Cfg/runtime을 상속하지 않고 EnvCfg, SceneCfg, 각 Manager Cfg, PPO Cfg와 runtime을 독립 선언한다. Isaac Lab 기반 클래스, 기존 자산, 검증된 계산 함수의 재사용은 허용한다. 기존 환경과 공용 함수의 결과를 바꾸지 않는다.

| 항목 | 계약 |
| --- | --- |
| 로봇 | 기존 UR5e + Axia80-M8 + RH56E2 및 F/T·촉각 유지 |
| 물체·선반 | 기존 Simple 자산·형상/크기·물성 분포 유지. 타겟 cylinder, 장애물 후보 풀16개. 현재 타겟 종류를 임의로 확대하지 않음 |

| 손 행동 | 기존 독립6축 절대 관절 목표 rad, 초기0rad |
| Action clip | Runner의12축 공통 ±π/2, OSC scale 적용 전. Last Action과 action-rate는 실행 clip 후 raw action |

성공의 정확한3cm 경계는 기존 코드의 `< .03`를 보존한다. 일반 지침의 `<=`와 달라도 이번 확정 계약에서는 기존 코드의 엄격한 경계를 유지한다. 새 기준점은 아래 형상 중심이다.

### FR-02. 좌표·중심·정책 정보의 구분

- **형상 중심(Centroid)**: 실제 타겟 위치, 목표 거리, Stabilize 초기 위치 대비3D 이동량의 기준. 현재 원통은 밑면 root에서 높이의 절반에 해당한다.
- **질량중심(COM)**: 접촉 모멘트의 기준. 현재 하부 질량 편중 원통은 자산 설정상 밑면에서 높이의20%다. 실제 scale 및 PhysX COM은 검증 시 대조한다.
- **대표 표면점**: 보이는 물체 표면의 한 점. 정책 관측에 사용하며 실제 중심으로 보정하지 않는다.
- **목표점**: 에피소드 동안 고정한 월드 점. 기존처럼 현재 EEF 기준 좌표로 관측한다. 목표의 XY가 도달 과업을 정의한다.

reset·보상·Gate·종료에는 실제 기하·물리 상태를 사용할 수 있다. Actor/Critic 모두 현재 물체 중심·COM·GT 원본 ID·조각 간 대응을 관측하지 않는다. 초기 표면점은 월드에서 고정하고 매 step 현재 EEF로 좌표변환한다. 물체가 움직여도 초기 시각 점을 실제 물체와 함께 이동시키지 않는다.

### FR-03. Scene와 reset

#### 초기 손 자세

타겟에서 목표로 향하는 XY 방향의 **정반대편**에 손을 둔다. 손바닥 법선은 목표 방향을 향한다. 명목 위치의 타겟 표면과 마주 보는 손 표면 간격은 약5cm다. EEF 원점에서 타겟 root까지5cm로 대체하지 않는다.

- 선반 X/Y 각각 독립 균등 오차 ±1cm.
- yaw 독립 균등 오차 ±10도.
- 기존 명목 EEF 높이 `default_local Z + 0.01m`, 기존 roll/pitch 유지. Z·roll·pitch 랜덤화 없음.
- 초기 손6축0rad, 기존 로봇 속도 초기화 유지.
- 장애물 배치 전에 같은 타겟·목표에서 최대4개 IK 후보를 확인한다. 관절/IK 유효성, 타겟·선반·자기충돌을 검사한다. 모두 실패하면 진단 정보를 남기고 중단한다.

#### 배치 금지영역·장애물 감축

**기존 RED ZONE 그대로 + 초기 로봇 팔과 손의 점유 공간**을 합집합으로 사용한다. 기존 RED를 타겟의 직선 이동 통로로 축소하지 않는다. 추가 로봇 공간은 충돌 형상에1cm 여유를 적용한다. 장애물의 실제 크기를 반영해 물체 전체가 이 영역을 침범하지 않도록 한다.

1. 기존처럼 장애물 요청 수0–6개와 후보를 추출한다.
2. 기존 큰 후보 우선 순서를 사용하되 후보마다 한 번의 배치 판정을 한다.
3. 유효 공간이 없는 후보만 생략하고 후속의 더 작은 후보도 검사한다. 이미 성공한 배치는 유지한다.
4. 실제로 배치한 물체만 활성화하고 실제 개수를 반환한다. 요청 수를 실제 개수로 기록하지 않는다.
5. 시각 관측에서16슬롯 초과 또는 타겟 미검출이면 장애물을0개로 줄이고 한 번만 재관측한다. 타겟 단독도 미검출이면 오류로 보고한다.

일반 배치는1회, 시각 관측은 최대2회다. 목표·타겟을 다시 뽑아 실패를 숨기거나32회 배치 재시도를 하지 않는다. 실제 장애물 수 분포는 요청 균등분포와 달라질 수 있으므로 감축률·0개 비율을 기록한다.

#### 논리적 reset 순서

타겟/목표 추출 → IK 후보 및 로봇 점유 공간 계산 → 장애물 배치 → **로봇이 관측을 가리지 않는 조건으로** 시각 snapshot 생성 → 필요한 경우 장애물0개 fallback → 선택 상태 반영 및 초기 형상 중심/자세·관측 cache·Gate·contact count·힘 이력 초기화 순서다. 기하 관측이므로 로봇 시각 메쉬를 관측 광선 대상에서 제외해 진입 전 장면을 표현할 수 있다.

부분 reset은 해당 env row만 갱신한다. 실패한 후보를 임시로 시뮬레이션에 쓰거나 전역 physics step을 진행해 다른 환경 시간을 이동시키지 않는다. reset 난수는 seed로 재현 가능하게 관리한다.

### FR-04. 관측과 모델

`surface_point`의 실제 시각 메쉬 광선 질의를 사용한다. 실제 RGB-D 렌더링/segmentation 모델이나 원근 센서를 구현하는 범위는 아니다.

| 항목 | 계약 |
| --- | --- |
| 관측 방향 | 기존 고정 정면 직교 광선, 기본1mm 간격 |
| 대표점 | 연결 가시 영역의 mask 중심에 가장 가까운 영역 내부 픽셀의 실제 표면 교점 |
| 필터 | 가시 폭2cm 이상 및 원본 전체 폭 대비20% 이상 유지 |
| 필터의 의미 | 20%는 현실 모델의 인식 가능성을 근사하는 환경 가정. 원본 전체 폭은 필터 내부에만 사용하고 정책에는 제공하지 않음 |
| 타겟 | 유효 조각 중 가시 면적 최대 조각 하나만 사용. 타겟의 나머지 조각을 장애물 관측으로 재사용하지 않음 |
| 다른 물체 | 분리된 가시 조각마다 독립 관측 물체. 원본 ID로 재결합하지 않음 |
| 시각 noise | 추가 좌표 noise·visibility flip·임의 누락·swap 없음 |
| 기타 센서 | 기존 F/T·촉각 처리와 noise 유지 |

**기존 관측 포맷을 보존한다.** 타겟 XYZ3D의 내용만 대표 표면점으로 바꾸고, 장애물은 `valid + XYZ` 16슬롯/64D를 유지하면서 XYZ를 같은 방식으로 바꾼다. 미사용 슬롯은 기존대로0으로 처리한다. 고정 snapshot의 슬롯 대응은 에피소드 내 유지한다.

기존 direct policy66D에 단계 flag1D를 추가해67D가 된다. 장애물64D 및 encoder64→32→16, Actor/Critic별 encoder, 본체 hidden256→128→64 구조는 보존한다. 결합 latent 입력은67+16=83D, action은12D다. 이 차원은 설계 산출값이며 실제 import/forward/export 검증은 미수행이다. 단계 flag는 다음 action이 실행될 단계(0=Stabilize, 1=Sweep)를 나타낸다. 연속 만족 시간이나 GT 오차를 추가 관측하지 않는다.

### FR-05. 접촉 하중 계측

손–타겟 필터의 접촉만 사용한다. 선반/테이블 반력·중력·장애물 힘을 섞지 않는다. 손목 F/T를 타겟 전용 접촉 모멘트로 대체하지 않는다.

법선 접촉 벡터를 `f_n`, 해당 점을 `p_n`, 마찰 벡터를 `f_f`, 해당 anchor를 `p_f`, 실제 COM을 `c_com`으로 둔다.

```math
\mathbf{F}=\sum_i\mathbf{f}_{n,i}+\sum_k\mathbf{f}_{f,k}
```

```math
\boldsymbol{\tau}
=\sum_i(\mathbf{p}_{n,i}-\mathbf{c}_{com})\times\mathbf{f}_{n,i}
+\sum_k(\mathbf{p}_{f,k}-\mathbf{c}_{com})\times\mathbf{f}_{f,k}
```

```math
S=\sum_i\|\mathbf{f}_{n,i}\|_2
```

**S는 법선 하중 합**으로 확정했다. 최초 첨부의 접촉점별3D 합력 norm합을 구현했다고 표기하지 않는다. 합력과 모멘트에는 계속 마찰을 포함한다. 법선과 마찰의 같은 index를 같은 점으로 취급하지 않는다.

100Hz에서 각 물리 sample의 힘·모멘트·압착을 계산한다. `get_contact_data`와 `get_friction_data`의 counts/starts 버퍼 재사용에 주의해 법선을 먼저 축약하거나 필요한 인덱스를 보존한다. 평균 접촉점×합력으로 모멘트를 근사하지 않는다. 반환한 impulse를 힘으로 바꾸는 dt는0.01초다.

### FR-06. Stabilize와 Gate

형상 중심을 `c`, episode 시작 형상 중심·자세를 `c0, R0`로 둔다. 현재 타겟 형상 중심→목표의 XY 단위 방향 `d`에 대해 힘을 평행·수직 성분으로 나눈다. 모멘트 축은 선반/중력 기준 수평XY·수직Z로 일관되게 표현한다.

```math
F_\parallel=\mathbf{d}^{\mathsf{T}}\mathbf{F},\qquad
\mathbf{F}_\perp=\mathbf{F}-F_\parallel\mathbf{d}
```

```math
R_{setup}=C\,\mathrm{clip}(F_\parallel/F_{test},0,1)
\exp\left[-\left(\frac{F_\parallel-F_{test}}{\sigma_F}\right)^2
-\frac{\|\mathbf{F}_\perp\|^2}{\sigma_\perp^2}
-\frac{\tau_z^2}{\sigma_{\tau,z}^2}
-\frac{\tau_x^2+\tau_y^2}{\sigma_{\tau,xy}^2}\right]
```

`C`는 실제 손–타겟 접촉 여부다. 접촉이 없거나 유효한 힘이 없으면 setup 점수0이다. 목표와 정확히 일치해 방향이 정의되지 않을 때도 임의 방향을 만들어 Gate를 통과시키지 않는다.

| 파라미터 | 확정한 첫 검증값 |
| --- | ---: |
| F_test | 0.5N |
| sigma_F | 0.2N |
| sigma_perp | 0.2N |
| sigma_tau_z | 0.005N·m |
| sigma_tau_xy | 0.01N·m |
| delta_p | 3mm, 형상 중심3D 이동량 |
| delta_R | 3°, 전체 자세 회전각 |
| 선속도 상한 | 5mm/s |
| 각속도 상한 | 0.05rad/s |
| S_max | 5N, 양 단계 공통 |
| 연속 만족 시간 | 0.3초=30 physics samples |

Gate는 실제 접촉, `|F_parallel−F_test|≤sigma_F`, `norm(F_perp)≤sigma_perp`, `|tau_z|≤sigma_tau_z`, `norm(tau_xy)≤sigma_tau_xy`, 초기 위치/자세 변화≤각 허용량, 속도≤각 상한, `S≤S_max`를 **모두** 만족해야 한다. setup 점수 하나로 통과하지 않는다. 통과 전 불만족 sample은 연속 시간을0으로 되돌린다.

한 번 통과하면 영구 latch한다. 통과를 확인한 policy step의 다음 step부터 Sweep을 실행한다. 통과 step 자체의 보상은 기존 Stabilize 단계로 계산한다. 다음 관측의 단계 flag와 다음 action의 실행 단계가 일치해야 한다. 종료와 같은 step의 Gate 달성은 달성 latch로 기록하되 동시 물리 실패는 성공보다 우선한다.

### FR-07. 보상 구성과 단계 경계

#### 단계 보상·초기 이동 비용

Gate 전 setup 원점수는0–1이다. Gate 후에는 같은 weight로 원점수1인 **안정화 완료 보상**을 매 step 지급한다. setup 자세 평가는 종료하며 초기 위치에 머물거나 테스트 힘을 계속 유지할 필요가 없다. 미래 보상을 일시불로 지급하지 않는다.

```math
R_{stage}=(1-G)\overline{R}_{setup}+G
```

```math
P_{move}=\left[\frac{\|\mathbf{c}-\mathbf{c}_0\|}{\delta_p}-1\right]_+^2,
\qquad
P_{rotate}=\left[\frac{\theta(R_0^{\mathsf{T}}R)}{\delta_R}-1\right]_+^2
```

이동·회전 비용은 Stabilize에만 적용한다.

```math
P_{squeeze}=\left[S/S_{max}-1\right]_+^2
```

압착 비용은 두 단계 모두에 적용한다.

`R_setup`와 `P_squeeze`는 각 physics sample에서 비선형 점수를 먼저 계산하고 policy step 내 평균한다. 서로 반대인 힘/모멘트가 시간 평균에서 상쇄된 뒤 안정적으로 보이는 오류를 피한다.

#### Sweep 거리 보상

`d_t`는 현재 형상 중심과 목표의 XY 거리, `delta_d=d_(t−1)−d_t`다. 역대 최단 거리 갱신량이 아니라 **이전 policy step 대비 변화량**을 사용한다. Sweep 진입 위치에서 이전 거리 이력을 초기화하므로 Stabilize 중 이동을 소급 지급하지 않는다.

접촉 유지 count는 기존 최근3회 중2회 인정, 인정+1/불인정−2, 범위0–20, 불인정 step 지급0을 유지한다. Sweep 진입 시 count/history를0으로 초기화하고 계수 `h=count/20`을 사용한다. 접촉0.01N 및 현재 EEF 높이<선반+12cm 조건을 유지한다.

방향 계수 `a`는 현재 목표 XY 방향과3D 손→타겟 합력의 cosine을0–1로 제한한다. 기존 physics sample 평균 합력을 사용하며 실제 접촉·수평 합력1N 이상이 필요하다. 목표1cm 내부의 방향1/가짜 접촉20 예외는 없다. 방향이 정의되지 않으면 계수0이다.

```math
r_{sweep}=G\left(w_{sweep}[\Delta d]_+\,h\,a
-38.91[-\Delta d]_+\right)
```

거리 증가 비용에는 접촉·방향 계수를 곱하지 않는다. 기존−25.94의1.5배인−38.91이다. Stabilize 동안 두 거리 항 모두 비활성화한다. 별도 Reaching·접촉 유지·방향 점수 보상을 중복 지급하지 않는다.

#### 전체 보상의 시간 단위

```math
r_t=\Delta t\left[
w_sR_{stage}-(1-G)(w_pP_{move}+w_RP_{rotate})
-w_c\overline{P}_{squeeze}\right]+r_{sweep}+r_{existing}
```

`r_existing`은 기존 공통 비용의 weight·dt 적용까지 포함한 값이다. 거리 차분 항은 함수에서 policy dt로 나누고 RewardManager가 dt를 곱해 최종적으로 weight×거리 변화가 되게 한다. setup·완료·압착·초기 이동/회전은 지급률 항으로 dt를 한 번 적용한다.

Gate 완료 보상은 이 항 자체에서 통과를 늦춰 지급률을 유지하려는 유인을 없앤다. 전체 정책이 움직임 비용 때문에 정지하지 않는지, 거리 왕복으로 이득을 얻지 않는지는 최종 weight와 함께 검증한다. 성공을 보장했다고 해석하지 않는다.

| 장애물 접촉 weight | (0,0), (1000,0), (3000,−0.02), (6000,−0.05), (10000,−0.05), (12000,−0.1) |

Deadzone 일정은 삭제하고 reset 제외각30도를 고정한다. 팔속도 임계값 일정은 기준 ForceDirection에서도 비활성이므로 새로 추가하지 않는다.

### FR-09. 모듈 책임과 연결 계약

기존 코드베이스는 환경 구성, Scene/자산, 역할별 MDP 구성과 계산 함수, runtime, PPO/모델을 분리한다. 이 구조를 유지한다. 기존 ForceDirection은 다른 Finger 환경의 Cfg/runtime을 상속하지만 새 환경은 그 상속 체인을 사용하지 않는다. Isaac Lab 기반과 검증된 계산 함수 재사용은 허용한다.

대표 표면점 벤치는 현재 단일 장면 처리와 CPU 연결요소 분석을 포함한다. 비교용 OBB·시각화 처리를 학습 경로에 그대로 넣지 않는다. 동일한 관측 계약을 만족하는 배치 처리와 데이터 전송 비용을 검토하되, 특정 최적화 알고리즘이나 미합의 성능 수치를 요구사항으로 추가하지 않는다.

## Testing Decisions

### 검증 지점과 원칙

사용자가 이번 명세 작성에서 수용한 구성은 **등록된 환경의 reset·step 입출력**을 주 검증 지점으로 삼는 것이다. 관측, 보상, 종료, 단계 변화, 부분 reset의 외부 동작을 한 시나리오에서 확인한다. 등록·환경 생성·Manager 연결을 건너뛴 계산 함수 테스트만으로 기능 완료를 판정하지 않는다.

physics 접촉 부호·좌표·시간 집계와 수식 경계는 제어 가능한 입력을 사용한 제한적인 검증으로 보완한다. PPO는 기존 모델의 forward·실제 gradient·export 경계에서 검사한다. 테스트를 위해 새로운 공개 API나 다수의 mock 전용 계층을 추가하는 것을 요구하지 않는다. private 필드 이름, helper 호출 횟수, 클래스 분할 방식 대신 계약된 출력과 시간 경계를 확인한다. 단, 최대 IK/배치/관측 횟수와 상속 독립성은 명시적 요구이므로 직접 검증한다.

### 기존 테스트의 참고 사례

다음은 현재 코드에서 확인한 검증 방식이다. 이전 환경의 임계값·목표 예외·상속 구조를 새 요구사항으로 가져오는 근거는 아니다.

- Simple 환경의 구성 격리·등록 대조, runtime 생명주기·RNG·부분 reset 검증: 새 환경의 독립성 및 다른 환경 영향 검증에 참고한다.
- Finger 행동의 wrapper clip, raw Last Action/action-rate, 모델 gradient/export 검증: 동일 제어 계약과 변경 관측 차원 검증에 참고한다.
- Finger 버전의 연속 타이머·latch·부분 reset·timeout 실패 우선순위 검증: 이번 Gate의30 physics sample과 policy 전환 경계에 맞춰 사례를 구성한다.
- SemiProf/ForceDirection의 packed 마찰 범위, 무효 버퍼·힘 상쇄, physics 수집 lifecycle, cosine 방향 검증: 새 COM 모멘트·법선 압착 하중까지 확장해 확인한다.
- 대표 표면점 메쉬 관측의 실제 표면 교점, 가림 누출 방지, 정면 대표점 선택, 반복 입력 재현성 검증: 타겟 선택·독립 조각·환경 관측 연결 검증에 참고한다.

- 추가 시각 noise/dropout/swap, 기존20% 노출 필터 제거, 타겟 종류 확대, 새 물성 분포, Z/roll/pitch 초기 오차 추가.

## Further Notes

### 확정·유보·검증 상태

- Q34에서 사용자가 통합 설계와 Gym ID `Inspire-Stabilize-Sweep-v0`를 확정했다. 이번 문서는 같은 요구사항을 개발 명세 형식으로 정리한 기준 문서다. 설계 확정이나 명세 작성은 구현 착수 지시를 대신하지 않는다.
- 신규 weight `w_s`, `w_p`, `w_R`, `w_c`, `w_sweep`는 사용자 요청으로 추후 조정한다. 완료 보상에는 setup과 같은 `w_s`를 사용한다. 이 유보는 후속 사용자 위임으로 해제됐으며, 문서 상단의 초기값을 사용한다.
- 정규화된 접촉·방향 인자의 곱이0–1일 때 같은 거리L의 왕복 거리 보상 상한은 `(w_sweep−38.91)L`이다. 정규화만으로 왕복 방지가 보장되지 않는다. 최종 weight에 따른 검증은 T15에 남는다.
- Gate 수치는 첫 물리 검증값이다. 현재 질량·마찰 분포에서 모든 조건을 실제로 달성할 수 있는지는 미검증이다. 구현 중 타당성 문제가 발견되면 확정 수치를 조용히 바꾸지 않고 근거를 남긴다.
- 기존 코드 분석·요구 대조·문서 검사는 수행했다. 신규 환경 import·단위/통합 테스트·GPU physics·reset 성능·학습·실물 검증은 수행하지 않았다.

### 이슈 게시 상태

`to-spec`은 프로젝트 이슈 트래커에 게시하고 `ready-for-agent` 라벨을 적용하도록 지시한다. 현재 대화와 확인한 프로젝트 설정에는 이슈 게시 대상이 지정돼 있지 않다. Git remote만으로 코드 저장소와 문서 저장소 중 게시 대상을 임의 선택하지 않는다. 명세는 로컬 기준 문서로 완성하며, 이슈 생성·라벨 적용은 미수행 상태로 기록한다. 스킬의 안내에 따라 게시 설정에는 `/setup-matt-pocock-skills`가 필요하다.
