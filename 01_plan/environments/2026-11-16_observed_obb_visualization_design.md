# 부분 관측 OBB 시각화 요구사항 인터뷰

상태: 사용자가 전체 설계를 확정했다. 후속 지시와 검증 접점 확인까지 반영한 [개발 명세서](2026-11-16_observed_obb_visualization_spec.md)가 현재 개발 계약이다. 이 문서는 인터뷰 근거를 보존하며 구현 완료 기록이 아니다.

근거: 사용자의 PLAN17 후속 요청과 2026-11-16 인터뷰 응답. [용어집](../../GLOSSARY.md).

## 확정된 범위

- 타겟뿐 아니라 장애물도 관측 OBB 생성 대상이다.
- 이번 작업은 충돌 없는 바운딩 박스 시각화 검토를 위한 것이다. 학습·제어·정책 관측 연결은 범위 밖이다.
- 인터뷰에서 구현 없이 요구사항을 확정했다. 후속 작업은 개발 명세서 작성이며 코드 구현을 포함하지 않는다.
- 정면의 고정 관측 시점을 가정한다. 실제 이미지 기반 가시성 판단은 reset 비용 때문에 사용하지 않고 기하 근사를 설계한다.
- 초기 관측은 장면 배치 후 한 번 생성하고 재배치 또는 명시적 재관측까지 고정한다.
- 정면에서 가려지지 않은 구간의 앞뒤 깊이는 온전히 관측한다고 가정한다. 좌우 20cm·앞뒤 10cm·높이 15cm인 정렬된 박스의 오른쪽 절반이 가려지면 왼쪽 10×10×15cm가 남는 예시를 사용자가 승인했다.
- 첫 구현에서 물체 형상을 물체 방향을 따라 회전하는 전체 박스로 근사하는 것을 승인했다. 사용자는 이를 '잘린 메쉬에 일반적인 OBB 방법을 도입하는 느낌'으로 구체화했다. 원본 박스의 방향을 결과 OBB에 그대로 강제한다는 뜻은 아니다.
- 가림을 유발하는 물체의 z는 무한처럼 취급한다. 앞 물체가 낮아도 뒤 물체의 윗부분이 보인다고 처리하지 않는다. 이 무한 높이는 가림 판정용 가정이며 출력 박스를 무한 높이로 만들라는 뜻이 아니다.
- 초기 물체 간 가림만 고려한다. 타겟과 활성 장애물이 서로를 가리며 로봇·손·선반 구조물은 가림 계산에서 제외한다.
- 분리된 가시 조각은 별개의 관측 물체로 취급한다. Perception에서 두 조각이 같은 물체라는 보장이 없으므로 GT 출처가 같다는 이유로 한 박스로 합치지 않는다.
- 매우 적게 노출된 조각은 관측 물체로 포함하지 않는다. 조각별 노출 폭 2cm 이상과 노출 비율 20% 이상을 모두 만족해야 한다. 경계값은 포함하며 서로 다른 조각을 합산하지 않는다.
- OBB는 수직축을 유지하며 잘린 XY 형상에 최소 면적 직사각형을 맞추고 원래 높이를 결합한다. 원래 물체 yaw를 고정해서 쓰지 않는다.
- 이번 검증에는 좌표 노이즈와 무작위 가시성 반전을 적용하지 않는다. 동일 배치에서 같은 결과를 내는 것을 목표로 한다.
- 각 조각에는 독립 관측 ID만 부여하고 타겟/장애물 역할은 판별하지 않는다. 원본 물체와의 대응은 시뮬레이터 계산·선택적 디버그 정보로만 취급한다.
- 기본 시각화는 통과한 관측 OBB의 선 표시다. 원래 전체 박스는 켜고 끄는 비교용 표시로 둔다. 모든 관측·참고 표시는 충돌과 물리 반응이 없다.
- 첫 검토는 현재 Simple 계열의 자산·배치 규칙을 재사용한 단일 장면과 별도 검토 실행기에서 수행한다. 정책·checkpoint·새 학습 환경을 도입하지 않으며 계산은 향후 다중 환경 적용을 고려한다.
- 사용자의 최종 후속 지시에 따라 개발은 기존 패키지가 아니라 워크스페이스의 src 아래 새 패키지에서 수행한다. 기존 Simple 자산·배치 규칙 재사용 결정은 유지한다.
- 물리 시뮬레이션으로 물체를 움직이지 않는 정지 배치를 검토한다. 수동 새 배치는 물체 배치와 관측을 모두 갱신하고, 수동 재관측은 현재 배치를 유지한 채 관측만 다시 계산한다. 검토용 화면 회전은 관측에 영향을 주지 않는다.

## 현재 소스에서 확인한 사실

- `mdp/observation_functions/wrench_refactor.py`의 초기 타겟 관측은 초기 link 위치를 저장하고 reset 고정 편향을 적용한 뒤 현재 EEF 좌표계로 변환한다. 명칭만 보고 형상 Centroid로 해석하지 않는다.
- `mdp/event_functions/wrench_refactor_relative_ik_test.py`의 `initialize_fast_geometry`는 물체 bounds를 초기화하고, 기존 가시성용 외접원 반경을 저장한다.
- 같은 파일의 `fast_reset_scene`은 shelf 좌표를 기존 정면 가시성 함수에 전달한다. 현재 활성 장애물 관측에는 가시성 bool을 적용하며, 부분 가시 형상을 OBB로 출력하지 않는다.
- 직접 의존하는 `src/scene_randomization/visibility.py`는 서로 겹치지 않는 원형 바닥면·같은 높이·평행 시선을 전제로 구간별 가장 앞 물체를 계산한다. 비율뿐 아니라 구간 경계와 소유 물체도 반환한다. 직육면체·높이 차이를 지원한다고 가정하지 않는다.
- `runtime/sweep_simple.py`의 기존 IK 범위 표시에는 rigid/collision 설정이 없는 선형 박스 marker의 구현 사례가 있다.

## 확정된 요구사항에 따른 구현 권고안 — 최종 대조용

1. startup에서 물체별 로컬 bounds를 준비하고, reset에서는 활성 물체의 위치·방향으로 박스 기하를 변환한다.
2. 선반 정면의 평행 시선을 가정하여 바닥면의 좌우 구간별 앞뒤 관계를 구한다. 가림 계산에서 높이는 사용하지 않는다.
3. 가장 앞에 보이는 형상을 구간별로 판정하고 연속된 같은 형상의 구간을 하나의 가시 조각으로 묶는다. 가림으로 떨어진 조각은 합치지 않는다.
4. 이 과정에서 조각의 노출 폭을 함께 계산한다. 원래 물체의 정면 전체 폭도 투영에서 재사용하여 폭·비율 기준을 함께 검사하고, 기준 미달 조각을 OBB 피팅 전에 제외한다. 가시성 판정을 별도로 반복하지 않는다.
5. 통과한 조각에 대해 원래의 계산용 박스를 해당 구간에 맞춰 자른다. 남은 구간의 앞뒤 두께와 원래 물체 높이를 유지한다. 실제 mesh를 생성하거나 점군을 대량 샘플링할 필요 없이 잘린 바닥면 다각형의 꼭짓점으로 계산하는 방안을 제안한다.
6. 조각마다 XY 최소 면적 직사각형을 계산하고 실제 높이를 결합해 독립된 관측 OBB를 출력한다.
7. 박스를 충돌 없는 시각화로 표시하고 스냅샷으로 유지한다.

이미지 생성·렌더 결과 판독·학습은 계산 경로에 넣지 않는다. 물체 단위 중심 깊이 정렬만으로 회전된 박스의 모든 가림 관계가 정확하다고 주장하지 않는다. 연산량과 정확도는 구현 전 설계 검토 및 후속 검증 대상이다.

### 계산량을 줄이는 설계 후보

- 전체 가시성 판정과 OBB 계산을 독립 경로로 두 번 하지 않고 같은 구간·절단 기하를 공유한다.
- 작은 조각을 제외한 뒤 남은 조각에만 OBB를 피팅한다. 다만 제외된 조각의 원래 물리 물체도 가림에는 계속 참여해야 하며, 관측에서 탈락했다고 뒤 물체를 보이게 만들지 않는다.
- 현재 물체들의 회전 박스 바닥면을 사용한다. 원형 외접원 기준으로 잘린 범위를 계산한 뒤 OBB에 억지로 적용하지 않는다.
- 가시성이 바뀔 수 있는 좌우 경계를 이용하는 구간 방식을 후보로 둔다. 근사 박스가 겹치는 상황에서는 앞면 깊이 순서가 바뀌는 경계도 필요하므로, 기존 원형·비겹침 전용 구간 판정을 무조건 그대로 재사용하지 않는다.
- 화면의 픽셀 수·mesh 삼각형 수에 의존하는 처리를 피한다. 실제 최속 구현이나 배치 규모별 CPU/GPU 우위는 아직 측정하지 않았다.

### 최소 노출 기준 — 확정

가시 조각의 폭을 $w$, 원래 실제 물체의 가림 전 정면 전체 폭을 $W$, 최소 폭을 $w_{\min}=0.02$ m, 최소 비율을 $r_{\min}=0.20$으로 둔다. 두 조건을 모두 만족해야 통과한다.

```math
w \geq w_{\min} \quad \mathrm{and} \quad w / W \geq r_{\min}
```

유효한 $W>0$에서 아래 비교로 합칠 수 있어 조각마다 비율을 별도로 나눠 계산할 필요가 없다.

```math
w \geq \max(w_{\min},\ r_{\min} W)
```

서로 분리된 조각의 폭은 합산하지 않는다. $W$와 원본 물체 대응은 이번 시뮬레이터 근사의 계산용 정보이며 관측 ID를 합치거나 관측의 타겟 역할을 부여하는 데 쓰지 않는다. 실제 Perception에서 동일한 비율을 구할 수 있다고 가정하지 않는다.

사용자가 최소 폭을 제안된 5mm에서 2cm로 변경했고 최소 비율 20%를 승인했다. 값은 시각화 검토용 설정으로 유지한다. 정면 전체 폭이 2cm보다 작은 물체는 전체가 보여도 제외되는 결과를 갖는다. 완전히 가려진 물체에는 관측 OBB가 없다.

## 최종 설계 대조

| 항목 | 최종 요구사항 |
| --- | --- |
| 대상 | 현재 Simple 자산·배치의 타겟과 활성 장애물 |
| 가림 | 고정 정면·물체 간 가림·높이 무시·이미지 미사용 |
| 형상 | 물체 전체를 회전 박스로 근사한 뒤 가시 구간으로 절단, 해당 구간의 전체 깊이 유지 |
| 분리 | 떨어진 조각은 별개 관측 물체, 원본 물체가 같다는 이유로 병합하지 않음 |
| 필터 | 조각별 폭 2cm 이상 AND 원래 전체 폭 대비 20% 이상 |
| OBB | 조각 XY의 최소 면적 직사각형과 실제 높이, 수직축 유지 |
| 관측 의미 | 독립 관측 ID, 타겟/장애물 역할 판별 없음, GT 대응은 계산·디버그 전용 |
| 표시 | 통과한 OBB의 선 표시, 원래 전체 박스 비교 토글, 모든 표시 충돌 없음 |
| 시간 | 정지 장면·초기 스냅샷·수동 재배치 또는 재관측, 뷰어 시점과 독립 |
| 범위 | 단일 검토 장면, 정책·checkpoint·학습·제어 연결 없음 |

ID를 스냅샷 안에서 좌우 순서로 부여하고 스냅샷 간 추적하지 않는 것은 표시 구현 권고안이다. 임계값 이외의 기하 수치 허용오차는 안정적인 교점·퇴화 형상 처리를 위한 구현 세부로 기록하고, 2cm/20%의 의미를 바꾸지 않는다. OBB 방향이 여러 개로 동률인 형상도 같은 입력에서 같은 결과를 선택하도록 한다.

사용자가 위 전체 계약을 확정했고, 후속 명세서 작업에서 '배치된 물체 정보 → 독립 관측 ID와 OBB 스냅샷' Interface 하나를 중심으로 계산을 검증하며 뷰어 동작은 별도로 확인하는 구성도 승인했다. 개발 명세서는 이 결정과 새 패키지 지시를 반영한다. 이번 작업에서는 코드를 작성하지 않는다.

## 후속 구현의 검증 조건 — 아직 실행하지 않음

| 사례 | 기대 결과 |
| --- | --- |
| 완전 가시·완전 가림 | 기준을 통과한 전체 박스 또는 관측 없음 |
| 한쪽 가림 | 남은 구간의 전체 깊이와 실제 높이에 맞춘 OBB |
| 중앙 가림 | 양쪽 조각 독립 처리, 폭·비율 합산 금지 |
| 낮은 앞 물체 | 뒤 물체 윗부분을 별도로 관측하지 않음 |
| 회전된 물체 | 박스 바닥면 절단 후 최소 면적 OBB 재계산, 원본 yaw 강제 없음 |
| 전체 폭 6cm·조각 1.9cm | 비율을 만족하더라도 최소 폭 미달로 제외 |
| 전체 폭 20cm·조각 3cm | 최소 폭을 만족하더라도 비율 15%로 제외 |
| 전체 폭 10cm·조각 2cm | 두 경계값을 만족하므로 포함 |
| 전체 폭 20cm·양쪽 3cm씩 | 각 조각 15%로 둘 다 제외, 합산 30% 적용 금지 |
| 노출 기준 미달 물체 | 관측에서 제외돼도 다른 물체를 가리는 효과 유지 |
| 동일 배치 재관측·뷰어 회전 | 관측 결과 동일 |
| 표시 토글 | 표시 유무가 물체 위치·가림 계산 결과에 영향 없음 |

정적 기하 검증과 실제 뷰어 검토를 구분한다. 후속 성능 측정은 startup 준비, reset의 가림+필터+OBB 계산, 표시 갱신을 분리해 보고한다. 학습 실행을 성능 검증의 전제로 삼지 않는다. 최속이라고 미리 보장하거나 근거 없는 시간 목표를 추가하지 않는다.

## 검증 범위

이번에는 문서 작성과 소스 읽기만 수행한다. 기하 계산 구현, 시뮬레이션, 렌더, 성능 측정, 학습은 수행하지 않았다.
