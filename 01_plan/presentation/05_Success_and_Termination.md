# 성공 판정과 Episode 종료

[발표 문서 안내](README.md) · [태스크와 프레임워크](02_Task_Definition_and_Framework.md) · [정책 입출력](03_Contact_Representation_and_Policy.md) · [보상 설계](04_Reward_Formulation.md) · [평가와 일정](06_Evaluation_and_Schedule.md)

기준일: **2026-10-05**. 주 근거는 `중간발표_최종.pdf`의 **실제 PDF 28쪽**이며, 보상과 실행 입력의 구분을 위해 15·23·24·26쪽도 참조한다. PDF 28쪽의 하단 인쇄 번호는 30이다.

> **문서 상태: 최종 중간발표 자료의 성공·종료 설계 설명.** PDF는 임계값을 기호로 제시한다. 이전 대화에서 정한 성공 오차와 PDF 표기를 구분하며, 실제 적용값·실물 Blind 성공 검출·선반 충돌 구현은 코드 검증이 필요하다. 아래 조건을 구현 완료나 실물에서 검증된 안전 사양으로 해석하지 않는다.

## 1. 성공, 실패, 시간 제한을 구분한다

과업의 목표는 **대상 물체를 목표 위치로 이동시키는 것**이다. Hand가 명령된 거리만큼 움직였다는 사실만으로 물체가 같은 거리만큼 이동했다고 볼 수 없다. 접촉 소실이나 미끄러짐이 발생하면 Hand 이동과 물체 이동은 달라질 수 있기 때문이다.

최종 PDF는 물체 위치 오차에 따른 성공 조건과, 물체 전도·선반 이동·시간 제한에 따른 종료 조건을 구분한다. 성공은 목표 달성을 나타내고, 다른 종료는 목표를 만족하지 못한 상태에서 해당 시도를 끝내는 기준이다. [PDF 28쪽]

| 결과 종류 | 최종 PDF의 조건 | 의미 |
| --- | --- | --- |
| 성공 | 대상 물체와 목표 위치 사이의 거리 오차가 임계값 미만 | 요구한 물체 이동을 만족 |
| 전도 종료 | 물체의 roll·pitch 기반 기울기가 임계값 초과 | 안정적인 Sweeping 조건을 벗어남 |
| 선반 이동 종료 | 선반의 위치 또는 자세 변화가 임계값 초과 | Hand·Manipulator의 충돌로 선반을 움직이는 상황 |
| 시간 제한 종료 | 제한 시간까지 성공·실패 조건이 발생하지 않음 | 정해진 수행 시간 안에 과업을 끝내지 못함 |

Episode 종료는 학습·평가의 시도 하나를 끝내는 판정이다. 실물에서 로봇의 운동을 멈추는 절차와 종료 뒤의 대기·복귀 행동까지 자동으로 정의하는 것은 아니다.

## 2. 성공: 현재 물체 위치와 목표의 오차

최종 PDF의 성공 조건은 다음과 같다.

```math
\|\mathbf{p}_t-\mathbf{p}_g\|_2<\epsilon_{p,g}.
```

| 기호 | 의미 |
| --- | --- |
| $\mathbf{p}_t$ | 현재 대상 물체의 위치 |
| $\mathbf{p}_g$ | 초기 물체 위치와 명령 방향·거리로 정한 목표 위치 |
| $\epsilon_{p,g}$ | 성공 위치 오차 임계값 |

목표점은 [태스크 정의](02_Task_Definition_and_Framework.md)와 [목표 보상](04_Reward_Formulation.md)에서 사용한 목표와 일치해야 한다. 성공 판정은 Hand Pose의 오차가 아니라 **물체 위치의 오차**를 사용한다. [PDF 23·28쪽]

최종 PDF는 임계값을 기호로 제시하며 구체적인 수치를 적지 않는다. 별도로 [이전 발표 정리본](2026-09-30_midterm/README.md#episode)은 **대화에서 정한 성공 기준을 1 cm 미만, 즉 0.01 m**로 기록한다. 이 사용자 결정과 PDF에 직접 인쇄된 식을 구분해 보존한다. 이번 문서화에서 성공 기준을 새로 변경한 것은 아니며, 실제 학습·평가 설정에 이 값이 적용됐는지는 코드로 확인해야 한다.

3차원 위치 전체를 평가할지, 선반 평면으로 투영한 오차를 사용할지는 구현·평가 계약에서 명시해야 한다. PDF 수식 표기는 위치 벡터의 Euclidean 거리다.

현재 식은 임계값 안에 들어오는 순간의 조건이다. 목표 영역에서 일정 시간 머무르거나 잔여 속도까지 낮아져야 하는지, 성공과 실패 조건이 같은 Step에 만족되면 어떤 결과를 우선하는지는 PDF에 명시되지 않는다.

## 3. 전도 종료: 물체의 기울기 제한

최종 PDF는 roll과 pitch의 제곱합에 대한 제곱근을 사용하여 전도를 판정한다. [PDF 28쪽]

```math
T_{\mathrm{topple},t}
=\mathbf{1}_{\{\sqrt{\phi_t^2+\theta_t^2}>\epsilon_{\mathrm{topple}}\}}.
```

| 기호 | 의미 |
| --- | --- |
| $\phi_t,\theta_t$ | 물체 자세의 roll·pitch 성분 |
| $\epsilon_{\mathrm{topple}}$ | 전도 판정을 위한 기울기 임계값 |
| $T_{\mathrm{topple},t}$ | 조건 만족 시 1이 되는 전도 종료 표시 |

Yaw 회전만으로 전도를 판정하는 식은 아니다. 선반 위에서의 수평 회전과 물체가 지지 상태를 잃는 기울기를 구분하려는 설계로 해석한다.

다만 roll·pitch의 기준 좌표계, 물체별 정상 직립 자세, 임계값 수치는 최종 PDF에 명시되지 않는다. 원통이나 비정형 물체의 초기 안정 자세가 다르면 같은 자세 표현이 같은 전도 의미를 갖는지 확인해야 한다. 이 식이 실제 전도와 일치하는지, 순간 기울기와 완전한 전도를 어떻게 구분할지는 평가용 자세·접촉 로그와 함께 검증할 항목이다.

전도 종료와 전도에 접근할수록 커지는 보상 페널티는 별개의 설계다. 최종 PDF의 보상식에 명시되지 않은 연속 전도 페널티나 가중치를 이 문서에서 추가하지 않는다.

## 4. 선반 이동 종료: 충돌의 결과를 측정한다

최종 PDF의 설명은 Hand 또는 Manipulator가 선반과 충돌하여 선반을 움직이는 경우를 종료 조건으로 둔다. 제시된 식은 선반의 위치·자세 변화 중 하나가 임계값을 넘는지 확인한다. [PDF 28쪽]

```math
\Delta p_{\mathrm{shelf}}>\epsilon_{p,\mathrm{shelf}}
\quad\lor\quad
\Delta\theta_{\mathrm{shelf}}>\epsilon_{R,\mathrm{shelf}}.
```

| 기호 | 의미 |
| --- | --- |
| $\Delta p_{\mathrm{shelf}}$ | 선반 위치의 변화량 |
| $\Delta\theta_{\mathrm{shelf}}$ | 선반 자세의 변화량 |
| $\epsilon_{p,\mathrm{shelf}}$ | 허용 선반 위치 변화 임계값 |
| $\epsilon_{R,\mathrm{shelf}}$ | 허용 선반 자세 변화 임계값 |

이 식은 모든 로봇–선반 접촉을 즉시 종료하는 조건이나 접촉력 임계값과 같지 않다. PDF의 수식은 **선반이 움직였는가**를 기준으로 표현되어 있다. 변화량을 Episode 시작 상태에서 계산할지, 이전 Step에서 계산할지, 위치·자세 변화의 크기를 어떤 함수로 계산할지는 미정이다.

과거 설계에는 작업판을 고정하고 Hand·Manipulator와 작업판의 접촉력을 페널티·종료에 사용한다는 안이 있었다. 고정된 선반은 접촉이 커져도 Pose가 바뀌지 않을 수 있으므로, 과거의 고정 작업판 조건과 최종 PDF의 선반 이동 식을 그대로 동시에 적용하면 종료 검출이 의도와 다를 수 있다.

현재 문서에는 최종 PDF의 이동 기준을 기록하고, 구현 계약의 상충을 **OPEN**으로 남긴다. 선반이 움직일 수 있는 환경에서 이동량을 판정할지, 고정 환경에서 접촉력으로 판정할지는 사용자 결정과 실제 환경 설정으로 확인해야 한다. 어느 쪽도 이번 문서 작성만으로 새 확정 사양으로 채택하지 않는다.

## 5. 시간 제한: 미완료 시도를 끝낸다

성공이나 다른 실패 조건이 발생하지 않은 상태에서 수행 시간이 제한에 도달하면 Episode를 끝낸다. [PDF 28쪽]

```math
t\ge T_{\max}.
```

시간은 Sweeping Episode의 시작에서 측정해야 한다. 별도 접근 과정이 포함되는지, 정책 Step 수를 시간으로 변환하는 주기가 무엇인지와 제한 시간의 수치는 PDF에서 정하지 않는다.

학습 구현에서는 시간 제한 종료를 상태 실패 종료와 어떻게 구분하여 PPO에 전달할지 확인해야 한다. 최종 PDF는 Episode 종료 조건만 제시하므로, Timeout의 Termination·Truncation 처리와 Value Bootstrap 방식을 이미 정했다고 해석하지 않는다.

시간 제한은 빠른 성공을 유도하는 보상과 역할이 다르다. 전자는 끝나지 않는 시도를 제한하고, 후자는 성공한 시도 중 더 빠른 완료를 선호하도록 한다. 최종 PDF의 시간 보상은 성공 시 기본 보상과 빠른 성공 보너스를 주는 형태다. [PDF 26쪽; 보상 설계]

## 6. 시뮬레이션 성공과 실물 Blind 종료를 분리한다

학습 환경은 물체의 현재 위치·자세를 정답으로 알고 있으므로 목표 오차와 전도를 계산할 수 있다. 이 정보는 보상과 평가에 사용할 수 있지만, 57차원 Actor 관측에 현재 물체 정답을 추가하는 이유가 되지는 않는다. [PDF 15·21·23·24쪽]

| 판정 | 시뮬레이션에서 사용할 수 있는 근거 | 실물 실행에서 남는 문제 |
| --- | --- | --- |
| 물체 목표 도달 | 현재 물체 GT 위치와 목표 위치 | 조작 중 시각 갱신 없이 물체 목표 도달을 검출하는 방식 |
| 물체 전도 | 물체 GT 자세 | 실물에서의 전도 관측 또는 외부 평가 방법 |
| 선반 이동 | 시뮬레이션 선반 Pose | 선반이 고정됐는지, 이동·충돌을 어떤 센서로 검출할지 |
| Timeout | Episode 경과 시간 | 시작 시점·제한 시간·종료 후 행동의 정의 |

실물에서 실행 입력을 Blind로 유지하면서 성능을 평가하려면, 외부 평가 장치가 관측한 물체 정답과 정책이 사용하는 센서 입력을 구분해야 한다. 외부 평가가 허용된다는 사실과 그 정보를 정책 또는 온라인 성공 검출기에 제공한다는 사실은 다르다.

전체 프레임워크에는 Success Detector가 그려져 있지만, 최종 PDF는 그 검출기의 입력과 판정 방법을 구체적으로 정의하지 않는다. Hand 이동량으로 물체 성공을 대체하거나 접촉 소실을 목표 달성으로 간주하는 규칙을 임의로 추가하지 않는다. 종료 판정 이후의 로봇 정지·대기·복귀와 별도의 실물 안전 감독도 구현 시 분리해서 명시해야 한다.

## 7. 보상과 평가에 연결하는 방법

성공 판정은 목표 위치에 충분히 도달했는지 결정하고, 목표 보상은 도달 전의 위치 오차 감소에 학습 신호를 제공한다. 빠른 성공 보상은 성공한 시도의 완료 시간을 반영한다. 전도·선반 이동 조건은 허용하지 않는 결과를 구분하여 해당 시도를 끝낸다. 종료 조건이 있다고 해서 그 조건에 접근하는 행동의 연속 페널티까지 자동으로 정의되는 것은 아니다.

평가에서는 성공률과 함께 종료 원인을 구분해 기록해야 한다. 예를 들어 최종 위치 오차가 작더라도 전도가 발생한 시도는 성공 조건과 실패 조건의 우선순위에 따라 별도로 판정할 필요가 있다. 접촉 소실이 반복되다가 Timeout이 발생한 경우에는 공식 종료 원인과 원인 분석용 접촉 로그를 함께 남겨야 한다. 이러한 기록은 센서·보상 비교에서 성능 변화가 목표 진행, 안정성, 접촉 유지 중 어디에서 발생했는지 해석하는 근거가 된다. 구체 비교 조건은 [평가 계획](06_Evaluation_and_Schedule.md)에 정리한다.

최종 PDF 28쪽은 높이 제한, 천장 접촉, 충격량 초과, 접촉 소실 자체를 독립적인 종료 조건으로 적지 않는다. 과거 논의에서 등장했다는 이유로 현재 확정된 종료 목록에 합치지 않는다. 필요한 추가 종료 조건은 별도 결정과 근거를 남겨야 한다.
