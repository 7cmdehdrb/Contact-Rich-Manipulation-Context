## 1. 무엇을 검증하는가

제안 방법에는 접촉 관측을 결합하는 선택과 물리적 해석을 보상에 사용하는 선택이 있다. 따라서 **Sensor Ablation은 실행 정책에 제공하는 정보의 기여**, **Reward Ablation은 같은 정보 아래에서 학습 신호의 기여**를 각각 확인한다. 두 비교에서 관측과 보상을 동시에 바꾸면 성능 차이의 원인을 구분하기 어렵다.

검증의 목표는 최종 성공률뿐 아니라 접촉 안정성과 수행 시간, 그리고 학습 효율을 함께 평가하는 것이다. PDF 33쪽은 Success Rate·Robustness·Execution Time을 예시로 제시하지만, 평가 횟수·학습량·통계 집계 방법까지 확정하지 않는다.

## 2. Domain Randomization의 위치

PDF 30쪽은 학습 중 초기조건·물체·물리·제어·센서 조건을 바꾸어, 하나의 정해진 조건에만 의존하는 정책을 줄이려는 계획이다. 이는 학습 환경을 구성하는 방법이며, 최종 발표에 별도의 DR 유무 비교 실험은 없다.

| 구분 | PDF에 포함된 변화 대상 | 해결하려는 학습 의존성 |
| --- | --- | --- |
| Arm 초기 상태 | 이상적인 초기 Hand Pose 주변의 변동, 그 Pose에 대한 IK 관절 구성 | 접근 결과가 항상 동일하다는 가정 |
| Hand 초기 상태 | 2D Hand Configuration의 초기 변동 | 항상 같은 손 형상에서만 조작하는 의존성 |
| 물체 | Pose, Shape, Size, Weight | 특정 형상·위치·하중에 대한 의존성 |
| 물리·제어 | Physics & Control Parameters | 시뮬레이션의 특정 접촉·제어 파라미터에 대한 의존성 |
| 센서 | Joint, Tactile, F/T Uncertainty | 이상적인 무오차 신호에 대한 의존성 |

PDF의 초기 상태 표기는 다음과 같다.

```math
\mathbf{p}_0^h\sim\mathcal{N}(\boldsymbol{\mu}_0,\boldsymbol{\Sigma}),\qquad
\mathbf{q}_0^r=\mathrm{IK}(\mathbf{p}_0^h),\qquad
\mathbf{q}_0^h\sim\mathcal{N}(0.5,\sigma_{\mathrm{hand}}^2).
```

여기서 `Hand Pose` 주변의 변동은 접근 후 근접 상태를 생성하기 위한 것이며, 공간 전체에서 임의로 시작하도록 바꾸는 설정은 아니다. Hand의 0.5는 정규화된 관절 표현의 초기 중심이다. 공분산·분산·각 변수의 범위는 PDF에 수치가 없다. Pose의 위치·회전 성분에 대한 분포, Hand의 [0,1] 범위 처리, IK 실패·충돌 상태의 제외 방식은 구현 시 정해야 한다.

물체의 Shape·Size를 변화시킨다는 것이 그 정답을 Actor 입력에 추가한다는 뜻은 아니다. 현재 [57D 관측](03_Contact_Representation_and_Policy.md)은 초기 물체 위치와 이동 명령을 사용하며, 실행 중 현재 물체 Pose나 형상 정답을 제공하지 않는다.

랜덤화 분포와 실제 접근·센서 오차의 대응은 추가 확인 대상이다. 아직 측정한 범위가 없으므로 랜덤화를 사용한다는 이유만으로 Sim-to-Real 강건성이 검증되었다고 주장하지 않는다.

## 3. Sensor Ablation: 관측 정보의 기여

### 3.1. 공통 관측과 네 조건

PDF 31쪽의 Base Observation은 다음과 같다.

```math
\mathbf{o}_t^{\mathrm{base}}=
[\mathbf{S}^{r}_t,\mathbf{S}^{h}_t,\mathbf{g},\mathbf{a}_{t-1}].
```

Robot·Hand 자기 상태 20D, Goal Condition 5D, Last Action 8D를 합한 33D를 공통으로 유지한다. 다음 차원은 Header까지 포함하는 18D 촉각 전체를 제거·유지한다는 해석의 합계이며, 제거 조건에서 Header를 따로 남길지는 확정해야 한다.

| PDF 조건 | Actor에 추가하는 접촉 관측 | 총 입력 차원 | 비교 목적 |
| --- | --- | ---: | --- |
| Case 1 | 없음 | 33D | 접촉 피드백 없이 가능한 범위와 접촉 관측의 필요성 |
| Case 2 | Binary Tactile 18D | 51D | 촉각 단독의 공간적 접촉 정보와 F/T 제거 영향 |
| Case 3 | Wrist Wrench 6D | 39D | 하중 단독 정보와 Tactile 제거 영향 |
| Case 4 | Tactile 18D + Wrench 6D | 57D | 제안하는 결합 관측의 효과 |

각 조건은 관측 구성을 바꾸어 **별도의 정책을 학습**한다. 학습된 결합 정책에서 센서값을 갑자기 0으로 만드는 시험만으로 이 Ablation을 대체하지 않는다.

### 3.2. 비교에서 읽어야 할 의미

| 비교 | 직접 확인하는 질문 | 해석 범위 |
| --- | --- | --- |
| Case 4 vs. Case 2 | 촉각에 Wrench를 추가하면 무엇이 개선되는가? | 공간 접촉 정보를 가진 조건에서 연속 하중의 추가 기여 |
| Case 4 vs. Case 3 | Wrench에 촉각을 추가하면 무엇이 개선되는가? | 전체 하중을 가진 조건에서 공간적 접촉 정보의 추가 기여 |
| Case 2·3 vs. Case 1 | 각 센서 단독으로 무엇을 보완하는가? | 자기 상태·초기 명령만 사용하는 기준선 대비 효과 |
| Case 4 vs. Case 1 | 접촉 관측의 결합이 어느 정도 도움이 되는가? | 접촉 피드백을 포함한 전체 개선. 두 센서의 기여 분해는 위 비교와 함께 판단 |

목표 도달이 좋아졌다는 결과만으로 정확한 물체 Pose나 Slip 상태를 추정한다고 주장할 수는 없다. 센서에 따라 개선된 실패 유형·물체 조건·접근 오차를 함께 확인해야 정보의 역할을 설명할 수 있다.

### 3.3. 동일 조건 비교에서 확인할 사양

관측 외의 Action·Controller·보상·종료·초기조건·훈련 예산을 통제한다는 것이 PDF의 비교 원칙이다. 다만 CoP 기반 보조 보상은 촉각과 Wrench를 사용하므로, Actor에서 센서를 제거할 때 학습용 보상 계산까지 없앨지 정해야 한다.

**구현 검토 제안(PROPOSED):** 시뮬레이터에서 보상 계산용 센서 신호를 유지하고 Actor의 센서 관측만 제거하면 같은 보상을 유지한 Sensor Ablation을 구성할 수 있다. 이 경우 `센서 없음`은 Actor의 실행 관측에서 제거했다는 뜻이며 학습 보상까지 접촉 정보를 제거한 조건은 아니다. 반대로 보조 보상도 함께 제거하면 관측과 학습 신호가 모두 바뀌므로 그 변경을 별도로 명시해야 한다.

Network 구조·입력 마스킹 방식, 촉각 Header 처리, 학습 Seed·예산과 평가 조건의 통제 범위는 PDF에 미명시다. Critic에 제공하는 특권정보가 있다면 그것도 각 조건에서 기록한다.

## 4. Reward Ablation: 학습 신호의 기여

### 4.1. 관측을 유지하고 보상만 변경

PDF 32쪽의 `Full Observation`은 초기 정보와 Tactile·F/T를 모두 사용하는 제안 관측을 뜻한다. 실행 중 물체의 전체 정답 상태를 보는 Oracle 관측으로 해석하지 않는다. 자기 상태·목표 명령·직전 행동을 포함한 전체 관측 구성은 그대로 유지한다.

아래는 슬라이드의 항 구성을 옮긴 것이다. 실제 실험에서는 [보상 설계](04_Reward_Formulation.md)의 각 가중치를 함께 기록해야 한다. 슬라이드에서 세 식 모두 사용한 `r1` 표기는 문서에서 조건 이름으로 구분했다.

| PDF 조건 | 사용하는 보상 항 | 바뀌는 학습 신호 |
| --- | --- | --- |
| Case 1. Base Rewards | Goal + Action Rate + Time | 목표 도달·행동 변화 억제·조기 완료 |
| Case 2. w/o Sub-Goal | Base + Normal + Contact | 접촉 방향 정렬과 접촉 유지 추가 |
| Case 3. Proposed Rewards | Case 2 + CoP 회전 Sub-Goal | 접촉의 물리적 해석에 기반한 중간 회전 목표 추가 |

### 4.2. 이 비교가 입증할 수 있는 것

Case 1과 Case 2의 차이는 Normal과 Contact를 **함께 추가**한 효과다. 접촉 상실·전도·목표 도달이 개선되는지 볼 수 있지만, 이 결과만으로 Contact 항 하나의 효과를 분리할 수는 없다. 각 항을 하나씩 제거하는 비교는 현재 PDF의 3조건에 포함되지 않는다.

Case 2와 Case 3의 차이는 CoP 회전 Sub-Goal의 추가 효과다. 학습 초기에 목표 도달률이 더 빠르게 높아지는지, 같은 학습량에서 최종 도달 성능과 안정성이 개선되는지를 확인한다. Sub-Goal 자체의 회전 추종 성능은 물체 목표 도달과 함께 보아야 하며, 중간 목표를 잘 따랐다는 사실만으로 과업 성공을 대체하지 않는다.

조건마다 보상 정의가 다르므로 총 Episode Return의 크기만 비교하면 효과를 판단하기 어렵다. **같은 성공 기준·평가 조건에서 측정한 과업 지표**를 비교해야 한다. 보상 구조·가중치의 탐색과 최종 비교 실험도 구분한다. 최종 비교에 사용할 구성을 정한 후에는 해당 구성과 가중치를 고정하고 조건별 정책을 학습한다.

## 5. 평가 지표와 결과 해석

다음 표는 PDF의 평가 목표를 실행 가능한 지표로 풀어 쓴 **평가 구체화 제안(PROPOSED)**이다. Success Rate·Robustness·Execution Time 이외의 상세 산식과 집계 방식은 아직 확정된 프로토콜이 아니다.

| 평가 목적 | 남길 지표·기록 제안 | 해석 시 주의 |
| --- | --- | --- |
| 정확성 | 성공률, 최종 물체 위치 오차 | Hand 이동 거리와 물체 도달을 구분. 성공 임계값을 모든 조건에서 동일하게 사용 |
| 안정성 | 접촉 상실·복구, 전도, 선반 충돌/접촉, 힘·모멘트 변화 | Actor에 제공하지 않은 평가용 접촉 정답과 센서 감지값을 구분 |
| 속도 | 성공 Episode의 완료 시간, 실패·Timeout 비율 | 빠른 실패를 빠른 성공과 섞지 않고 함께 보고 |
| 학습 효율 | 동일 환경 Step에서의 성공률 곡선, 정한 성공 수준까지의 학습량 | 기준 성공률·평가 주기·학습 예산을 사전에 정의 |
| 강건성 | 물체·접근 오차·센서 불확실성별 성능과 실패 유형 | 어느 조건을 변화시켰는지 명시. 평균 성공률 하나로 일반화 범위를 대신하지 않음 |
| Sub-Goal 해석 | CoP 유효성·신뢰도, 회전 추종과 과업 결과의 관계 | CoP 변화만으로 물체 Slip이나 Pose를 정확히 식별했다고 주장하지 않음 |

기록에는 정책·환경 Commit, 학습 설정, 보상 가중치, 평가 물체와 목표, Seed, Controller 조건, 종료 이유가 연결되어야 한다. 여러 반복의 평균과 변동을 보고하는 방식, 학습·평가 물체의 분리, 실물에서의 정답 측정 방식은 남은 설계 항목이다. 실행 가능한 기록 형식은 [연구 로그 템플릿](../../00_guidelines/templates/RESEARCH_LOG.md)을 참고한다.

선행연구와의 비교는 Task·관측·Robot·Controller·시작 조건이 같은지 확인한 뒤 수행한다. PDF의 Future Works는 비교를 계획하지만, 어떤 논문의 코드를 어떤 조건으로 재현할지까지 확정하지 않는다. 서로 다른 Task의 논문 성공률을 직접 나란히 놓고 방법의 우열로 해석하지 않는다.

## 6. 후속 일정과 단계별 산출물

PDF 33쪽의 일정은 2026년 10월 첫째 주부터 11월 셋째 주까지의 계획이다. 주차를 임의의 날짜로 바꾸지 않고 그림의 범위를 유지했다. 아래 산출물은 일정의 작업 의미를 구체화한 제안이며, 진행 완료 보고가 아니다.

| 단계 | PDF의 계획 구간 | 작업 내용과 산출물 제안 |
| --- | --- | --- |
| 시뮬레이션·센서 검증 | 10월 첫째–둘째 주 | 센서 영역·Wrench 좌표·부하 보정 확인, Actor GT 누출 점검, 유효 접촉/무접촉·약한 신호 로그 |
| 정책 구현 및 학습 | 10월 첫째–넷째 주 | 관측·Action·Controller·보상·종료 구현, 보상 구조와 가중치의 반복 조정, 비교에 사용할 구성 고정 |
| 비교 실험 | 10월 넷째 주–11월 둘째 주 | 센서 4조건과 보상 3조건의 별도 학습·동일 평가, 결과와 실패 사례 수집 |
| 결과 분석 및 비교 검증 | 11월 둘째–셋째 주 | 정보 기여·학습 기여 해석, 실패 조건 분석, 가능한 선행연구 비교와 적용 한계 정리 |

정책 학습 기간을 길게 둔 이유는 보상 가중치만 맞추는 것이 아니라, 기본 보상과 Sub-Goal이 어떤 행동을 만드는지 확인하고 수정해야 하기 때문이다. 비교 실험과의 일정 겹침은 환경·실험 준비를 병행할 수 있다는 의미로 해석하되, 최종 조건 간 비교에는 고정한 설계 버전을 사용한다.

실물 전이는 [프레임워크](02_Task_Definition_and_Framework.md)의 목표로 남는다. 현재 일정 그림에는 실물 검증의 독립 기간이 없으므로 날짜를 새로 확정하지 않는다. 장비·센서·Controller·Blind 종료 방식이 확인되면 실물 평가 조건과 범위를 따로 기록한다.

| Reward Ablation | 항별 가중치, CoP 회전 목표 구체식, 공통 학습량과 평가 기준 |
| 학습 효율 | 비교할 환경 Step·평가 주기·기준 성능, 반복 수 |
| 평가 조건 | 시험 물체·초기 오차·명령 분포, 성공·실패 집계와 실물 정답 측정 |
| 선행연구 비교 | 재현 대상과 사용할 구현, 관측·제어·Task 차이의 통제 |

센서와 보상의 기여를 분리해 확인하고, 유효한 조건과 실패하는 조건을 함께 정리하는 것이 이 단계의 결과물이다.
